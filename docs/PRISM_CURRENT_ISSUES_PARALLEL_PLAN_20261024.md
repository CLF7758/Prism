## 2. 已确定问题：怎么修改、什么才算通过

### P01—P03 保存反馈（AI-02）

**入口**：`prism/view.py` 的 `do_save`、`_show_save_phase`、`on_saving_finished`；`prism/fileio/save_preparation.py` 的 `start_capture/run/_publish_phase/finish`；`prism/widgets/__init__.py` 的 `PrismProgressDialog`；底层 `SQLiteIO.write` partial分支只作为信号边界核对，不先重写writer。

**做法**：
1. 给每次保存一个稳定operation_id，绑定project_id、目标路径、捕获修订。UI收到请求先显示“准备保存”，无需等待第一次逐行progress。
2. 阶段统一为：已接受→捕获/准备→写入→确认→结束。结束必须分为已确认保存、取消、拒绝、失败、写入但未确认。
3. 精确百分比没有可靠分母时用不确定进度，不能把捕获行数当写盘百分比。不要循环processEvents强行刷屏。
4. Worker只发信号/不可变结果，不操作控件。GUI接收时检查operation/project仍归自己；过期消息不改变新任务。
5. 手动保存成功显示时间；保存期间新编辑存在时显示“本次快照已保存，之后编辑尚未保存”。只在确证修订不变时清dirty。
6. 自动保存可见但非侵扰：失败保持可见状态并限制相同失败重复提醒，不在每次tick弹窗，不无限无声重试。
7. 只读/准备未完成/会话失效的拒绝也要有原因；不能在UI上假装成功，也不能因加反馈改变事务和原件协议。

**验收**：快/慢部分保存、全量保存、手动/自动、取消、写失败、确认失败、新编辑、连续点击、换工程旧回调全部覆盖。界面消息与源修订和磁盘结果相符；实际重开验证；任务完成后不残留进度框/worker/等待标志。反馈延迟候选目标≤100ms或下一次可绘制帧，最终阈值注明参考机器；没有真实绘制证据不能声称“用户一定看见”。

**特别注意**：当前进度框minimumDuration已经为0，不能把根因写成默认4秒。已有WIP已经增加反馈和show，先补缺口与核验，不再造第二套保存状态。

### P04—P06、P17 计数与发布（AI-03，调用方由AI-07）

**先固定术语**：全库素材数、当前结果数、实际视口内容数、选中数、标签匹配数必须分开。同字节的两个资产记录不等于一个资产；图像重复计数与物理存储去重是两套概念。当前“未分类”代码以默认/无归属画布为主要规则，不能测试AI擅自改成 `_categories` 为空。材质、页面、脑图节点是否计入同一标签树，应写清当前规则及产品选择。

**做法**：
1. 使用已有目录+dirty overlay统一取数，不扫描驻留100张冒充全库；标签别名/父标签按资产ID去重，不直接相加。
2. 发布一个不可变 `CountSnapshot` 契约，至少含project、query、source_revision、overlay_revision、count_kind、value/unknown、complete和request_token。
3. 同一帧的通知合并成一次recount；一次计算供侧栏与底部消费。不要只把300ms改0就宣布优化完成。
4. 用户选择/当前结果已提交可以立即发布已知值；全局统计尚未就绪显示更新中或明确的上次确认值，禁止unknown显示0。
5. 模型发布和布局提交分别通知，分清“结果有多少”与“当前画面已画多少”；不得等下一次滚轮才更新底部。
6. 聚合滚轮使用 `_update_status(..., interaction=True)` 或等价纯缓存接口，不能在缩放路径打开SQLite、stat存档或重建标签树。
7. 保留颜色计数、过滤栏、工具栏刷新。`__main__._on_recount` 不只是状态栏函数，不能把它删掉或让它永远不执行。

**验收**：一次编辑后全部相关计数按同一修订更新；快速30次编辑无刷新风暴、无漏最后一次。A→B→A快速切换旧结果不回写。37个跨画布标签的独立ID期望集正确。观察普通画布与聚合画布的滚轮路径，查询/stat调用次数为0。大工程计数计算慢时仍不堵住交互；单独报告计算耗时和发布延迟。

### P08 相机（AI-05，view.py必须排队）

工具栏/右键/Ctrl+0/底部“Show All”等实际入口都列出调用图，先确定统一名称“重置相机”。普通画布、聚合画布、材质或其他独立视图由各自边界提供器返回当前范围的有效内容bounds，共用同一适配算法与padding，不能互相委托成递归。

明确规则：当前活动范围、可见过滤、隐藏/回收站、未加载资产的目录bounds、注释、空画布、单个超宽/超高素材、已旋转素材都要有一致决定。重置不是“上一次fit的切换”；清理previous_transform，不能第二次点击恢复旧相机。是否将注释算入范围沿用现有产品规则或登记待决定，不由AI顺手改变。

**验收**：同一状态下所有入口得到相同transform和中心点（允许浮点容差）；重复操作幂等；普通/聚合/空画布、过滤和加载中均不递归、不把无关画布算进去；按钮文案/提示/快捷键一致。

3. 累计rollup注明cumulative并在会话边界重置/带owner身份；记录结束时flush尾部计数，不能把换工程前的同名累计量当新工程工作量。
4. 生命周期/版本/关键操作摘要有独立的有界保留策略，或在开始/结束保存manifest。不要单纯把所有日志无限加大；也不删除原日志来“解决轮转”。
5. GC只有真实区间与GUI线程归属才能关联卡顿；重叠时长并集计算，不和父阶段相加。90%覆盖可表述GC主导该窗口，不代表知道哪个对象/分配点有错。模态用户操作不因墙钟长误判。
6. 队列字段必须拆开：当前pending/running/ready，真实最老任务年龄（需task id与enqueued_at），当前busy周期时长，历史峰值。若没有逐任务身份，oldest_age应unknown，不能用首次submitted时间伪造。
7. 分析器最后快照中的null要保留；不能拿历史max填最后depth。旧格式字段缺失保留unknown，不从文件大小猜I/O，不把rejected/stale/ready暂态等于丢图。
8. `_gc_intervals`等新状态需要有界、线程安全，测试替身/关闭过程中可用；异常保护不能让采集悄悄消失。

**验收**：固定输入离线重放结果可重复；已有正确字段保持，口径修正项逐项说明；父子重叠不重复、跨session不合并。队列归零后年龄不是600秒。快/慢/失败采样与诊断模式生命周期准确。同一业务回放日志体积显著下降但关键操作仍可追溯；用原生小工程对照诊断开销，不能用3次采样宣布全应用≤3%。

## 5. 哪些可同时做，哪些必须排队

### 5.1 可并行

- AI-01基线台账、AI-04材质只读、AI-08解码只读、AI-10存储只读、AI-11日志离线分析可同时开展；各写各目录。
- 接口约定完成后，AI-02保存、AI-03计数、AI-06查询、AI-09日志可在各自文件内并行开发。

- AI-07可以先做R05和布局设计；契约定稿后再在自己的画布文件开发。AI-03只提交画布接线要求，不去改该文件。
- 小型纯逻辑回归可并行，但每次命令必须有独立输出/配置/夹具，且没有进程/文件冲突。

### 5.2 不可并行

| 冲突 | 必须如何安排 |
|---|---|
| AI-02保存 vs AI-05相机都需view.py | AI-02先收口释放文件，AI-05再接；不是“改不同函数就安全” |
| AI-03计数 vs AI-06/07模型/画布提交 | AI-03定接口，AI-06/07改自己文件，集成统一验收 |
| AI-06缓存 vs AI-07几何/驻留 | QueryKey/GeometryKey、失效和所有权先冻结；不能各自扩大缓存后拼起来 |
| AI-07热点装饰器 vs AI-09采样契约 | AI-09先给API，AI-07接线；同一文件不双写 |
| AI-03计数需要project_catalog.py | 暂由AI-06独占；AI-03给出精确需求/patch，不抢写 |
| AI-10发现安全缺陷涉及view/partial保存 | 交AI-02核准后补最小修复；只读取证AI不越权改 |
| 多个原生/十万图/ETW/大量哈希测试 | 同一时段只运行一个重型/原生测量实例；其它做离线分析 |
| 性能A/B期间源码、日志模式、数据或配置变化 | 冻结测量窗口，变化后只重做受影响实验，不能把混合版本数据比较 |
| AI-12独立最终验收期间持续开发 | 冻结候选版本；发现失败回开发包，产生新版本后定向重验 |

**可以同时研究不等于可以同时实机测量；可以同时开发不等于可以同时写同一个文件。**

### 5.3 建议波次

- **第0波：当前不启动。** 用户分发任务书，AI-01登记owner和WIP；各AI确认边界后方可开始。
- **第1波：并行取证+接口。** AI-04/08/10/11先只读；AI-02/03/06/09核准各自WIP并发布接口；AI-07先R05；AI-05做不碰view的入口清点。
- **第2波：确定边界的开发。** AI-02保存、AI-03计数、AI-06查询、AI-09日志各自开发；AI-05菜单可同步。AI-07在契约就绪后实现几何/驻留最小包。
- **第3波：顺序集成。** AI-02→AI-05交接view；先QueryKey/模型，再布局和计数消费，再日志关联；安全阻塞优先修，不能为抢性能绕开保存保护。
- **第4波：独立验收。** AI-12按冻结版本定向验收和规模/长循环；失败只回对应包，保留原结果，不反复从头跑全部。

## 6. 每个AI最后必须交回的八件套

统一目录：`artifacts/dispatch-20261024/AI-XX/批次号/`。不写共享同名REPORT，不覆盖前一批失败。只读AI省略实际产品diff，但要明确“产品零写入”与其验证范围。

1. **REPORT.md**：结论先行；必须逐项回答“错在哪里、什么操作触发、实际调用链、证据是否可重复、哪些仍未知、下一步改哪个边界”。标问题P编号、阶段和验收状态。
2. **result.json**：每条case的ID、预期、实际、PASS/FAIL/BLOCKED/UNTESTED、证据等级D/U/V、源码版本、session/PID/seq、截图/日志路径、耗时/资源条件。
3. **source-manifest.before.json / after.json**：受测依赖文件全SHA256+mtime+相对路径根。日志128位截断前缀必须按同样约定比对，不能和完整SHA256直接比较。
4. **experiments.json**：每次实验完整命令、cwd、开始/结束时间和时区、超时、退出码、stdout/stderr路径、依赖源文件、是否受并发修改影响及处置。
5. **raw/**：未截断原始输出、日志冻结副本/其哈希、JUnit或逐项结果。必须保留失败；pytest断言通过但进程0xC0000005，退出验收仍失败。
6. **changes.diff + CHANGES.md**：研发AI列实际变动文件/函数、为什么必要、接口、兼容性和回退办法。无git可使用原文件快照生成unified diff，禁止擅自git init。只读AI交“未改产品”的范围记录。
7. **evidence/**：视觉类必须含对应阶段截图/连续帧/几何表，性能类含阶段时间与资源数据，数据类含ID集合/关系/哈希核对。没产出说明原因并标未验收，不能用空图冒充截图证明。
8. **protection-and-processes.json**：哪些原件未触碰、哪些仅stat/采样、哪些全哈希、哪些副本实际写入；所有自己启动的PID/子进程/端口及结束状态。仅mtime/大小一致不能声明“字节全一致”。

推荐result.json字段最少为：`task_id, problem_ids, stage, source_manifest, environment, experiments, cases, conclusions, evidence, protected_assets, untested, limitations, remaining_processes, next_step`。

每个结论引用具体文件与行号/日志session和seq；源码移动后复核，不把历史行号当当前事实。报告不得只写“全部PASS”；必须列多少项、跳过哪些、哪些条件没有覆盖。

## 7. 总体验收与退回标准

### 7.1 五种可接受交付状态

- **取证完成**：证据可复核，原因仍可标U；这不代表问题已修。
- **代码待验收**：有完整修改和相关回归，未过独立真实入口验证。
- **验收通过**：规定场景和条件全部满足，证据完整；说明范围。
- **失败/受阻**：失败原因、已做尝试、需要何种输入明确，不藏失败。
- **未测**：没有实际运行/覆盖；不能塞进PASS数量。

### 7.2 研发包可以被接收的条件

1. 只改授权边界，源码和测试版本可确定；无同文件双写覆盖。
2. 用户能走正式入口，结果符合契约；底层API/编译/行数不单独算产品通过。
3. 必要异常分支覆盖，保存与原件安全不回退，旧回调不覆盖新状态。
4. 性能数据有相同条件的对照，至少报告冷/热、P50/P95/P99/max、GUI与后台分开。没有完整应用旧基线就不声称“全应用提升X%”。
5. 不隐藏/降质/强制GC/关闭GC/放宽旧超时/删除断言掩盖失败，不让测试主动请求高清代替UI。
6. 所有程序异常和进程非0退出都登记；旧失败须改前独立复现或代码契约证据，不能口头说“本来就失败”。

### 7.3 规模验收矩阵（AI-12）

- 100、1000、1万、10万；独立真实资产与复制资产分别报告，记录格式/分辨率/总字节/独立原件数、分类/标签分布。
- 普通画布、全部/未标签/未分类、复杂筛选/排序、快速返回、四模块切换。
- 远/中/近、缩小后焦点放大、快速平移、停止后的全视口被动清晰恢复。
- 首屏可见、可操作、查询完成、布局提交、实际正确绘制分别计时。
- 改标签/归属、移动、撤销重做、保存中再编辑、保存重开、原件导出/源哈希。
- 长循环至少覆盖缓存装满、淘汰、返回旧范围、换工程、关闭；观察对象驻留/RSS趋势而非单个峰值。
- 图像/UI质量不退化、命中/选择正确；帧率目标注明刷新率。60Hz下16.7ms可作帧预算参考，**不能把4ms合作切片宣传成没有超过16ms的保证**。

硬件、DPI、GPU、冷暖和诊断模式须写入结果。不得先拍脑袋承诺所有机器100k首屏1秒/内存几百MB；先固定参考条件与验收门槛。

### 7.4 直接退回的交付

- 没有版本/命令/原始结果；只说“编译通过”“感觉流畅”“X项测试通过”。
- 把重复资产压测当十万独立图片负载。
- 把异步墙钟、父子span、GC与覆盖dispatch相加制造总卡顿。
- 将未知显示0，将旧计数充当本次扫描，将模型行数当真实画面完成。
- 先改代码再只测修改后的实现，没有独立期望结果。
- 测试自己补请求高清、自动修源文件/补数据，或删掉失败断言。
- 没有清理自己的进程，却批量终止其它会话进程。
- 对未复现或缺画面的材质抖动、原生退出写“彻底根治”。
