# 下载节点、图片裁切和 PDF 导出

2026-10-16 源码集成。未覆盖已发布的 v0.3.10 安装包。

## 使用方式

- 在具体画布上右键，选择“下载视频”。节点出现在鼠标右键的位置。
- 粘贴链接或整段分享文字，按回车或点击“开始下载”。解析阶段显示等待进度，传输阶段显示字节进度；B站分开的音视频流分别显示进度，之后显示合并和检查状态。
- 下载由独立进程执行。画布、工具栏和其他操作继续响应；最多同时下载两个任务，等待和运行合计最多 20 个。
- 完成后，视频自动加入创建节点的原画布，节点随即自动消失；失败节点保留重试入口。视频保留原文件，不改变用户当前选中内容，也不强制切换画布。正在导入素材、拖动节点或编辑文字/裁切时，等待操作结束再插入。
- 拖动节点标题栏可以移动节点，在不同画布缩放倍率下都跟随鼠标；输入框和按钮保持原有交互。视频在节点最后所在位置插入。
- 切换到其他画布时隐藏原画布的节点，下载继续。移除节点会取消尚未完成的任务。关闭工程导致节点销毁时取消对应任务，防止把视频插进另一个工程。关闭软件时终止工作进程及其 FFmpeg 子进程。
- 下载结果保存到用户 Downloads/Prism 下的独立任务目录。节点是临时任务界面，不进入素材统计、自动排列、工程存储或 PDF；完成的视频是正常工程素材，支持保存和撤销。
- 公共素材聚合视图不创建下载节点，需要先打开一个具体画布。

图片右键菜单新增直接的“裁切图片”，复用已有裁切与撤销命令。右键其他图片时，先把操作目标切换到该图片。拖动边框调整范围，回车确认、Esc 取消；原图字节不被裁切覆盖，已有“重置裁切”仍可恢复完整图片。

裁切控件已改为四角和四边中点的 8 个小圆点，视觉直径保持约 9 个屏幕像素，点击区域约 15 像素；拖动边点只改变该边。

视频未播放时显示开头的有效画面，黑场和淡入初期会在有上限的开头扫描中跳过。使用现有 PyAV 在两个后台解码任务中生成预览，等待队列最多 128 项，共享预览缓存最多 32 MiB；不在主线程解码整段视频，不改变原视频字节。画布和右栏共用预览，右栏按实际可用宽度居中，显示视频真实分辨率而不是预览图尺寸。

后续画质规则：不压缩、不二次编码，默认选择最高可用流。B站音视频仅进行流复制合并；如果实际可得分辨率低于平台提供的原片标称尺寸，明确报错，拒绝导入低清替代，不再静默接受 480p。没有原片尺寸可核对的平台仍只能保证使用上游返回的最高可用流，不能把平台分发流宣称为创作者上传的逐字节原片。

PDF 是现有导出窗口中的格式选项，没有新增专门的菜单栏或右键入口：

- 画布：现有导出窗口选择 PDF。输出当前可见素材组成的完整画布，保留排布、裁切、笔刷和文字，排除选择框与下载节点。使用 Qt PDF 绘制，不先分配整张画布大小的位图。
- 文档：现有导出窗口的 PDF 格式继续使用原有图文分页导出。
- 脑图：现有导出窗口选择 PDF。异步取得 simple-mind-map 已排版的完整 SVG，去掉视口平移缩放，通过 Qt WebEngine 打印；不是截取当前屏幕可见部分。保留中文字体、富文本的段落边距和节点图片。输出一张保持比例的整图页面，极大页面等比缩到 PDF 常规尺寸范围内。
- 格式下拉选择优先于预填的默认后缀，例如从默认 `note.docx` 改选 PDF，会写成 `note.pdf`。

## 开源组件与部署

入口与节点属于 Prism 的界面适配代码；平台解析与格式选择复用上游工具，没有重写平台解析算法：

| 平台 | 组件 | 固定版本 | 许可证 |
| --- | --- | --- | --- |
| 抖音 | F2 + curl_cffi | F2 f6be8c0ffba9a127075bbeafe4838716650b6325 / curl_cffi 0.16.3 | Apache-2.0 / MIT |
| 小红书 | XHS-Downloader | 3261312721f0b37c705ba6515885bc7f34349f2f / 2.8 | GPL-3.0 |
| B站 | bilibili-api-python + FFmpeg | 17.4.2 / 现有 FFmpeg 组件 | GPL-3.0-or-later / 按实际 FFmpeg 构建 |
| 其他网站 | yt-dlp | 现有组件 | Unlicense，另保留第三方声明 |

三个国内平台采用本轮验证成功的匿名访问路径，不自动读取浏览器 Cookie。平台仍可能限制具体视频、画质或访问；不能保证任何链接永久可下载，不绕过登录验证、DRM 或付费权限。

本机组件已准备。全新开发环境和构建机执行：

```text
python tools/setup_video_download_component.py
python tools/setup_platform_video_components.py
python tools/bundle_components.py --output <新的空 staging 路径>
```

三个平台分别运行于 `video-f2`、`video-xhs`、`video-bili`，不把其依赖混进 Qt 主程序环境。构建流程已加入准备命令，组件打包工具会携带对应运行时、源码与许可文件，不携带个人 Cookie、设置或下载目录。

XHS 的两处适配明确记录在准备脚本和组件清单：开启 TLS 验证；源类型是 video 时，不因多个封面帧错误地降成图集。适配器继续使用上游下载器与进度回调，把每任务写入缓冲限制为 1 MiB。

## 验证与边界

通过真实的 Prism QProcess 服务重新下载了用户最初给出的三个原链接，三个文件均完成音视频轨、时长与完整解码验证。最终复测还逐一核对了后台原件快照和下载文件的 SHA-256 一致。UI 20ms 事件采样持续响应，最终复测最长间隔约 47ms；这只是本机该次下载的测量，不代表所有操作的性能承诺。

有针对节点真实鼠标/键盘输入、取消、跨画布隐藏、场景销毁、原画布插入、保留选择、撤销/重做、右键裁切、PDF 格式选择及画布 PDF 实际渲染的回归。脑图 PDF 用真实 Chromium 渲染检查中文和两个分支，在视口被移到图外后仍能导出完整图。

本轮没有替换已安装 EXE，也没有发布新版本。需要重新启动最新源码版才能使用这些更改；后续安装版构建会携带这些组件。
