## 已证实的问题与修复

### 1. 添加贴图后仍是旧画面

VTK PBR 的生成代码直接采样 `tcoordVCVSOutput`，旧实现却为 UV0 的所有贴图注册自定义坐标属性，导致默认 varying 未定义。真实原生日志出现着色器编译错误，Python 的 `Render()` 仍正常返回。

修复前，WoodCarving 灰模、添加颜色、添加法线、添加 ORM 后四张图片的 SHA-256 完全相同；原始日志见 `artifacts/woodcarving-before.txt`。这证明之前的“任务完成”不能证明贴图生效。

现在 UV0 使用默认 TCoords；非零 UV 集同时注册属性和生成后采样替换；切换诊断通道时重建当前属性映射。独立 GPU 测试核对 UV0/UV1 像素差异、切换通道后恢复、再次回到 UV0，以及主动注入错误着色器必然失败。

额外的像素检查发现：线性法线图不能放进 VTK 的 PBR albedo 接口。通道查看现使用无光照的普通纹理路径，与完整 PBR 材质分开。测试检查输入 `(128,128,255)` 法线图的实际输出通道值，以及切回完整材质后像素恢复一致；透明度 0.25 的亮度变化、自发光开关的颜色差异也有像素对照。

### 2. 原生错误假成功及日志缺口

新增检查式 `MaterialRenderer.render()`，监听 VTK ErrorEvent，失败抛出异常，禁止将失败帧作为完成。原生输出进入日志，不创建 Win32 隐藏错误窗口。

预览进程失败事件包括任务、请求、模型、修订、草稿代次、材质数量、阶段、错误类型及耗时。预览和封面控制器都接回现有 `record_model_event`，封面进程失联不会错误地关闭正常预览的编辑能力。失败不记录贴图字节或 Base64。

### 3. 最新封面可能永远不生成

旧实现遇到已有封面任务直接返回，后续提交被合并掉，但旧帧又因为修订过期被拒绝，最终没有新帧。现在在途期间记录刷新请求，任务结束后再生成最新版本。最终仍按完整目标身份拒绝过期结果。

### 4. 透明与自发光上传后不生效

手动添加透明贴图、或把不透明材质的透明度调低，会启用混合模式；原本的裁切/混合模式保留。给无自发光的材质手动添加自发光贴图，初始化有效的颜色与强度。关闭自发光槽会清零其发光输出。AO 强度传入原生属性。

### 5. 重复解码和共享材质重复分配

派生 ORM/透明贴图命中缓存时，在解码原图之前返回，数值调整不重复解码 4K 图。活动纹理与本次安装准备按键复用；即使可选 LRU 小于当前模型贴图集，也不会对共享材质的每个 actor 重建同一纹理。原图不重采样、不减面、不覆盖。
