# Prism 后续功能开发与复用规范

本文针对当前桌面版结构。目标是让新功能接入已有能力，不让画布、脑图、文档、材质库分别造一套存储、标签和搜索。

## 现有模块怎么复用

| 能力 | 优先使用 | 新功能的接入要求 |
|---|---|---|
| 项目读写与版本迁移 | `prism/fileio/sql.py`、`schema.py` | 控件不直接开 SQLite 连接；继续保存在一个 `.prism` 文件里 |
| 原文件与附件 | `source_store.py`、`fileio/attachments_store.py` | 原文件和显示用小图分开，导出原文件前校验；读失败不能当成空文件写回 |
| 文件类型判断 | `media_types.py`、`asset_import_service.py` | 拖入、批量导入使用同一份分类；支持的显示格式可以比原文件格式少 |
| 文件夹与页面 | `workspace_service.py` | 使用稳定 ID、项目归属、父节点和回收站，不用名称充当 ID |
| 标签及全局搜索 | `tags.py`、`project_catalog.py`、`project_search.py` | 提供元数据和结果跳转，不单独建立另一份标签或搜索库 |
| 文件导出 | `export_service.py`、`fileio` 中对应格式模块 | 界面只选范围和路径；写文件和格式转换交给格式模块 |
| 材质参数、槽位与交接 | `material_service.py`、`material_parameters.py`、`material_transfer.py` | 记录业务含义，保留原图；预览调节与持久数据分开 |
| 材质和 GLB 显示 | Babylon.js + `widgets/material_render.py` | 扩展适配层；不再自写 PBR/GLB 渲染内核 |
| 文档和脑图编辑 | 已打包的 Quill、simple-mind-map | 复用编辑器，Python 负责附件、保存和项目交互 |
| 图片显示与大画布 | `image_decode.py`、`image_pyramid.py`、`lod.py`、虚拟化与瓦片模块 | 界面线程不解原图；滚动、缩放只调度可见区域 |
| Windows 文件拖出 | `external_drag.py` | 传真实文件 URL，不传预览截图；源文件路径在接收方读取前保持有效 |
| 操作与性能日志 | `performance_trace.py` | 记录阶段、任务编号、等待和执行耗时、失败；不记录图片内容 |

## 各层负责什么

1. 控件层处理输入、布局、显示状态和错误提示。
2. 工作流层负责一次完整操作，如“选范围→后台处理→显示结果”。
3. 服务层负责项目记录、分类、搜索、导入计划等业务规则，不依赖具体控件。
4. 存储层负责 SQLite、原始字节、版本迁移、写入失败回滚和备份。
5. 渲染/编辑器适配层把项目记录交给已有引擎，接回显示结果。

不要把所有后台任务合成一个无边界的“万能服务”。图片解码、文件 IO、浏览器渲染有不同的线程和资源生命周期，可以共享取消、任务编号、日志格式和过期结果检查。

## 新功能最少需要做到

- 元数据查询不解图片、不读整份附件；页面切换不重建所有缩略图。
- 文件原始字节和预览代理分开。转换只用于显示或用户明确选择的转换导出。
- 后台结果检查项目 ID、对象 ID、版本/请求编号。旧任务不能更新新打开的项目。
- 缓存明确键、失效条件、内存上限和清理时机。占位图不能充当真实资源已加载的标志。
- 保存不能与加载或另一轮保存重叠。写失败必须保留原文件，不将读取失败结果写为 `NULL`。
- 页面提供加载、保存、关闭/释放三个明确阶段；编辑器切换不丢未提交内容。
- 文件级操作 QAction 挂在主窗口，局部编辑快捷键留给对应编辑器。
- 菜单不启动无必要的嵌套事件循环；重复打开不会残留菜单或吞输入。
- 错误日志带阶段与对象 ID。性能指标区分同步处理耗时、完整显示等待、首次与重复操作。
- 用真实业务回归：修改→切换→保存→关闭→重开→导出校验。不能只断言某个内部函数被调用。

## 推荐的逐步拆分顺序

1. **先保证存储与数据完整性**：补上大项目完整保存、另存为、取消、写失败、关闭重开的回归。持久化模型与 GUI 对象的混用是优先治理项。
2. **再清理界面线程里的 IO**：统计大小、缩略图、原图处理走已有后台入口；缓存元数据由项目加载/保存发布。
3. **再收敛跨模块重复规则**：文件类型、资源定位、标签、任务状态、导出范围逐项合并；保留原 API 的兼容导出。
4. **逐项缩小大文件职责**：`view.py` 留视图交互，`items.py` 留图元；业务迁往已有服务或工作流。避免一次性移动全部代码。
5. **最后增加新业务模块**：使用上述接口注册入口、数据、搜索和导出能力，每次只引入一个可回归的切片。

文件长度只是定位职责混杂的线索，不是要求机械拆成固定行数。先有可重复测试和实际调用边界，再拆文件。

## 验证入口

### 编辑器提交约定（2026-10-20 补充）

- 模块导入不能替换宿主的进程异常钩子或启动桌面监听。只有应用 main 入口安装异常处理器；测试要保留 pytest-qt 的异步异常捕获，校验进程退出码，不能只看通过数量。
- 重型可选后端的导入也属于工作量：视频缩略图由现有工作线程导入 PyAV，失败后切回 QtMultimedia；GUI 不应为了 available() 检查先加载一遍原生解码库。
- 导航树复用主窗口设置对象，保持按 projectId 隔离。不要在每次滚动/展开的 debounce 回调重新创建设置存储；独立组件允许注入设置依赖。
- 性能日志自身失败不能阻断用户事件。Qt 对象可能用普通属性覆盖方法，诊断读 QObject 元信息时调用 Qt 基类接口；后台事件不计入 GUI 响应性。心跳延迟应附带最近 GUI 事件完成数据，区分阻塞与计时器饥饿。

- `store_to_scene()` 在活跃网页读取失败、超时或项目身份改变时返回 `False`。保存、导出、页面切换、删除当前页面和关闭窗口必须中止当前操作，不能拿旧缓存假装保存成功。尚未启动网页或主程序数据等待下发时，主程序持有的数据仍是权威来源。
- 页面导航共用 `WindowWorkspaceMixin._store_current_page()`。标签回退不能触发文档从 scene 重新载入，否则会在保护失败后再次覆盖未提交内容。恢复快照也不能在读取失败后覆盖之前的快照。
- 脑图导入调用 `MindMapPanel.set_tree()`，禁止先写私有 `_tree` 再读回旧网页。文档导入复用 `set_html()`。新增编辑器也应提供明确的内容替换入口。
- 屏幕预览和成品输出分开：视口可以使用 LOD，`scene.render()` 的成品输出要按源分辨率取图，临时解码像素不能长期留在每个图元上；原文件导出保持源字节。用黑白单像素条纹验证输出细节，不能只断言“导出成功”。

网页编辑器的即时保存统一使用 `widgets/editor_snapshot.py`：有界等待当前网页内容，过期回调丢弃，调用方在提交前再次检查项目身份和控件生命期。文档与脑图均复用此入口；宿主推送尚未确认时禁止反向读回旧页面。

保存时使用 `fileio/save_snapshot.py`：GUI 提交编辑器后复制文档、脑图、页面、材质、分类、标签和附件成员列表，worker 写入这份独立数据。附件保持惰性读取，不为了创建快照解码或加载全部文件；成功后在 GUI 确认源库重绑定，只清除本次确实保存的附件修订。保存失败、新项目身份或之后的新编辑不能被标成已保存。保存准备、worker 运行、GUI 确认三个阶段都必须防止重入。文件读写期间不允许新建、打开替换或关闭当前项目，以免销毁 worker 仍使用的场景。

这还不是整个场景的线程隔离：画布几何和图元源引用仍沿用原有写入路径。后续应在 GUI 提取不含 Qt 对象的画布 DTO，并设计 save_id、删除源保留、Save As 重新绑定和撤销修订确认，再让 worker 完全脱离 live scene。冻结快照外壳或只加版本号，都不能代替这项工作。

搜索结果卡片统一复用 `SearchCard`，素材浏览器不要另写一套文档/脑图预览绘制。全局类型筛选传入共享搜索服务，不能在某个视图里强制覆盖成“素材”而让类型选择失效。

画布裁剪要按实际绘制区域验收。Qt 的 `QGraphicsScene.render()` 可能给虚拟图层传入整个图层的 `option.exposedRect`；绘制前需要结合 painter 的实际裁剪区域查询空间索引，不能把同一批不可见记录重复画进每个瓦片。至少保留“100 张分散图片，单图区域只访问 1 张”的回归，并验证裁剪、旋转、堆叠和导出像素。

异步任务完成后，业务记录仍有效与 Qt 控件仍存活是两个独立条件。回写 UI 前必须同时验证；错误处理和 finally 回调同样不能访问已销毁控件。

- `python tools/run_tests_safe.py --platform windows --timeout 120 --report artifacts/full-audit/full-suite.txt`
- `python -m pytest tests/test_architecture.py tests/test_archive_size_cache.py`
- `python -m flake8 prism tools --select=E9,F63,F7,F82,F402,F601`
- 本机真实项目深测：先制作副本，再显式运行 `tests/_audit_actual_project.py`。私人项目数据和下载素材不加入发行包或公共 CI。

自动化测试崩溃、超时、跳过和断言失败必须分别记录；进程崩溃不能因为前面的断言通过而算通过。全量测试报告和已修复后的复测要分别保留。


## 2026-10-20 缓存和范围查询边界

缓存目录应复用会话中已配置的 `thumbnail_cache.cache().directory`，图像金字塔不得对每张图片重新创建 QSettings。资源树保存焦点、展开和滚动位置前先比较当前值；恢复布局发出的重复信号不应触发无效设置落盘。设置保存和图片解码使用不同资源生命周期，不要把设置对象传进解码 worker。

空间查询先复用 `AssetSpatialIndex`。查询路径完全包含索引边界时，可以直接判定命中；边缘、旋转角落、孔洞等情况仍使用 Qt 精确路径判断。性能回归要同时验证精度，不得将所有形状查询直接改为包围盒相交。


## 2026-10-21 大工程显示与缓存补充规范

- 原图、显示级别、分组合成、世界瓦片是不同的数据与生命周期；显示缓存失败不允许修改原图。SQLite的BUSY/LOCKED是暂时争用，不等于损坏，不能据此删除缓存库。预览读写必须短等待并能退回源数据；写事务失败后回滚，线程只关闭自己的连接。
- 分组预览复用既有Qt delegate，不另写图片或材质渲染内核。缓存层限额独立记账；同一分组的新旧分辨率替换必须先减去旧占用，淘汰和失效同步维护索引。
- 相机可见区域决定任务优先级与图像LOD。临时粗瓦片或过采样细瓦片的尺寸不能改变单图请求级别，避免32/64/192反复争抢解码队列。轮点附近优先，离屏过期工作让位。
- 冷启动覆盖和后台预取必须分开。只有真正缺少屏幕可见覆盖时才能绕过等待规则，不能因邻近的离屏瓦片没有缓存就同步重绘数千图片。无可执行工作时暂停瓦片计时器，等待数据或相机变化再启动；已画好的真实像素保留到替换准备好。
- 缩小到全局时限制局部重画，避免一个分组完成就触发大范围原图遍历。中距离可先发布焦点区域，完整细化仍要有绘制预算；不能仅凭“缓存数据已到”宣称屏幕已经清楚。
- 回归测试必须观察Qt实际绘制与当前视口。滚动条出现后的视口变化要重新读取，不能要求已离屏图片继续加载；测试也不能调用请求高清的接口替UI补图。合成棋盘细节的像素对比与真实资产压力测试互补，二者不可互相替代。
- 性能报告分别记录打开、操作分布、实际强制绘制、焦点/全视口清晰恢复、父进程内存和未统计范围。包含等待时间的操作样本不能换算固定FPS；一次通过不能掩盖耗时尖峰或实验回退。


### 显示缓存测试边界（2026-10-21）

- 缓存就绪不代表屏幕更新。LOD、分组合成、tile至少各有功能回归，并用真实viewport截图检查最终源图像素。测试不得调用请求高清接口替UI补工作。
- 诊断缓存使用get(touch=False)，避免观察器改变LRU淘汰。记录观察本身耗时，重型轮询不得混同产品耗时。
- 对接近屏幕采样极限的细纹理，固定对比阈值会随采样相位变化。保留细节焦点测试，另用可辨识大色块验证全视口发布，区分画质、采样与调度。
- 合成分片progress只能因真实源/裁剪/模型变化取消；同一源的更清晰预览到达应保留progress，并将旧部分标stale补画，避免每张解码重启整组。


### 编辑器模块复用与验收

- 文档沿用Quill，脑图沿用simpleMindMap；容器负责页面ID、生命周期、快照与持久化，不复刻引擎编辑逻辑。
- 切换模块前通过统一_store_current_page读取引擎最新快照，不能只信最后一次异步change回调。快照失败应拒绝切换/保存，避免覆盖新内容。
- 同工程页面返回应复用_page_panels实例；新工程打开则重新绑定场景，禁止沿用旧project内容。分别记录首次ready与复用返回时间。
- Python/mock契约、实际QWebEngine编辑切换、小样本保存重开、真实大型工程完整性要分层记录，不将一层通过描述为全部功能通过。


### 原生PBR参数映射验收

- 不以JS属性读回等于目标值作为渲染正确证据，还要在同一素材上比较最终像素响应，并验证恢复默认。
- 当前Babylon PBR的OPACITYRGB路径会以贴图亮度覆盖材质alpha；透明度倍乘需映射原生opacityTexture.level，既有素材复用时也必须更新/恢复。禁止改shader内核修补应用参数映射。
- 连续alpha与二值裁切素材分开验证；SSS需说明实际采用的引擎模型（当前为薄表面Burley透射），不将引擎开关通过宣称为所有UE材质等价。


### 异步图片刷新接口约定

- request_display_refresh(item)表示某个源预览像素更新：只累计该card区域dirty；显式无item刷新仍表示全视口刷新。
- wake_display_queue只恢复细节请求调度，不意味着像素变化。解码器空出队列槽应使用该入口，禁止用全屏invalidate作为唤醒副作用。
- _publish_display合并实际dirty区域后交给共享CanvasTiles失效，场景/模型结构变化仍走全失效。分组完成另以自身bounds发布。
- 安全回归通过不等于性能候选成功；保留前后相同阶段的调用次数与时间。v42可见tile优先候选因构建次数回升而撤回。
