## 1. 已确定的产品边界

用户工作链：导入模型 → 中间列表显示模型封面 → 使用现有贴图槽位或应用已有材质 → 更新效果与封面 → 双击交互查看 → 单个或批量导出原件。

### 1.1 必须复用的现有能力

- 左侧资源树、文件夹管理、导航提交与页面切换。
- 材质库的卡片风格、网格／列表、卡片大小、多选、右键操作。
- 标签系统、备注系统、搜索及管理约定；新增模型载体接入，不再建一套系统。
- 现有贴图槽位控件、贴图准备和通道处理能力。
- 原件存储、附件读取、保存快照、部分项目保存、项目搬迁与诊断基础。
- 当前材质库及其 Babylon 渲染保持原有职责。模型库使用模型后端适配器，不把 Babylon 材质对象直接传给 F3D。

### 1.2 模型库界面

左侧顺序：材质库 → 模型库 → 标签。模型库是项目资源入口，不要求用户新建画布页。

中间：

- 卡片主体是当前材质效果的模型封面图片，不是统计文字，也不是每张卡片一个实时三维场景。
- 卡片下方显示名称、现有标签。格式可作为简短角标；详细统计集中在右侧。
- 更换贴图后，旧封面可暂时保留，但必须显示“封面更新中”；不能把旧图标为最新。
- 支持网格／列表、大小调整、多选、批量移入分类、批量导出。
- 大量数据采用可见区域复用与有界图片缓存；不能仅向下追加所有卡片。

右侧：

- 模型封面／当前效果、打开大预览、更新状态。
- 现有贴图槽位，不增加“材质槽管理”页签。
- “版本与文件”：格式、大小、统计口径、主文件、依赖清单、缺失项、导出原件。
- 现有标签、备注。

双击：

- 同现有大预览一致的外观与工具栏，支持旋转、缩放、平移、回正、设为封面、返回。
- 完整材质、材质加边线、纯线框。纯线框需要适配，不冒充 F3D 现有边线开关。
- 默认只保留一个模型大预览窗口；切换模型复用窗口。多模型多窗口不作为首版要求。
- 第一版以整模型应用一份库材质或通道覆盖为范围；导入时保留模型原有多材质效果。逐部位点选换材质、材质槽管理不是首版承诺。

### 1.3 格式及导出

| 格式 | 入库与交互查看目标 | 原件导出 |
|---|---|---|
| FBX | 由 F3D Assimp 插件读取；验证静态、骨骼与贴图样本 | 原 FBX 与已收集依赖 |
| OBJ | 验证 OBJ、MTL、多材质与外部贴图 | 原 OBJ、MTL、贴图及目录结构 |
| GLB | 验证内嵌资源及存在时的外部依赖 | 原 GLB 与依赖 |
| glTF | 验证 JSON、BIN、贴图、内嵌 data URI | 原 glTF 文件包 |

不为交互预览强制转换 GLB。F3D 读取原始文件到内存场景，再生成交互画面和封面。

只交付“导出原件”，包括单个、批量。库内贴图调整属于 Prism 项目数据，不写回原件，也不随“导出原件”改写 FBX、OBJ 或 glTF。

首版暂缓：修改后模型文件导出、格式转换、建模、减面、重拓扑、动画编辑、骨骼修改、CAD 与 DCC 专有工程格式、在线素材商城、团队共享数据库。

### 2.3 必须先验证或小范围扩展的能力

1. 纯线框：现有 render.show_edges 最终设置 SetEdgeVisibility，只能确认边线叠加。计划在独立的小补丁中增加表面／边线叠加／纯线框表示方式，并验证切回后原材质恢复。
2. 几何统计：当前 SceneInfo 只有文件数、Actor 数、点数与 Cell 数。不能把 Cells 命名成三角形数。计划新增统计适配，分别报告加载后的多边形、三角形、点线元素及实例口径；无法证明原始 DCC 多边形数时明确不提供。
3. 材质映射：Prism 的 Babylon 材质对象不能直接交给 F3D。UI、原贴图和参数能复用，渲染对象需要重新绑定。
4. SSS、置换、复杂透明、UDIM 和 DCC 专用着色器没有得到同等支持的验证。第一轮样本实验必须形成能力表；未支持项不得显示为已经生效。若这些是首版必需项，必须先扩大后端能力验证，再冻结交付范围。
5. 官方 Qt 示例在 initializeGL 中加载模型，并使用定时更新。它是接入参考，不能作为“不阻塞主界面”或大规模性能的证明。

小补丁范围预计涉及 library/options.json、window_impl、vtkF3DRenderer，以及 scene_info_t、vtkF3DMetaImporter 和 Python 统计绑定。具体文件集合以第 2 步实验结果冻结。每个补丁独立提交、独立验证，不在 Prism 业务层绕用 F3D 私有对象。

贴图槽位映射的验证起点如下。这是已存在选项的对接设计，不代表已经验证与材质球等效：

| 现有操作 | F3D 对接起点 | 交付时必须检查 |
|---|---|---|
| 颜色贴图／颜色值 | model.color.texture、model.color.rgb | 色彩空间、颜色乘数、透明通道 |
| 法线与强度 | model.normal.texture、model.normal.scale | DirectX／OpenGL 方向、强度、UV |
| AO／粗糙度／金属度 | model.material.texture；model.material.roughness、metallic | ORM 通道打包和贴图乘数，不能漏 AO 或乘两次强度 |
| 发光 | model.emissive.texture、model.emissive.factor | 贴图与强度在封面、大预览中一致 |
| 透明度 | model.color.opacity 与颜色纹理 Alpha | 不透明、裁切、半透明分别验证；独立透明图需要预览用合成适配 |
| 贴图变换 | model.textures_transform | 全局变换与现有每通道控制是否等效；不等效必须明确能力差异 |
| SSS／置换等高级项 | 尚无已验证的一一对应 | 第 2 步决定补齐成本和首版范围，不能直接宣称完整复用 |

## 3. 推荐代码架构

### 3.1 总体关系

~~~text
Prism 主进程
  现有资源树、导航、标签、备注、搜索、项目保存、日志
                     │
  共用库外壳 ──── MaterialLibrary（原有）
       │
       └──────── ModelLibrary（新增模型展示适配）
                        │
                  ModelLibraryService
                  ├─ ModelRepository：元数据、版本、事务
                  ├─ ModelImportService：依赖收集、原件入库
                  ├─ ModelExportService：原件完整导出
                  ├─ AppearanceAdapter：现有槽位与贴图准备
                  └─ ModelTaskController：优先级、取消、结果提交
                              │ 独立本地通信协议
             ┌────────────────┴────────────────┐
   F3D 离屏任务进程                    F3D Qt 大预览进程
   读取／统计／封面                    交互／显示模式／设封面
             └────────────────┬────────────────┘
                       同一 F3D 参数适配器

所有持久数据 → 当前项目存储体系
派生图片与预览工作文件 → 有预算、可重建的缓存
所有事件 → 当前 Prism 日志与诊断包
~~~

右侧默认显示封面和更新状态；修改贴图触发异步渲染更新。双击的大预览是外观沿用现有窗口的独立 Qt 窗口，由辅助进程托管。它不是强行把另一个进程的原生窗口塞进主界面。

这样设计的目的：

- F3D／VTK 读取或原生渲染崩溃不直接终止 Prism 主进程。
- 原生长调用不在 Prism 主 GUI 线程执行。
- 不需要改造现有材质库渲染器。
- 不引入跨进程窗口重挂接、共享主窗口 OpenGL 上下文等额外不确定性。

独立预览进程仍可能在加载大文件时短暂不可操作；主进程必须能显示加载状态、取消请求并终止卡住的辅助进程。不能把“主进程没有卡”当作预览加载性能合格。

### 3.2 模块划分建议

建议新增以下职责模块，名称可随仓库约定调整，职责边界固定：

| 模块 | 职责 | 不承担什么 |
|---|---|---|
| model_contracts | 记录、协议、状态、能力与错误码定义 | 不导入 Qt 或原生渲染 |
| model_service | 创建／编辑／删除／恢复模型，校验修订号 | 不直接复制文件或渲染 |
| model_repository | 模型域查询、分页、事务与保存接线 | 不创建第二套项目数据库 |
| model_import | 导入规划、依赖解析、哈希、提交 | 不改变模型拓扑 |
| model_export | 原件清单核对、临时目录、完整导出 | 不重新编码模型或贴图 |
| model_appearance | 现有贴图槽位 → 可保存配置 → F3D 参数／派生贴图 | 不修改原始贴图 |
| model_jobs | 任务去重、优先级、取消、重试、进程监督 | 不直接碰界面控件 |
| model_f3d_backend | 受控调用 F3D API，版本／能力适配 | 不依赖主窗口或 scene 全局变量 |
| components/model_worker | 离屏任务进程入口 | 不打开用户交互窗口 |
| components/model_preview | Qt 交互进程入口 | 不直接写项目数据库 |
| widgets/model_library | 模型库控制器，共用卡片与布局 | 不重新实现标签／备注 |
| widgets/model_details | 右侧模型信息和现有贴图控件接线 | 不承担后台加载 |

共用外壳以小范围提取为原则，不建设庞大的插件框架。MaterialLibrary 继续保持现有接口；材质库与模型库通过展示适配传入标题、卡片摘要、右侧面板和操作回调。

### 3.3 通信、任务与提交

主进程独占项目数据库写入权。辅助进程只读经过授权的工作目录，并输出结果文件与小型结构化消息。

使用专用本地通信通道传递协议，不能把 F3D stdout 当成可靠 JSON 协议。原生日志独立接收。

每个请求必须带：

- 协议版本、项目会话 ID、打开代次。
- 模型 ID、原件修订、外观修订、相机修订。
- 请求 ID、任务 ID、任务类型和优先级。
- 原件清单引用、外观配置引用、输出路径。
- 固定的 F3D／插件／适配器版本。

结果写入项目或替换封面前，再核对所有者与修订。模型被删除、项目被切换、贴图被再次修改或窗口已关闭时，旧结果只能丢弃，不能覆盖新状态。

默认资源并发：一个离屏 F3D 任务进程、一个交互预览进程；磁盘扫描／复制另受 I/O 并发预算限制。大预览优先，重型预览可暂停并释放后台引擎。具体预算由第 2 步测量后冻结，不能凭 CPU 核数无限增加引擎。

任务优先级：当前模型交互／当前外观更新 → 可见卡片缺失封面 → 用户指定批量任务 → 空闲预生成。被取消和失败项不算完成。

## 4. 数据、存储与原件正确性

### 4.1 数据身份

| 数据 | 所有权与持久规则 |
|---|---|
| 模型记录 | 项目拥有，稳定模型 ID，与文件名解耦 |
| 原始主文件与依赖 | 导入时收存到项目管理资源，字节不可变，SHA-256 校验 |
| 补选资源 | 单独记录补充来源，不伪装成导入时就存在的原件 |
| 外观配置 | 项目拥有，保存贴图引用、通道、强度等；有独立修订号 |
| 应用库中材质 | 保存当次配置及受管理贴图引用的快照；不跟随源材质以后自动变化 |
| 封面角度 | 项目数据，和模型绑定；换机器重开仍可重建封面 |
| 几何统计 | 派生信息，注明统计口径、算法与后端版本 |
| 封面 PNG／预览工作目录 | 派生缓存，可清理、可重建，有预算与使用租约 |
| 原件导出 | 某一确定原件修订的完整副本，不包含库内外观覆盖 |

### 4.2 元数据结构

建议增加 model_records 和 model_files 领域表或等价的现有存储映射：

- model_records：ID、所属项目／文件夹、名称、备注、标签引用、主文件 ID、格式、原件修订、外观修订、封面相机、状态、统计摘要、创建／更新／删除时间、未知字段。
- model_files：模型 ID、文件 ID、角色、包内相对路径、原始名称、大小、哈希、受管理 source_ref、依赖来源与缺失状态。
- 外观配置保持独立可修订，可存于模型记录的明确字段；不与原始文件清单混用。
- 可查询的名称、格式、文件夹、删除状态及必要排序字段建立索引；卡片只读取摘要。
- 标签沿用项目现有体系，新增模型载体绑定和计数，不建立同名的另一套标签表。

表名只是实施建议；禁止为了模型库替换整个项目数据库或重新迁移现有材质记录。若现有存储后端要求不同映射，保持同一领域契约，统一实现全量／部分保存。

模型原件通过现有受管理资源／附件后端扩展接入。大文件必须有路径或流式读写接口；不能让全部模型字节常驻 scene，也不能为方便塞进只面向图片的小对象缓存。第 3 步先验证大文件通道，再决定需要补哪些适配。

### 4.3 必须接入的保存边界

- 全量保存、另存为、自动保存、保存重开。
- BoardSaveSnapshot 或等价模型域快照；后台保存不得读取后来的可变界面状态。
- PartialDomain／PartialProject：模型域覆盖范围、明确删除、冲突检查与保存确认。
- 保存期间继续编辑：保存 A 修订成功后不能清掉 B 修订的待保存标记。
- 只加载一部分项目：未载入的模型、字段、文件与依赖必须保留。
- 删除／恢复／回收站、附件引用与资源租约；缓存清理不能删除原件。
- 只改标签、备注、封面角度时，不重新写入模型和贴图大文件。
- 旧工程升级采用新增结构；不破坏原材质和页面。含模型的新工程被不识别模型域的旧版本打开时，必须阻止静默覆盖或明确提供安全只读／兼容副本路径。

### 4.4 模型依赖与可搬迁

- OBJ：解析 mtllib 和 MTL 贴图引用，保留大小写、空格、重复文件名与目录层级。
- glTF：区分外部 BIN／图片、内嵌 data URI 与缺失资源；不自动访问远程 URL。
- FBX：区分内嵌／外置贴图、相对／绝对引用；记录真实依赖来源。
- 包内相对路径与临时输出路径分别校验。不能因 ../ 或同名文件把依赖写到错误位置。
- 同一模型不同目录里的同名贴图必须分别保留；不能用哈希前缀随意改名导致原引用失效。
- 原件引用了绝对路径时，“字节不变”和“所有外部软件搬迁后无需指定资源目录”不能同时自动保证。原件不改写；导出时提供路径对照与缺失说明，Prism 预览使用自身依赖映射。
- 缺文件时允许入库为“不完整”；不得显示“依赖完整／导出完整”。导出不完整原件包需要清楚列出缺失项，不能报完整成功。

## 5. 分 12 步实施

每步均有可单独评审的结果。日志埋点从第一步进入，步骤 11 是汇总与故障验收，不是到最后才开始记日志。

### 第 1 步：冻结范围、数据契约与独立样本

做什么：

- 固定本方案的 UI、四种格式、原件导出与现有能力复用范围。
- 定义记录、修订、文件清单、任务协议、错误码、统计口径和日志字段。
- 建立真实样本及独立期望清单；记录当前 Prism 的材质库、保存和导航基线。
- 对本地 F3D 源码生成版本清单，选择可重复构建的固定提交或发行包；下载目录只作为源码参考，不作为运行时依赖。

效果：后续开发不再各自解释“原件”“封面已更新”“三角形数”。

交付标准：范围表、字段表、样本清单、原件哈希清单、已测／未测表及基准环境齐备。样本期望不从待实现的读取器反向生成。

### 第 2 步：F3D 最小验证，决定是否进入正式集成

做什么：

- 在隔离实验入口验证四种格式、插件加载、PyQt6 窗口、离屏输出和日志转发。
- 使用同一参数验证封面与交互窗口外观一致。
- 验证基础 PBR 槽位映射；记录不支持的 SSS／置换等能力。
- 验证边线；制作纯线框和统计适配的最小补丁，确认维护成本与正确性。
- 注入坏模型、超时和原生进程异常，验证主进程不受牵连。
- 记录首次启动、冷加载、内存／显存峰值与退出资源释放。

效果：真实证明“能读取、能看、能上贴图、能出封面、能隔离失败”。

交付标准：至少覆盖第 8 节样本类别；格式／材质／统计／显示模式能力表有实测证据；未通过的必需能力有明确修复路径与成本。未通过不能直接扩大改造，也不能在后台偷偷改成模型转换流程。

### 第 3 步：模型域与项目存储

做什么：

- 实现 ModelRepository、模型字段校验、来源与依赖清单、原件资源接入。
- 接入全量、部分加载／保存及快照确认。
- 验证未知字段保留、小修改写入量、大文件流式通道、删除恢复和另存为。

效果：即使没有界面，也能安全持有一条模型记录及完整原件。

交付标准：保存重开字段与原件一致；保存中继续编辑不丢；部分工程保存不删除未加载模型；项目搬迁后原件可读；不把模型塞进材质图片校验规则。

### 第 4 步：提取共用库界面，保持现有材质库行为

做什么：

- 为卡片提供资产展示摘要适配，不再写死“贴图数量／材质分辨率”。
- 共用网格／列表、选择、滚动状态、右键、空状态、大小控制。
- 增加可见区域复用与缓存预算；控制传给 WebEngine 的数据批次。
- 增加模型详情外壳，复用已有槽位、标签和备注控件。

效果：同一套布局可展示材质或模型，模型卡片主体始终是封面。

交付标准：现有材质库操作基线通过；切换两库不串选中项／滚动位置／右侧详情；长时间滚动不持续累积所有卡片节点和图片。

### 第 5 步：独立 F3D 后端与大预览窗口

做什么：

- 建立版本握手、reader 清单、参数适配、进程监督、本地消息协议与超时处理。
- 基于 Qt6 示例改造独立 PyQt6 大预览窗口，套用 Prism 的现有主题和工具栏约定。
- 接入鼠标、滚轮、回正、窗口缩放、显示模式、设封面与关闭。
- 默认一个预览窗口；项目关闭／切换时取消旧任务、停止读取、释放缓存租约。

效果：双击原始 FBX／OBJ／GLB／glTF 直接交互，不生成中间 GLB。

交付标准：DPI、窗口焦点、快捷键、关闭、项目切换、超时终止与重开正确；坏文件或辅助进程崩溃不会退出主程序；取消不能只改文字，必须停止或隔离实际任务。

### 第 6 步：模型与依赖导入

做什么：

- 文件／文件夹拖入和导入按钮接同一导入服务。
- 后台扫描、依赖收集、流式复制与哈希，临时阶段完成后提交模型记录。
- 显示阶段、当前文件、成功／失败／缺失／取消数量；不对不可估算的耗时显示假进度。
- 同字节原件可复用受管理资源，但模型记录保持用户可区分；去重不等于自动合并资产。

效果：导入后立即出现模型卡片和状态，封面可以随后补齐。

交付标准：中文／空格路径、同名依赖、外置 BIN／MTL、缺文件、取消、磁盘满、原件在复制期间改变均有确定结果；未完成项不会被标为成功。

### 第 7 步：封面、统计与后台调度

做什么：

- 基于离屏示例生成封面；优先可见卡片与当前模型。
- 保存封面角度和渲染配置，封面缓存带完整签名。
- 后台统计，注明加载后数据／实例口径；原始拓扑未知时不伪造。
- 复用同一原件的已加载引擎来更新外观封面，避免滑动一次参数就重读大模型。
- 快速修改只保留最新任务；原件变化、外观变化和相机变化分别失效相应缓存。

效果：模型列表逐步出现正确封面，统计不会阻塞浏览。

交付标准：旧项目／旧模型／旧贴图配置的结果不能回写；封面清缓存后可重建；列表不加载全模型；失败有占位与重试入口，不使用默认材质球冒充模型封面。

### 第 8 步：接现有贴图槽位与材质库应用

做什么：

- 现有颜色、法线、粗糙度、金属度、AO、透明与发光等经过能力表映射。
- 优先复用现有贴图准备；独立粗糙度／金属度／AO 按 F3D 要求生成预览用 ORM。
- 通道、法线方向、强度、透明与色彩空间用受控样本核对。
- 应用已有材质时生成模型自己的配置快照；支持恢复原始外观和撤销本次修改。
- 大预览与封面使用同一外观修订和同一派生贴图。

效果：用户继续按材质球的操作上贴图；封面与大预览显示当前模型效果。

交付标准：参数实际生效，不支持项有明确状态；修改 A 模型不影响 B 模型或源材质；保存重开配置一致；任何预览加工不覆盖原始图片。

### 第 9 步：接入导航、标签、备注、搜索与管理

做什么：

- 在现有树与库控件注册中增加 model 分区和模型详情切换。
- 复用导航提交、前后状态、当前页保存与返回位置。
- 扩展标签载体、过滤、计数、回收站及全局搜索结果跳转。
- 名称、备注、标签、分类等编辑走同一模型服务和修订机制。
- 统一计数：模型条目数不包含贴图／BIN／封面数量；过滤命中数、已显示数、后台待完成数分开。

效果：模型库像现有材质库一样属于当前项目，跨模块操作不丢上下文。

交付标准：材质和模型计数不串；重开回到合理位置；搜索定位到正确模型；不同项目同名模型不串任务；未加载域不被误删。

### 第 10 步：原件单个与批量导出

做什么：

- 固定导出时原件修订和依赖清单，校验可读性、大小与哈希。
- 按模型独立目录输出，保持内部相对路径，不转码、不修改内容。
- 先写临时目录，验证后发布；取消／失败清理临时项，已完成项可列清。
- 对缺依赖、绝对路径引用、重名和权限失败给具体清单。
- 复用现有文件对话框、防覆盖、后台任务和原件校验基础。

效果：单个或多选模型完整取回导入原件。

交付标准：独立校验器验证文件集合、目录关系、大小、哈希；不漏 MTL／BIN／贴图，不把封面替代模型；导出不会修改项目原件。批量部分失败不能显示“全部成功”。

### 第 11 步：日志、诊断包与恢复

做什么：

- 汇总贯穿前十步的事件与性能跨度，关联导入、原件、预览、封面、保存和导出。
- 接入 F3D Log.forward，控制等级，捕获辅助进程退出、stderr 与退出前的有限日志。
- 将模型后端版本、队列、资源、失败清单和裁剪信息纳入现有诊断包。
- 验证日志磁盘满、写线程失败、异常风暴和大量重复警告。

效果：用户报告“这个模型打不开／封面不更新／导出漏图”时，能沿同一个请求追到失败阶段。

交付标准：可定位故障，不记录原件二进制或贴图 Base64；诊断导出脱敏、有界；日志失败不阻止编辑与保存；记录丢失或裁剪不能伪装成完整证据。

### 第 12 步：端到端、规模、资源与打包验收

做什么：

- 用完整用户链路测试，不用内部 API 成功替代界面结果。
- 做 100／1,000／10,000／100,000 条规模矩阵、冷暖缓存和长期运行。
- 独立核对保存重开、搬迁、导出原件和故障恢复。
- 固定 F3D、VTK、插件和运行时，验证离线安装、升级与回退。
- 回归原材质库、画布、文档、脑图的关键导航／保存链路。

效果：交付的是可用的模型库，而不是只有截图的演示。

交付标准：第 8～10 节标准通过，失败和未测项保留，完整版本与环境可重现。原件丢失、保存丢编辑、旧结果覆盖、错误报成功、主程序被辅助进程拖垮均为阻断发布问题。

## 6. 可以怎样并行开发

这里描述实施时的分工，不代表本次启动团队或修改实现。

| 工作线 | 可独立承担的工作 | 专属主要文件 | 依赖 |
|---|---|---|---|
| A 数据与原件 | 第 3、6、10 步 | model_repository、model_import、model_export | 第 1 步契约；第 2 步后确定正式范围 |
| B UI 与外观 | 第 4、8 步 | 共用卡片适配、model_library、model_details、model_appearance | 第 1 步摘要接口；第 2 步能力表 |
| C F3D 后端 | 第 2、5、7 步 | model_f3d_backend、两个进程入口、F3D 独立补丁 | 第 1 步协议；第 2 步是扩大工作的门槛 |
| D 日志与验收 | 第 1 步样本／基线、第 11、12 步 | 模型日志适配、独立核对与性能场景 | 契约确定后贯穿全程 |
| 集成负责人 | 第 9 步及共享保存／导航接线 | __main__、window_workspace、workspace_service、保存域、全局搜索／标签入口 | A/B/C 各自交付接口 |

推荐顺序：

1. 第 1 步统一契约；第 2 步先做最小实验。
2. 实验通过后，第 3、4、5 步并行；D 线同步建立日志和验收工具。
3. 数据通道可用后做第 6 步；后端可用后做第 7 步；两者与第 8 步逐步联调。
4. 第 9 步由集成负责人集中接线；第 10 步可以和 UI／预览收尾并行。
5. 第 11 步完成诊断闭环，第 12 步统一验收。

禁止并行冲突：

- 不让多人同时修改 material_library.py、cards.js、__main__.py 和 partial_project.py。
- 协议／数据结构变更由一个负责人发布版本，其他人通过适配跟进。
- 不让渲染后端直接改标签、保存域或全局搜索代码。
- 不在同一个提交里同时重写材质库和增加模型库。
- 端到端期望集与原件核验由独立验收工作线维护，不能只复述实现方返回值。

## 7. 日志设计

### 7.1 复用位置

- 业务／异常：现有 prism/logging.py 和 Prism.log。
- 交互／性能／队列：prism/performance_trace.py 的 TraceContext、operation、QueueAccounting、ResourceAccounting。
- 诊断导出：prism/diagnostics.py，扩展允许的模型摘要与来源清单。
- 辅助进程日志由监督器关联项目、模型与请求，再汇入已有日志体系。若另设原生崩溃日志，必须同时接入诊断包允许规则和轮转。

### 7.2 必记事件

| 阶段 | 事件及结果 |
|---|---|
| 后端启动 | 版本、构建、reader／插件、图形后端、能力表、启动失败 |
| 导入 | 扫描、依赖收集、复制、哈希、提交、缺失、失败、取消 |
| 列表 | 查询、摘要安装、可见卡片数、图片请求与安装、缓存预算 |
| 预览 | 入队、排队时间、准备、原生加载、渲染、首画面、关闭 |
| 外观 | 外观修订、合并旧任务、派生贴图准备、结果提交／过期丢弃 |
| 封面 | 签名、缓存命中、生成、发布、失败、失效、重建 |
| 保存 | 快照修订、实际提交修订、资源绑定、更新确认、冲突 |
| 导出 | 固定清单、校验、写入、复核、发布、部分失败、回滚 |
| 故障 | 超时、退出码、原生崩溃、重启、资源超预算、诊断裁剪 |

通用字段：项目会话、打开代次、模型 ID、请求／任务 ID、来源／外观／相机修订、阶段、耗时、字节数、队列深度、结果、错误码、后端版本。跨进程使用各自单调时钟测本地耗时；端到端耗时由主进程测量，不直接相减未校准的进程时间戳。

### 7.3 用户可见状态与故障定位

- 任务状态与日志阶段一致：等待、读取中、生成封面、更新中、成功、缺文件、失败、已取消。
- “提交了渲染命令”“产生了图片文件”“界面已安装图片”“用户可交互”分别记录，不互相替代。
- 首帧渲染完成不冒充显示器呈现；验收用端到端观测和用户任务。
- 错误显示稳定的问题编号，诊断包能按编号定位；用户不需要看 F3D 内部堆栈。
- Native 日志回调不得直接调用 Qt 控件或同步刷磁盘；按等级进入有界队列。
- 普通模式不逐帧记录相机、像素、所有文件完整路径；重复警告合并，保留次数与首末时间。
- 日志按现有 off／normal／diagnostic 模式；额外诊断有时限，资源采样有频率上限。
- 记录日志丢弃、裁剪与写入故障；诊断本身不能引入新的长停顿。
- 诊断包不收集模型、贴图、备注正文或凭据；原始路径按现有脱敏机制处理。

## 8. 独立正确性与产品验收

### 8.1 样本

至少 24 个独立样本，四种格式每种至少 6 个。可以一例覆盖多个类别，但报告必须列出覆盖关系：

- 内嵌／外置贴图、OBJ+MTL、glTF+BIN、多目录同名贴图。
- 中文、空格、大小写差异、长路径。
- 多网格、多材质、实例、含点线内容、四边面或多边面。
- 透明／裁切、法线方向、粗糙度／金属度／AO 通道、发光。
- FBX 骨骼与动画文件、静态模型、不同导出来源。
- 缺图、缺 BIN、坏文件、加载超时、导入期间原件变化。

独立期望：原件文件集合与哈希、确定的依赖关系、由独立工具／人工确认的统计口径、材质通道检查样本。不能用 F3D 自己返回的数再作为其正确性的期望。

### 8.2 必须完成的用户任务

1. 导入 OBJ 文件夹，检查 MTL 与多张同名贴图，封面和大预览正确。
2. 导入 glTF+BIN+贴图，保存、退出、重开、搬迁项目，再打开和导出。
3. 导入原有多材质 FBX，先看到原效果，再整模型应用库中材质。
4. 使用原有贴图槽位修改外观，封面更新；保存中继续修改，重开保留新编辑。
5. 快速切换多个模型、连续修改贴图、切换项目，旧任务不回写。
6. 单个与批量导出，独立核对原件；原件导出不包含库内外观覆盖。
7. 删除、恢复模型，标签备注与依赖关系仍正确。
8. 后端崩溃／磁盘满／取消后仍可操作、保存项目，失败原因可定位。

### 8.3 发布阻断项

- 原件字节变化、文件遗漏被报完整成功。
- 模型与贴图错误配对，跨资产／跨项目串结果。
- 保存重开丢失编辑、部分加载导致未加载内容被删除。
- 封面标为最新但实际来自旧外观，或模型预览拿材质球冒充。
- 辅助进程异常导致 Prism 退出，或项目关闭后后台继续持有原件。
- 无法解释的统计数被标成精确原始面数。
- 老项目打开／保存导致已有材质、文档、脑图或画布数据变化。

以下是待最小实验校准的验收目标，不是当前已测成绩。统一参考 R0，即本次只读查询到的用户机器：

- CPU：Intel Core i9-13900K，24 核、32 逻辑处理器。
- 操作系统：Windows 11，系统版本 10.0.22621、Build 22621。
- 内存：约 128GiB，系统返回 137,242,947,584 字节。
- GPU：NVIDIA GeForce RTX 4080 SUPER，nvidia-smi 返回 16,376MiB 显存，驱动 595.79。
- 当前显示模式：2560×1440；系统同时有虚拟显示适配器，测试必须注明本地显示或远程会话。
- 磁盘：Samsung SSD 980 PRO with Heatsink 2TB（NVMe）和 TOSHIBA MG08ACA16TE 16TB（SATA HDD）。

主性能验收以模型库和缓存均位于上述 NVMe 的条件为准；HDD 素材读取另列，不混用一个阈值。路径到磁盘映射、剩余空间、DPI、电源模式和后台负载在第 1 步冻结，并记录测试时的实际系统版本与驱动。固定 Prism/F3D/VTK 版本。硬件配置已查询，不代表已运行任何模型性能测试。

### 9.1 负载矩阵

每档 100、1,000、10,000、100,000 个模型条目，另记录依赖文件总数与总字节。

至少分开两类数据：

- 索引规模集：小模型组成，可完成十万条独立记录的查询、滚动、保存测量；不能用它证明重型模型加载性能。
- 真实混合集：FBX 30%、OBJ 20%、GLB 30%、glTF 20%；至少 70% 为独立主文件内容，记录真实去重比例。包含 2K／4K 常规贴图与单独标注的 8K 重型组。

记录分类分布（均匀／单文件夹集中）、标签冷热分布、备注长度、变更历史、缺失比例、资源位置、SSD 空间、冷暖状态。无法准备完整十万真实混合集时明确标“未测”，不能用复制同一份模型替代。

模型复杂度另分：

- S：加载后不超过 10 万三角形，至多 4 张 2K 贴图，总文件不超过 40MiB。
- M：10 万～100 万三角形，至多 8 张 4K 贴图，总文件不超过 200MiB。
- H：超过 M；单独测量，不沿用 S/M 阈值，也不静默减面／缩图通过。

分别测试应用缓存冷／暖；OS 缓存状态单独说明。初次全库生成封面不计作打开库的前置条件。

### 9.2 R0 下的目标

## 10. 回退与维护

- 模型入口可在开发构建中停用，但已保存模型数据必须保留；不能以隐藏入口代替功能验收。
- 共用卡片提取先保持材质接口兼容，可单独回退 UI 改动。
- 模型存储采用新增领域结构，迁移事务失败回退；不删除旧表，不让不支持模型域的旧程序静默覆盖。
- F3D 固定版本、构建选项、reader、VTK、Python ABI 和最小补丁；更换 F3D 不改变原件。
- 不从 Downloads 加载运行时；正式依赖放入项目既有组件／打包体系，支持离线安装与资源定位。
- 后端启动失败时库仍可查看名称、标签、备注、已有封面和导出原件；交互预览明确显示失败与重试。
- 保留第三方许可证与补丁说明，遵循 F3D 自身贡献规则；本地集成不默认向上游提交。
- 维护性验收：UI 不依赖 F3D 私有对象；业务服务不持有 Qt 控件；辅助进程不写项目数据库；协议、缓存签名和未知字段有版本规则。
