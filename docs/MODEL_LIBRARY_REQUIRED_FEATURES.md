# 模型库必须完成的功能

用户确认：目录、全局标签与搜索、法线覆盖、SSS、置换、纯线框全部必做。
这是交付要求，不是可删除、可长期禁用的候选项。此前核心链路仅为阶段成果。
在功能真正实现和验证前保留安全门，但不能把这些门的存在当作功能完成。

## 逐项完成标准

| 功能 | 必须达到的行为 | 必须验证 |
|---|---|---|
| 模型目录 | 复用资源树；创建、重命名、移动、删除恢复；模型归属目录并过滤 | 全量／部分保存、重开、工程搬迁、目录删除与模型原件引用、切项目 |
| 全局标签 | 使用现有标签管理、层级、别名和计数；模型是明确的独立载体 | 标签重命名、删除、批量编辑、保存重开；资产／材质／模型／页面计数不混用 |
| 全局搜索 | 模型名称、备注、标签、文件及格式可检索；结果跳到正确目录、卡片与详情 | 非首分页、过滤状态、同名模型、切项目后的过期结果、保存后索引更新 |
| 法线覆盖 | 四种目标格式中，有有效 UV 的表面可应用法线；缺切线时派生计算，不要求作者重导出 | UV 接缝、硬边、镜像 UV、DirectX/OpenGL 方向、强度、多材质、原件不变 |
| SSS | 实际次表面散射；可控强度、颜色和厚度／模型尺度关系 | 皮肤／蜡等独立参考；背光与侧光；区分薄表面透光、玻璃、Alpha；保存重开 |
| 置换 | 贴图改变实际几何，轮廓随之变化；编辑不累积；原件不变 | 强度、正负方向、中点、UV 接缝、细分预算、恢复原形、相机与统计口径 |
| 纯线框 | 只显示几何线，不保留填充表面；与“材质加边线”分别存在 | 遮挡面、多个子网格、透明模型、切回材质、封面及独立预览一致 |

贴图没有 UV 等输入问题必须解释具体模型的限制与恢复办法；不能以整个格式禁用代替实现。
新增设置不是默认解法。统计必须说明原始拓扑、三角化和置换后派生几何的区别。

## 已核对的现状

- 当前原件存储、导入导出、服务及独立进程接线可以复用，不因渲染改造重做。
- ResourceTreeService 已有模型区门；尚不能只开门，必须补齐模型归属与目录生命周期。
- project_search.py 已有材质结果载体，可按同一结果／跳转契约扩展模型。
- render.js 已有 Babylon 模型加载分支，但该分支没有接上模型贴图修改、置换和视图模式，不能认定已经满足要求。
- render.js 中现有 SSS 仅设置 isTranslucencyEnabled，属于薄表面透光；不能冒充真正散射。
- 本地 Babylon 包包含 isScatteringEnabled、enableSubSurfaceForPrePass 和 wireframe 的实现。代码存在不是像素效果通过。
- 本机存在 Blender 4.5，可作为隔离的格式读取／派生几何候选。不能据此要求用户安装它，发行依赖与许可证还需落实。
- F3D 4.0.0 当前公开接口不足以单独完成所有目标，因此不把 F3D 作为不可改变的架构前提。

## 实施依赖

1. 先做格式读取与高级材质最小实验：真实四格式读取、UV／切线、纯线框、散射和轮廓置换。
2. 决定统一渲染执行路径，复用当前材质参数、槽位和封面／预览契约。必要时增加隔离的几何读取与渲染适配器。
3. 管理线按既有工程保存／资源树接入目录、标签、搜索；不等待渲染特性全部完成，但必须各自通过保存和失败恢复验证。
4. 渲染线按法线／纯线框、真实置换、真实散射推进。封面、大预览和保存重开使用同一外观语义。
5. 最终按“导入→归档→打标签→全局找回→修改材质→切视图→保存重开→原件导出”的完整任务验收。

原件继续保持字节与目录关系，不强制转换用户的模型，不增加“导出修改模型”。允许生成可重建的内部几何与像素缓存；不能用转换丢失材质或几何来掩盖读取缺陷。

总集成及架构决策仍由当前主对话负责，不增加新的总集成 AI。未完成项继续记作发布阻断，不能改写成永久“不做”。
