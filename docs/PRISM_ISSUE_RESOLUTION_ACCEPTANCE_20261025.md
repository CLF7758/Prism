# Prism 现有问题闭环与开发放行标准

日期：2026-10-25。补充约束：开发文档的“机制可行”不等于用户问题已经解决，更不等于可以保证任意工程、任意设备、任意故障下100%成功。

## 1. 本次收紧的决定

1. 优先解决用户实际遇到的问题，新存储格式只作为经验证的候选手段。能在旧后端修好的问题先修，不以迁移为前置。
2. 旧工程直接可用、原件字节保真、未加载数据不丢，是硬性验收。新格式未通过，不向用户开放转换，不删除原源。
3. 材质布局、相机、菜单、保存反馈分别有正式入口验收，不能由存储原型代替。
4. 只有固定候选在固定工作负载上通过，才对这组支持范围签署通过；未知或未测不写成功。
5. 如果分离式后端不能在正确性、体验或维护复杂度上取得足够收益，允许否决该后端，继续优化旧格式。不能为证明先前方案正确而强制迁移。

## 2. 用户问题逐项绑定

|---|---|---|---|
| 保存无感知/取消文案错误 | 捕获/写入/提交/确认状态及UI反馈 | D06 B＋D14 A | 从真实保存入口看到即时反馈；成功、取消、失败、已写未确认各自准确；重开校验；捕获后编辑仍dirty |

以上均先复核当前候选。已经修好的功能只补缺失的独立验收，不重复改写；只在历史版本上存在的缺陷保持历史归档。

## 3. 正确性硬门槛

- 支持格式的原件/附件：迁移、保存重开、原件导出的长度和完整SHA256全部一致；截图相似不算通过。
- 实体、关系、正文、全局元数据、未知字段：独立校验器逐项对照，无静默丢失。不能支持的扩展在预检明确拒绝。
- 保存期间新编辑不丢，旧工程/旧epoch/旧查询回调不能覆盖新状态。
- 源/已有目标在失败、取消、冲突时不被破坏。已真实提交后，反馈必须说明实际磁盘状态。
- 新目录不依赖旧源路径；完整迁移验证通过前不发布成功，任何阶段不自动删除源。
- 新程序直接打开旧`.prism`，目标旧版通过兼容导出重开；不能声称旧程序自动理解新格式。

硬门槛失败一项即不放行，不能用性能提升或体积缩小抵消。

## 4. 性能验收必须签收的工作负载

先冻结参考机器、磁盘、Qt/Python、DPI、候选哈希、原件分布和缓存状态。以下是**开发目标，不是已达到的成绩或设备无关保证**：

1. 保存/切换/查询动作的可见受理反馈：参考负载下P95不超过100ms、最大不超过250ms；后台总耗时另计。
2. 有效热聚合切换：确认返回条件未变时，不全库重新评估或重建代理；界面响应达到同一交互反馈预算，安装/几何/GC分别计量。
3. 计数：局部反馈立即发布；依赖目录时显示pending并保留上次确认值，目录结果就绪后主动更新，不等待用户再次操作。正常就绪索引上的常用编辑计数，以250ms作为初始确认目标。
4. GUI线程不得同步等待后台Event/join、原件读取或全库扫描；发现超过100ms的普通事件需要逐条解释并修补，不能仅把任务放到“切片”函数就当达标。
5. 近景清晰恢复按固定格式/尺寸/视口清单验收焦点和全视口完成时间；损坏原件单独报错，不能堵住其他图。不得以永久低LOD换取快速完成。
6. 冷打开/冷查询、完整迁移/导出按数据量与磁盘计量；不强行承诺55GB处理在固定短时限内完成，但首屏和输入不能被其同步阻挡。

以上目标在D01正式确认后锁定。确需调整须记录原目标、原因和产品决定，不允许测后扩大timeout或减少工作量把失败改为通过。

## 5. 达到“确定解决”的证据顺序

```text
当前候选复现用户问题
→ 绑定具体入口和可测错误
→ 最小修复
→ 相同工作负载before/after
→ 原件/数据完整性检查
→ 固定候选真实原生操作验收
→ 用户同一工程复测
→ 只对已覆盖的问题与支持范围销号
```

原型、单元测试、独立原生验收、用户复测四层分别登记，不互相替代。故障注入只在专用副本；真实工程复测由用户操作或使用明确授权的专用副本。

## 6. 如果某条路线没有解决问题

- 查询快了但GUI仍卡：继续D12处理对象/安装，不继续拆数据库来回避。
- 分离式后端读源不比旧后端好：保留旧格式并分析具体I/O/连接/解码成本，不强推迁移。
- 图片额外压缩无收益：STORE，保原字节；不用转码达成虚假的体积目标。
- 默认对象库只读副作用/媒体租约无法正确适配：该后端不放行；只在独立评审后选择替代实现，不边开发边隐式切换格式。
- 原生退出问题未定位：不能把“本轮未复现”当修复完成，必须保留未验收状态及下一取证入口。

## 7. 最终交付判定

可以承诺的是：按固定支持范围执行完整验证，失败不伪装成功，未过闸门不开放迁移，用户原件始终受保护。

目前不能诚实承诺的是：仅凭方案或这些合成原型，100%保证解决所有真实工程、所有设备上的全部问题。这个结论必须由上面的逐项实测形成，不能提前写进方案。

下一步继续D01/D02，并将本表作为16步计划的必需验收附件；新存储开发不能替代现有问题的定点修复。
