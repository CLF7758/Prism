## 1. 接手后必须先理解的目标

用户的问题是：十万图工程打开慢；画布、文档、脑图、材质之间切换卡；全部图片等聚合页面卡；快速缩小再放大后图片长期模糊；连续使用资源消耗过大。

最终应呈现：

1. 打开大工程，先看到并能操作上次页面，而不是等全部图片、全部页面准备结束。
2. 切换模块只准备目标需要的数据，上一模块的编辑正确提交，不整窗闪烁，不被旧回调覆盖。
3. 全部图片、未标签、未分类、默认画布都能容纳大量资产，自动合理排列。
4. 远景看真实图片合成，中景逐层细化，近景根据实际屏幕像素变清晰。用户滚轮放大哪里，哪里优先清晰，随后整个可见视口清晰。
5. 不靠隐藏图片、白块、长期马赛克、降低画质或删功能来换速度。
6. 内存、后台队列、纹理、临时文件有上限、有归属、能释放，不能打开多少页面就永久累积多少资源。
7. 原文件、绑定、通道、标签、备注及未加载数据不能因部分加载而丢失。

**现在没有证明十万图正式入口已经流畅。不要接手后写“基本完成”，也不要拿保存测试数量替代打开与切换的结果。**

## 5. 必须采用的架构：在现有框架上收口，不换引擎

现有栈继续使用：Python + PyQt6 + SQLite，Babylon/GLB现成渲染，PyAV现成视频处理。禁止自己写材质渲染内核、模型加载引擎、图片编码器或Qt替代品。

### 5.1 五层分工

```text
界面层：画布/聚合列表/材质库/文档/脑图/搜索
   │ 发查询与编辑命令；只接收当前有效结果
应用协调层：打开控制器/导航/取消/优先级/资源预算
   │
项目会话层：已加载范围、dirty覆盖、撤销重做、保存快照/回执
   │
目录与记录访问层：摘要、计数、ID分页、空间查询、按ID详情
   │
源文件层：SQLite中的原件/附件、流式读写、原始字节导出
```

这是职责图，不要求创建五个巨型新类。优先扩展当前模块。每个数据事实只能有一个权威来源；缓存必须能失效或重建。

| `search_candidates.py` / `project_search.py` / `search_controller.py` | 候选索引、精确过滤、dirty覆盖、分页跳转 | 只搜当前scene，返回空却标称全库无结果 |

### 5.3 所有异步操作必须遵守的契约

请求至少携带：project_id、open_epoch、operation_id、scope、generation。涉及内容还要携带source_revision/resource_id。ID和修订值来自项目与服务，不用对象内存地址充当持久ID。

操作顺序：请求 → 查询/解码/布局纯数据计算 → 生成不可变结果 → GUI安装前核对项目/epoch/generation → 安装有限工作量 → 真实绘制 → 完成。

- 旧项目或旧generation结果直接丢弃并释放资源，不能“顺便应用”。
- SQLite连接由所属线程创建使用关闭，不跨线程共享一个连接。
- 后台使用QImage等允许的独立数据；QPixmap、QWidget、场景安装按Qt线程要求处理。
- 取消贯穿查询、批次、解码、结果安装；不能只取消最后回调，后台仍无限工作。
- 后台结果队列必须有上限和背压。可见任务优先于预取，不允许预取占满所有槽位。
- 同一资源同版本同规格并发请求合并，不重复读、解码和安装。

### 5.4 目录摘要与详情必须分开

摘要建议包含：稳定ID、类型、真实canvas/page归属、标题、可筛选标签/评分/删除状态、尺寸/裁剪/位置、源与预览引用、必要排序键。保留已有格式，不强迫一次性写入所有新列。

详情才包含：完整JSON、编辑器正文、复杂属性、材质完整绑定等。原件BLOB按需单独读取。

不得在摘要中塞大段base64预览。共享字符串只能作局部节省，不能代替按需数据访问。

目录查询返回有界行、cursor、complete/unknown状态、source_revision；不能只返回list，让调用者猜是否读完。

`None`表示未知或不可用，`0`表示可信地没有记录。必须保留这一区别。

### 5.5 dirty覆盖规则

基础目录来自磁盘快照。用户修改形成overlay：新增、修改、移动、删除/恢复。所有计数、筛选、搜索、归属和导出都看“基础目录+overlay”。

- 修改后立即反映，不能等保存后搜索才更新。
- overlay只确认已保存快照内的版本，保存期间的新编辑继续dirty。
- 保存成功后原子推进目录版本；失败不得推进，也不得显示已保存。
- 未加载内容保持不变；不在当前对象列表不代表删除。
- 第一阶段可以复用当前安全会话，后续再收口高效dirty journal；不要为追求最小diff先重写全部底座。

## 7. 执行路线：共9步骤，先性能后可选项

### 实际优先顺序

```text
最小步骤0记录（不重做诊断）
  ├─ 步骤1：直接去重/版本复用
  ├─ 步骤3：正式当前页按需打开 ← 步骤2只补启用安全门
  ├─ 步骤4：异步切换协调
  ├─ 步骤5：聚合布局/LOD/清晰恢复

        ↓
正式入口全流程验收、文档与遗留项结算
```

不能为了“按顺序”先花多轮扩展步骤2，把打开、切换、显示都搁置。也不能为追求快而启用会丢数据的部分加载。

### 步骤0：只补必要的性能记录和完成状态

目标：已有报告够开工，不重新全量摸排。为新流程留必要证据，区分可操作与后台完成。

做法：

- [ ] 在现有performance_trace和ProjectLoadService扩展操作关联ID，不另造日志系统。
- [ ] 记录request/start、当前页记录加载、可操作、可见画面就绪、后台目录完成、cancel/error/end。
- [ ] 耗时用单调时钟；标清线程、是否包含子调用，异步阶段不直接相加当墙钟。
- [ ] 同步关键路径只写小事件，不每张图落盘、不每帧抓堆栈。
- [ ] 计数记录实际读取详情条数、源字节、安装条数、重复arrange次数、队列峰值、过期结果丢弃量。
- [ ] 资源记录只看本进程树；临时目录从source_store租约或专用目录递归统计。
- [ ] 采集开关可关闭；关闭重日志后功能相同。旧dispatch采集不准不能记成无停顿。

输出：一份阶段字段说明与日志示例。已有日志有字段就复用，禁止先新建庞大监控面板。

完成条件：一次打开/切换可以按operation关联到实际工作量与完成状态；无索引时不伪造完成。此步可随步骤3一起落地。

### 步骤1：去掉重复查询、刷新、计数、布局入口

涉及：project_catalog.py、资源树/分类面板、__main__.py、asset_browser.py、material_library.py及已有revision服务。

- [ ] 列出一次点击触发的refresh路径，合并同revision请求，取消已经被显式refresh满足的timer。
- [ ] 使用已有ID/后代索引、材质摘要与revision，不对每个按钮重新深拷贝全部记录。
- [ ] 计数、树节点数量优先目录可信统计；未知显示准备中，不扫描全详情填0。
- [ ] 同过滤条件/排序/数据版本重复进入，复用结果；过滤条件必须包含标签、评分、查询、范围、删除状态等所有实际影响项。
- [ ] 查询缓存键包含project/epoch/revision，切工程不能命中旧结果；限制结果缓存容量。

目标：避免加载一页、保存时删掉其他页。该步是安全依赖，不是继续扩张新功能的主战场。

已有实现先复用。逐条核对：

- [ ] 当前加载ID和基线登记真实，不靠scene当前对象推断整库。
- [ ] 材质、资源树、附件、board、页面正文及工程元数据范围明确。include_domains默认/正式启用范围必须检查，不能非空工程就无法保存。
- [ ] 未加载字段不写；显式清除用已实现替换/删除语义，不把省略当空。
- [ ] 移动画布走显式授权命令；默认画布ID、真实画布、聚合虚拟范围不混用。
- [ ] 保存期间再编辑，ack只确认快照内版本；ack失败保持dirty，不显示保存成功。
- [ ] 另存后源引用、目录版本、停放记录与下一次保存指向新文件。
- [ ] 原地只写差异；附件与原件关联同事务或有明确恢复协议。
- [ ] 尚未支持的硬删除等操作，在执行前明确禁用/拒绝，不让用户操作后到保存才发现不支持。

完成条件：允许启用的普通编辑、标签备注、材质绑定和页面切换能保存重开；未加载行和源字节一致。不能把“全部拒绝保存所以不丢数据”标为可用。

如果仍有安全缺口：补最小对应路径，记录限制；继续独立推进布局、缓存、媒体延迟工作，不被不相关硬删除功能拖住。

| 规模 | 数据/布局策略 | 远景 | 中景 | 近景 |
| --- | --- | --- | --- | --- |
| 100 | 小摘要可整体准备，避免不必要后台层级 | 足够远时真实合成 | 可直接绘制清晰小预览 | 按屏幕像素取细节 |

## 8. 代码质量和扩展标准

### 8.1 必须遵守

1. 最小职责修改，沿用现有命名与模块。大函数拆成有明确输入输出的小函数，不把业务全部堆入view.py或__main__.py。
2. 持久ID、页面ID、资源树ID、虚拟范围ID分清；归属变化集中走命令，禁止各模块直接改属性造成索引不同步。
3. 不可变结果与明确错误类型；取消、未知、空结果、失败区分，不用空list/0吞异常。
4. 缓存键写全，缓存必须有容量和失效规则。不要用全局变量留住整个窗口/项目。
5. 不在paint/showEvent/滑块每个事件中做数据库全扫、磁盘读取或全量深拷贝。
6. 不用processEvents忙等和任意sleep解决同步；复用Qt信号、timer和已有异步提交协议。
7. SQL参数化；IN列表有界；游标及时关；连接线程归属明确。
8. 不拼接新的原件压缩/转码流程。预览错误不能修改原件来“修复”。
9. 可选依赖缺失有明确fallback；项目仍可打开，不因未装pyvips阻止主线。
10. 同项目多入口复用一套查询/打开/源读取/导航，避免每加模块再写一套fetchall。
11. 不把硬编码中文状态当协议；结构化状态供UI翻译，日志保留可追踪ID。
12. 不通过删断言、扩大超时、降低分辨率、删功能或去掉源校验让结果“通过”。

## 9. 合格标准：正确性硬门槛 + 性能目标 + 证据

### 9.1 正确性硬门槛，任一失败不能交付为完成

- 正式入口使用新路径，不是测试专用入口成功。
- 未加载内容、未知字段、原件、附件不丢；修改保存重开一致。
- 数量、归属、标签、搜索、全选、多选导出覆盖正确。
- 当前画面不长期白块/缺图/糊图；近景恢复后符合相同渲染条件下的参考图。
- 材质不透明、透明裁切、半透明、金属/粗糙/法线/AO/自发光/SSS、自定义通道保持已有支持；不要求浏览器与用户UE母材质逐像素等价。
- 滑块离开材质丢弃临时调整，源图/绑定/通道/标签/备注保留。
- 源冲突、取消、写入/回执失败不会显示保存成功；退出不会把旧任务写回新项目。

### 9.2 性能验收建议值：开发目标，不是当前实测成绩

下列数值用于接手者约束设计；必须注明硬件、DPI、GPU/远程、磁盘、目录状态、缓存冷热、数据集。若发现不合理，提交有数据的调整理由，不能悄悄放宽。

| 场景/指标 | 合格目标与解释 |
| --- | --- |
| 同范围重复进入 | 无内容/几何变化时全量rebuild/arrange次数为0；query不重新读全库详情 |
| 界面同步工作 | 常规单次尽量≤16ms；切换启动同步部分≤100ms，不能反复出现>100ms工作；单项超预算必须解释和拆分 |
| 有效目录+当前100图打开 | 目标1—3秒内当前页可操作；不依赖总共十万条详细记录准备完成。首帧清晰另报 |
| 已准备模块重复切换 | 目标0.3—0.5秒进入目标可操作状态，常规同步阶段≤100ms；编辑异步提交时间单列但不从用户等待中扣掉 |
| 无目录首次打开 | 不承诺固定秒数；必须可响应、可取消、可恢复、进度真实；证明当前页完整才报可操作，后台构建工作量另报 |
| 快速缩放/平移 | UI不能长时间冻结；建议交互帧耗时p95≤33ms；>100ms尖峰逐个定位，不能以平均值掩盖 |
| 缩放停止后焦点清晰 | 已有匹配预览/热缓存目标≤0.5秒；需源读取解码目标≤2秒。异常格式/大图单列，不允许普遍10秒糊图 |
| 缩放停止后全视口清晰 | 热态目标≤2秒、需要源读取目标≤5秒；以屏幕像素所需清晰度为准，不要求远处小图解码全部原像素 |
| 队列/内存 | 每类有声明上限；固定工作集稳定后不随轮数无界增长；新增工作集按预算淘汰，不靠超时强杀 |
| 原地增量保存 | 改少量记录不重读/重写全部原件，实际变更行可证明；不承诺所有介质固定毫秒 |
| 55GB另存 | 明确复制阶段与进度，可取消、可恢复安全；不以原地保存耗时冒充整库另存 |
| 搜索 | 已就绪索引常规查询目标≤300ms首批结果，输入可取消；长正文/首次建索引单列，不能漏未加载结果 |

所有秒数只是目标。若尚未实测，写“未验收”，不得写“已达到”。性能改善必须同时满足画质与数据正确性，不能单看时间。

### 9.3 如何确认清晰，避免测试造假

1. 记录动作完成时刻，随后仅观察实际界面绘制与缓存状态。
2. 测试不调用request高清、不主动加载目标详情替UI补漏。
3. 同视口、DPI、裁剪、旋转、透明条件下，与充分加载的参考画面对照。
4. 分别记焦点区域与全视口，不能只证明鼠标下面一张清楚。
5. 停止后仍存在不匹配像素需求的低清块，要算未恢复；远景屏幕只占几像素不要求原图尺寸。
6. 低清覆盖可作短暂过渡，不得永久依赖，也不能用截图压缩掩盖模糊。

### 9.4 验证工作控制范围

用户已提供大量定位报告，不要先重复全测才开发。每个代码任务完成后只做相关最低必要回归；正式入口接通后做端到端验收。不要每改几行重跑359项或重复十万图旧入口。

## 附录A：最容易写错的流程，按此顺序实现

以下是概念伪代码，不是当前API的精确签名。先核对现有方法，适配现有服务，不要把伪代码中的名字直接复制成新的平行系统。每个步骤都要能取消和报错。

### A.1 正式打开，不能用fetchall补空缺

```python
def request_open(path):
    # GUI线程：先完成当前编辑提交，必要时按现有策略处理dirty。
    token = begin_new_project_epoch(path)
    cancel_previous_project_jobs()
    show_loading_state(token)
    submit_worker(read_structure_and_catalog_state, path, token)

def structure_ready(result, token):
    # GUI线程：回包先核对token，过期结果只能释放。
    if not is_current(token):
        release_result(result)
        return
    install_small_structure(result.structure)
    target = resolve_valid_last_page(result.structure)
    if result.catalog_is_complete_and_current:
        request_scope_page(target, cursor=None, token=token)
    else:
        start_or_resume_bounded_catalog_build(token)
        # 能证明该页完整才走独立加载；否则显示发现进度。
        request_provable_target_scope_or_wait_for_discovery(target, token)

def request_scope_page(scope, cursor, token):
    # 工作线程：目录给有界ID，按ID取得详情，保持源版本一致。
    ids_page = catalog_page(scope, cursor, token)
    details = read_details_by_ids(ids_page.ids, token)
    return_batch_to_gui(details, ids_page, token)

def batch_ready(batch, page, token):
    if not is_current(token):
        release_result(batch)
        return
    # 与当前dirty canonical合并，而不是盲目替换。
    records = session_register_or_reuse(batch)
    install_with_existing_scene_budget(records, token)
    if page.has_more:
        schedule_next_needed_page(page.cursor, token)
    update_scope_completeness(page)
    mark_interactive_only_when_actual_target_is_usable()
```

注意：

- `has_more`不表示马上循环取完整个工程，只续取当前目标需要的范围。
- 单页非常大时，当前页完整性与视口准备状态分开。能操作已明确加载的区域，不得将尚未加载内容当删除。
- 当前页ID发现如果依赖旧格式全库JSON扫描，要承认首次建目录成本，不能在GUI线程做它，也不能空页假完成。
- 原则上先不改工程文件格式；旁路目录是可删除重建的缓存，源文件仍为权威。

### A.2 切换页面：先提交编辑，再打开最新目标

```text
用户点击B
  → 记录最新导航意图B
  → 若A有异步编辑快照，启动/等待其现有提交回调
用户又点击C
  → 最新意图替换为C；不重复提交A，不先实例化B
A提交完成
  → 确认A内容版本与快照一致
  → 加载C需要的数据与界面
任何B旧请求返回
  → token/generation不匹配，释放，不应用
```

保存请求不能覆盖导航意图，也不能绕过编辑提交屏障。用明确请求类型协调：导航可最新优先，保存必须确认对应快照，关闭必须等安全结果。不要把所有请求简单覆盖成一个lambda。

### A.3 焦点清晰恢复

```text
滚轮/平移改变视口
  → 更新view_generation和焦点
  → 立即绘制当前合法真实覆盖，禁止清空成白块
  → 空间查询得可见分组/图片
  → 按投影像素计算各项所需LOD
  → 相同源版本/规格请求合并
  → 焦点优先，其次其余视口，最后有限预取
后台结果返回
  → 校验源版本；旧generation不做无用GUI安装
  → 有用结果进入有预算缓存
  → 只标脏相关tile/composite区域
  → 分帧安装/合成并记录真实绘制达到目标的时刻
```

不要每个滚轮事件都销毁整个缓存。generation控制任务是否仍有用，source_revision控制内容是否正确，两者不能混为一谈。旧视口结果可能仍有缓存价值，但不能挤掉新视口任务。

### A.4 全选、多选、导出

```text
普通多选：selected_ids + 当前查询revision
全选当前查询：query_snapshot + 排除的ids（必要时）
导出：冻结选择语义 → 目录解析ID批次 → 逐批读取原件 → 写目标 → 校验/记录结果
```

不要求把十万详情全部加载才全选。导出开始后用户改筛选条件，不能使导出集合中途变化。目标同名须有稳定的避冲突规则，不能覆盖成最后一张。失败清单保留原ID和源标识，用户能知道哪项没导出。

## 附录B：缓存失效表，禁止一律清空或一律不清

| 事件 | 应失效/更新 | 应保留 |
| --- | --- | --- |
| 源图解码出更清晰级别 | 相关图片显示版本、覆盖它的tile/composite | 卡片位置、资产归属、无关图片缓存、空间索引 |
| 改标题/备注 | 卡片文本、相关搜索文本及适用排序 | 源图片、无关布局；标题排序启用时才重排受影响范围 |
| 改标签/评分 | 查询结果/计数/搜索，适用排序 | 原图及未变范围图像缓存 |
| crop/旋转/尺寸改变 | 相关几何、位置包围盒、空间索引、图像tile | 未受影响分组；不能复用错误几何 |
| 移动画布 | 源/目标范围成员、计数、搜索归属、受影响布局组 | 原件内容缓存；源版本没变不重解码 |
| 新增/软删/恢复 | 范围成员/统计/局部布局/索引 | 其他资产详情、其他组布局 |
| 全局排序或布局模式改变 | 当前范围位置与索引；视觉搜索保排名 | 源解码结果；不会因此改原件 |
| 改卡片大小 | 合并后更新当前几何/布局与所需LOD | 可复用的合适源解码级别 |
| 清除注释/切走页面 | 注释图元/笔迹状态，按产品规则处理 | 合法图片缓存，在预算内保留 |
| 工程切换/源文件被替换 | epoch相关全部请求、源版本相关缓存/目录 | 只有能证明资源标识和版本相同的共享对象可保留 |
| 原地保存成功 | 目录/索引版本及基线原子推进 | 未变化源像素缓存；保存不是图像变化 |
| 另存成功 | 源位置引用/目录归属，旧租约释放时机 | 逻辑ID与未变化内容的正确缓存，不能继续读错误旧工程 |

每个缓存实现须在代码附近说明：key、占用估计、拥有者、淘汰规则、上述事件的处理。仅调用reset不算失效设计。

## 附录C：故障与降级处理表

| 故障/状态 | 用户看到什么 | 程序怎么处理 | 不允许 |
| --- | --- | --- | --- |
| 目录不存在 | 正在准备目录/发现页面，进度可取消 | 后台有界建库，记录checkpoint | 默认全部数量0并说已打开 |
| 目录与源不匹配 | 重新准备，已失效范围不当可信数据 | 取消旧查询，重建或受控增量同步 | 混读旧ID与新源详情 |
| 某原图缺失/损坏 | 对应项清晰错误状态，其他项可用 | 保留记录与源信息，允许恢复/重试 | 删除记录或用白图覆盖原件 |
| 可选解码后端缺失 | 正常继续或明确格式限制 | fallback Qt，记录一次诊断 | 应用启动失败或无限重试 |
| 异步编辑提交失败 | 保留原页内容与dirty，显示可重试原因 | 不跳过保存屏障，保留最新意图供重试 | 静默离开丢修改 |
| 旧结果返回 | 不应造成界面变化 | 丢弃并释放临时资源 | 写回新项目或新选择 |
| 内存预算不足 | 先保当前视口，渐进准备其他内容 | 停低优先任务、淘汰可重建非可见资源 | 丢dirty或无限开队列 |
| 保存冲突/失败 | 未保存状态与具体原因 | 回滚/拒绝发布，保持dirty | 显示保存成功 |
| 导出中取消 | 已完成项与取消状态明确 | 停后续批次，临时输出按规则清理 | 把取消当全部导出成功 |
| 关闭时仍有任务 | 按已有策略等待安全点或取消 | token失效、释放租约、有限退出 | 关闭后回调访问已销毁Qt对象 |
