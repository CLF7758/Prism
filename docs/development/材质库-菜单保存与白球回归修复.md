# 菜单、保存和白球问题修复（2026-10-19）

## 确认的问题

- 运行日志中的自动保存只有开始，没有结束，同时附件与画布原图读取反复出现 `sqlite3.OperationalError: database is locked`。大事务写入期间，懒加载附件另开连接读取同一个数据库，写入缓存溢出后读连接等待当前写连接。原代码还会把临时读取失败的空结果缓存起来。
- 未加载的材质缩略图共用默认白球的图片哈希。浏览器收到前一批白球后，误以为其余记录的真实缩略图也已加载，因此不再请求。双击产生单张预览更新后才恢复。
- 文件操作的 QAction 只挂在画布上。画布隐藏后，Ctrl+S 等文件快捷键不能可靠使用。

## 改动

- 在原项目保存时保留未改动附件，只写新增或修改的附件；另存为时逐个读取原文件，缺失原图则停止保存。重建前的备份同时接管旧附件来源。临时读取失败不写入缓存。
- 保存或读取任务仍在运行时，不再启动另一个保存任务。
- 每张待加载卡片使用独立请求标记；收到请求确认后由后台任务补上真实缩略图。确认消息不再重复传输默认白球 PNG。
- 主窗口复用已有文件操作 QAction，使隐藏画布时仍可保存、打开和另存为。
- 左上菜单改用持有引用的非阻塞 popup，避免嵌套 exec；右键导出用真实鼠标事件检查。

## 验证

`tests/test_material_menu_save_regression.py` 联合附件、拖出和菜单回归：39 项通过。

- 300 个已保存的真实材质逐个滚动显示，不选择、不双击；300 张卡片均加载实际 PNG，选择不改变。
- 左上菜单重复打开、真实鼠标右键导出菜单、画布隐藏时 Ctrl+S 均通过。
- 同文件保存保留已有原图，不调用另一个附件读取连接；新增附件可保存；另存为保留原字节；读取失败可恢复。
- 用户项目的副本：2,645,848,064 字节、332 个材质，材质与附件保存 870.9 ms，未额外加载原图到附件缓存；900 张测试原图 SHA256 校验通过。此时间仅指材质和附件等项目附加数据，不代表完整画布保存时间。

远程操控端的菜单交互尚未现场复测。正在运行的旧程序不会自动加载修改过的 Python 和 JavaScript，需要关闭后从 BAT 重新启动。
