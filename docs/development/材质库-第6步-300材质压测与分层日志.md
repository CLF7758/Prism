# 材质库：300 个真实材质压测、日志和补漏

日期：2026-10-19。本记录覆盖此前“调整参数会保存”的说明；用户已明确选择离开材质就丢弃预览调整。

## 实际测试资源

从 [Poly Haven](https://polyhaven.com/license) 下载 300 个不同的 CC0 材质，每个包含颜色、法线、粗糙度三张 1K 原图，共 900 张。不是重复复制一个材质凑数量。来源、原始地址和上游 MD5 保存在 `artifacts/material-tests/polyhaven-300/manifest.json`。下载工具使用独立 User-Agent、四个工作线程、断点复用和文件校验。Powered by Poly Haven。

原生 Windows、正常启动的 WebEngine 配置、Babylon 官方引擎逐个渲染了全部 300 个球。日志识别到 RTX 4080 SUPER / ANGLE D3D11 / WebGL 2；没有关闭 GPU 或用软件渲染冒充。

本地验收项目：`artifacts/material-tests/stress-300/PolyHaven-300.prism`，约 612 MiB，包含源文件和真正的球形缩略图。资源、项目、导出样本、截图均在忽略目录，不打包进应用。

## 卡顿原因和修复

| 实际发现 | 修改 |
|---|---|
| 每次选中重新解码全部缩略图，把 256px 放大成 480px 再压缩；旧流程每次选中约 10 秒，卡住的栈在 QImage.save | 选择只更新右栏和选中状态；已有 PNG 直接使用，缓存缩略图 |
| 没有修改参数也会写入默认值，触发 configure 和全目录刷新 | 比较实际含义一致的默认值，没变化就不写入 |
| 更新一个球仍发送整个库；完整消息约 18.6 MB | 单球增量更新；列表只发送约 148 KB 元数据，图片按可见范围请求，每批最多 16 张 |
| 打开保存项目时，主线程逐个读全部缩略图；栈在附件 SQLite 查询 | 复用现有懒加载附件存储，后台按可见卡片读取 |
| 右栏提交后台任务之前就读取了原图 | 读取原图、提取通道、小图制作全部移进工作线程 |
| 已保存项目中，看过的原图长期留在附件缓存 | 后台预览和导出通过现有存储流式读取干净原图；未保存的新文件仍完整保留 |
| 快速选中时旧任务继续排队 | 开工前跳过过时任务，提交结果仍检查项目、材质和签名 |
| 第一轮实际暴露滚动停在 48 张 | 去掉会被 Chromium 暂停的双层动画帧门，复用 SurfaceStudio 的 drawCards(true) 追加卡片 |
| 静止画面持续渲染 | Babylon 空闲停帧，鼠标、滚轮、相机复位、贴图变化时唤醒，隐藏停止 |
| 缓存和临时目录无退出上限 | 编码缩略图最多 512 条/32 MiB，槽位小图最多 512 条/8 MiB，准备好的预览输入最多 16 组；清理不再使用的临时目录，保留打开预览正在使用的文件 |

## 实测结果及限制

完整测试报告：`artifacts/material-tests/stress-300/report.json`。

- 300 个球全部实际出图；准备、渲染、抓取每个缩略球中位数约 516 ms。
- 旧选择流程对照样本中位数约 10,371 ms。
- 同轮 100 次改造后的选择，界面处理中位数约 5.7 ms；101 次滑块事件中位数约 1.2 ms。
- 900 个原文件全部导出，SHA-256 与上传内容相同，没有缩图、转码或改通道。

保存后重新打开的最终测试：`artifacts/material-tests/stress-300/final-ui/report.json`。

- 包含完整主题和懒加载数据库，打开到首批真实缩略图约 0.80 秒。
- 100 次选择中位数约 10.6 ms，没重建目录。
- 全局搜索返回 300 条材质结果，跳到第 300 个后自动滚动让它可见。
- 最终界面测试没有触发 500 ms 主线程停顿告警。
- Python 主进程驻留内存峰值约 470 MiB，不包含独立 Chromium/GPU 进程。

这些是这台机器、这批 1K 素材的实测，不能外推成 300 份 8K 资产的结果。滑块事件耗时不等于 GPU 最后一帧显示完成耗时，也不是固定帧率承诺。旧流程对照故意制造的卡顿单独分阶段记录；生成验收项目时直接写 SQLite 的测试步骤也不能算成正常异步保存的界面耗时。

## 日志使用

材质库工具栏新增“性能日志”，打开现有应用日志目录。正常启动默认记录，不用先开调试。

复用 `prism/performance_trace.py` 的异步 JSONL、主线程心跳、卡顿栈、Qt 事件耗时、滚动文件和崩溃记录，没有再建一套日志系统。

- operation：选择、刷新、缩略图、贴图检查、渲染输入等耗时。
- material_task_queued/start/work/finished/cancelled：同一 task ID 串起排队、执行、过时取消，标明任务类别和材质。
- material_render_request/done/capture_done：同一 token 串起渲染和截图。
- material_browser：每秒汇总脚本长任务、帧提交、加载贴图、等待场景就绪、置换、截图和脚本错误；记录引擎识别到的 GPU。
- material_performance/material_cache/process：队列、缓存、临时目录、附件驻留量、Python 内存和 CPU。
- gui_stall/gui_recovered/slow_dispatch：主线程阻塞的位置、耗时和恢复。
- material_render_timeout/material_browser_process_exit：35 秒未完成的预览和浏览器进程退出。

日志单文件约 4 MiB，带滚动备份及数量限制，不写入贴图像素/base64 图片。诊断失败不阻止编辑。GPU 驱动内部执行栈不能单凭 Python 日志取得；日志用于区分界面、磁盘、排队、浏览器和渲染阶段。

整理命令：

```powershell
.venv\Scripts\python tools/summarize_material_performance.py <日志路径> --output <报告路径>
```

## 追加交互已落实

1. 离开材质、创建下一个、切换文件夹、筛选到该材质不可见、保存或离开材质库时，丢弃强度、颜色、反转、置换中点等预览调整，恢复默认。原图、槽位、通道、法线格式、标签和备注保留。有默认缩略图缓存就恢复缓存；没有则不继续展示已丢弃的调整效果，下一次打开会重新渲染。
2. 整个球形图片区域和渲染背景纯黑；内置默认球也用同一个 Babylon 引擎重新生成。旧项目保存的灰色背景缩略图在该材质重新渲染后更新，不改写源贴图。
3. 名称、备注、标签、原图文件名、提供的 UE 版本进入现有全局搜索，新增“材质球”类型。结果双击/打开后进入对应文件夹、选中、滚动定位；不把材质伪装成画布图片。
4. 材质标签加入已有标签树、计数、搜索、重命名、删除和撤销。含材质的标签也能查到材质，复用现有 TagEdit 命令。

### 新增：左键拖出源贴图到 UE

用户已明确本轮只导入贴图，不创建 UE 材质实例。

- 在卡片上按住左键移动，单选带出该材质当前槽位绑定的原图；Ctrl 多选后拖动任意已选卡片，带出整组选中的源图。
- 同一张 ORM/ORT 被多个槽位使用，只发送一份原文件，不导出拆分通道或缩略球图片。换槽后留下的未使用历史文件仍收存在 Prism，但不夹带进这次拖动。
- 普通文件保留名称。同名或 UE 规范化后会撞名、但内容不同的文件，临时交接文件名添加哈希防冲突；文件字节不变，Prism 中的原名不变，右键导出原文件的规则不变。
- 复用原图导出器做 SHA-256 校验和复制，后台准备；复用画布的 Qt 原生文件拖动并抽成共同入口。发送的是本地文件 URL，UE 使用[现有文件拖入导入流程](https://dev.epicgames.com/documentation/unreal-engine/importing-assets-directly-into-unreal-engine?lang=en-US)。没有新写 UE 导入器。
- 源文件放在 Prism 设置目录下的 `material-transfers/<SHA-256>/文件名`，保持稳定，不在拖完或退出时删除，供 UE 的重新导入引用。因为要保留重导入路径，该目录不随临时预览缓存自动清理。
- 大批量首次准备需要时间。保持左键按住；若提前松开，只准备文件，不在鼠标已松开后突然启动拖动；再次拖动会复用已经准备好的文件。
- 该步骤只向 UE 提供图片原文件；UE 的贴图压缩、sRGB、重新命名和导入提示由 UE 现有导入器处理，不把自定义通道配置冒充成已经传给 UE。

`tests/test_material_texture_drag.py` 检查单选、多选、真实 WebEngine 左键移动手势、旧事件拒绝、提前松开、去重、名称冲突和原图字节。`tests/_verify_material_drag_300.py` 另检查完整 300 材质的文件准备及原生文件 URL。

实际 300 材质/900 张源贴图交接准备与哈希检查通过，首次后台准备约 5.2 秒。拖动及卡片相关回归通过 15 项；另补了“松开后又按下另一处，旧准备任务不得启动新拖动”的手势隔离检查。结果保存在 `artifacts/material-tests/stress-300/texture-drag-report.json`。

本机没有运行中的 UnrealEditor。本轮验证到了 Prism 的真实左键手势和文件交接载荷；没有把模拟 Qt 拖动执行当作 UE 接收端实测，也未宣称已在 UE 内容浏览器完整验收。

## 自发光、SSS 与查漏结果

`tests/_verify_material_special_effects.py` 用真实贴图实际出图，并比较开启/关闭的像素差异，而不只检查有没有报错。

- 自发光：Khronos CompareEmissiveStrength 原图；关闭灯光和环境光后，强度 0/1 仍有实际差异。许可保留在 `third_party/material-test-assets/Khronos`。
- SSS：用户植物 ORT 按 R 透明遮罩、G 粗糙度、B SSS；提取像素逐个对应原图 B 通道，背光下强度 0/1 有实际变化。
- 两者均核对导出原图哈希；也检查空闲停帧和相机交互唤醒。
- 其他回归涵盖颜色 Alpha、裁切/半透明、任意打包通道/独立贴图、法线 G 反转、四种预览形状、置换控件、多选/批量导出、原图缺失、过时结果和项目切换保护。
- 新发现并修复 16 位灰度 PNG 置换问题：Pillow 直接转 RGBA 会把大于 255 的值夹白。显示副本现在映射 0..65535 至 0..255，原始 16 位文件逐字节保留。

仍需明确的边界：

- 现在验收的是 Babylon 原生薄表面透光，适合叶片等薄材质。完整皮肤、蜡、玉石的体积 SSS 尚未完成，不能写成“SSS 全部正确”。
- 浏览器预览不能承诺与 UE 母材质逐像素一致；UE 原包取回以原包为准。本轮未实现 UE 插件。
- 通道语义不能可靠地从文件名/像素猜出；仍遵从用户明确的槽位和通道绑定。
- 尚未验收所有 DDS 压缩格式、EXR/HDR 和特殊色彩空间，不能宣称全格式支持。

## 架构和复现入口

渲染仍用 Babylon.js 8.26.0 和官方 glTF Loader，SurfaceStudio 的卡片生成函数未修改。新增部分是 Prism 的缓存预算、任务调度、日志、传输和数据服务适配，没有自写 PBR、GLB 或 SSS 内核。原文件存储、显示副本、元数据和界面状态继续分开。

- 下载：`tools/fetch_material_benchmark.py`。
- 全量出球/导出：`tests/_benchmark_material_300.py`。
- 保存后复开、主题、全局搜索和定位：`tests/_verify_material_library_300.py`。
- 自发光/SSS：`tests/_verify_material_special_effects.py`。
- 回归：`tests/test_material_performance.py`、`tests/test_material_global_search.py`、`tests/test_material_adjustment_reset.py`。

完整相关回归通过 78 项；之后最新补充集合通过 30 项；附件存储/材质记录另通过 40 项。集合有交叉，不相加冒充总数。截图见 `artifacts/material-tests/stress-300/final-ui/library-300-final.png`。
