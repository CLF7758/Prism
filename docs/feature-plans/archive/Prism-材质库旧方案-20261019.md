# Prism 材质展示库 + UE 收取插件：整体开发方案（大白话）

版本：4.0　更新：2026-10-19

**Prism 负责展示、保存、分类和取用。真正的 UE 母材质由用户提供，本项目不设计、不重建、不替换它。**

本文是当前唯一的整体实施主方案，覆盖 Prism、UE 插件、先后顺序、下载资料和验收。以前关于“用 AssetPort 生成 UE 母材质”的要求作废。

## 1. 先把两边的工作分清楚

| 谁 | 负责什么 | 不能混淆的地方 |
|---|---|---|
| 用户 | 提供真实的 UE 母材质、实例、贴图和必要依赖 | 不要求用户按我们的想法重做母材质 |
| Prism | 材质库入口、文件夹、标签、搜索、球体展示、预览调节、保存和导出 | 调预览粗糙度，不等于修改了真正的 UE 母材质 |
| UE 插件 | 把选中的真实材质整理完整、交给 Prism；再从 Prism 放回兼容项目 | 不重新生成用户的材质图，不擅自换母材质 |

Prism 内部为了画出球，会使用现成渲染器的材质对象。这只是展示所用的东西，不能把它叫成“我们替用户做的 UE 母材质”。

整个项目始终围绕：**收集什么、存什么、怎么取出来。**

## 2. 全部工作的先后顺序

| 阶段 | 先完成什么 | 完成后用户能干什么 |
|---|---|---|
| 第一阶段：Prism | 先入口和页面，再分类标签、存储、球展示、预览调节和导出 | 没装 UE 也能把贴图收进库、分类、套球查看并取出 |
| 第二阶段：UE 收取 | 再开发插件入口、完整收集和原样取回 | 把用户真实的 UE 材质收进库，之后放回另一兼容项目 |
| 第三阶段：跨电脑交接 | 完整搬库、更新包、大库优化和冲突恢复 | 首次传完整库，以后主要传变化 |
| 最后：整体发布 | 两端联调、兼容、故障和离线安装验收 | 用户不用安装开发环境就能正常使用 |

准备源码可以一次性完成。开发不能把 UE 放到 Prism 入口前，也不能先做一个球体实验就当材质库已经有了。

### D. 用户自己提供的 UE 材质资料

这部分不是 Git 依赖，也不是让开发替用户制作：

## 4. 第一件开发工作：先在正确位置做入口

左侧内容分区固定为：

```text
画布
脑图
文档
材质库
  未分类
  木材
    地板
  金属
  皮肤与蜡
标签
```

**材质库紧跟文档，标签仍是最后一个内容分区。** 不把材质库放到标签下面，也不藏进设置或某个弹窗。原有底部工具保持所在工具区域，不借这次改造乱排整个侧栏。

这一项在引擎接入之前完成，并单独验收。不是在树上加几个字：点击后必须进入真正的材质库页面，不能误进文档页、画布页或搜索结果页。

材质库跟当前 `.prism` 工程保存。同一工程里的画布都能引用它；跨工程通过材质包导入。第一版不暗中变成扫描整个电脑的公共全局库。

## 5. 入口、空页面和切换怎么工作

| 用户做什么 | 应该出现什么 |
|---|---|
| 点击“材质库”根目录 | 中间显示当前工程全部材质，不限于某个文件夹 |
| 点击子文件夹 | 显示该文件夹范围；包含子目录的规则明确显示，默认包含 |
| 第一次打开空库 | 显示“还没有材质”，提供新建文件夹、导入贴图入口；不自动塞假样例 |
| 没选材质 | 右侧显示简短说明，不残留上一张图片或文档的属性 |
| 选中一条材质 | 右侧显示该条预览、贴图、资料和预览设置 |
| 双击材质 | 打开更大的展示页面或窗口，保持同一条记录 |
| 从文档/脑图切进来 | 先接收并保存原页面有效编辑，不丢最后输入 |
| 从材质库回到文档/画布 | 原页面内容、位置和选择按原有规则恢复 |
| 再次进入材质库 | 恢复上次文件夹、搜索、滚动和选中项，不重复创建页面 |
| 删除当前选中材质 | 中间列表更新，右侧清空或选择相邻项，不引用已删除对象 |
| 切换工程 | 换成新工程的材质库，不串入旧工程贴图和预览 |

搜索、Delete、Ctrl+S、拖放都按照当前页面工作，不能进入材质库后仍操作背后的画布。Ctrl+S 保存当前工程需要的全部内容，材质不是一个临时网页。

入口骨架阶段可以先不显示尚未接通的导入功能；最终材质库交付时，空库里的新建、导入按钮必须可用，不能只做占位按钮。

## 6. 分类和标签怎么做完整

文件夹复用 Prism 当前的资源树服务。支持多层、新建、改名、移动、拖动、删除、恢复和撤销。一条材质一个主要文件夹，可以有很多标签。

分类移动只改归属，不重新复制几十 GB 贴图。删除文件夹时明确选择“内容移到未分类”或“连内容一起进回收站”。根入口不能被用户删除或拖到别的内容分区。

标签复用当前标签体系。材质参与标签重命名、合并、删除、计数、查询和批量修改，不只是在材质卡上显示几段字符串。

点击最下面的标签时，筛选结果要能找到该标签下的材质；若同时有普通图片等内容，按类型分组或明确筛选范围，不能只搜画布图元而漏掉材质。

材质支持按名称、标签、文件夹、透明方式、是否有 SSS、自发光、是否缺贴图查找。文件夹和材质数量必须来自真实记录，不靠启动每颗球统计。

材质拖到画布后是引用卡。删除一张卡只删除这次摆放；要删除库里的记录，用户在材质库里明确删除。同一材质可以被多张画布引用而不重复保存贴图。

## 7. Prism 到底收什么、存什么、怎么取

### 第一类：普通贴图和展示资料

收集：一套颜色、法线、金属、粗糙、透明、自发光、厚度等贴图，或用户手工指定的一组图片。

保存：原文件、每张图的用途和通道、名称、分类、标签、预览设置、预览图和来源。

取出：原样导出贴图，或者导出包含贴图与展示资料的 Prism 材质包。这里没有创建 UE 母材质。

### 第二类：用户已经做好的 UE 材质

收集：UE 插件整理好的原生材质、实例、父材质和必需依赖，以及版本、路径清单和 UE 预览图。

保存：原生文件完整保管；能取得的普通贴图单独关联。所有资料仍属于同一条材质记录。

取出：插件把这套真实资产按记录还原到兼容 UE 项目。用户只要普通贴图时，导出已经取得的图片文件。

同一条“木头”可以同时有普通贴图和 UE 原生包，界面显示“两者都有”，不拆成两个毫无关系的东西。

## 8. 展示必须分清“UE 原效果”和“Prism 套球预览”

Prism 的现成网页渲染器不能直接运行任意 `.uasset` 材质图，也不能保证复现用户母材质里的全部自定义节点。

所以保留两种展示：

- **UE 原效果**：插件在 UE 里生成的预览图，忠实保留收集时看到的效果。
- **Prism 贴图预览**：用已有渲染器把贴图套到球、平面、方块上，允许调粗糙度等查看效果；复杂 UE 材质可能只能近似展示。

预览设置单独保存。用户把球上的粗糙度从 0.5 调到 0.8，只改 Prism 这份展示设置，不改原始贴图，不改保存的 UE 包，也不在取回时擅自替换 UE 原参数。

如果用户要真正修改 UE 材质，就放回 UE 编辑，再收集成新版本。首版不把 Prism 做成 UE 材质编辑器。

## 9. Prism 第一期展示能力：八项全部支持

| 能力 | 用户能怎么查看或调预览 | 必须测什么 |
|---|---|---|
| 不透明 | 正常套图查看，忽略未启用的透明来源 | 颜色图带透明通道也不擅自挖洞 |
| 半透明 | 预览透明程度、透明图与背面 | 看得见背景，多层遮挡有明确处理 |
| 透明裁切 | 选择透明来源、通道、裁切门槛、背面 | 树叶轮廓和网眼正确；默认门槛显式设为0.5 |
| 金属度 | 数值或贴图，带环境反射 | 0和1效果合理，不能因为没环境光黑成一团 |
| 粗糙度 | 数值或贴图，选定正确通道 | 高光变化正确，改动只影响预览 |
| 法线 | 法线图、强度、DirectX/OpenGL方向 | 凹凸方向正确，不修改原图 |
| 自发光 | 图、颜色、强度和现成光晕 | 表面亮度与光晕分别生效、可恢复 |
| SSS次表面散射 | 开关、厚度和现成散射配置 | 真实散射开启，不能用半透明假装SSS |

这些都是 Prism 的展示能力，第一期不能把任何一项移到 UE 阶段才做。

SSS 和普通透明不是同一回事。保存时要包含现成渲染器需要的场景单位和散射配置；不能只保存一个勾选框，重开却没有效果。

使用现成的 `isScatteringEnabled`、`scatteringDiffusionProfile`、厚度及场景散射设置。不能把薄表面透光的距离滑条直接改名，就假装自己实现了另一套 SSS。

三种透明方式与其他预览属性分开记录，不做成八个互斥分类。对半透明与屏幕空间 SSS 等组合，先核对现成实现的真实限制，写支持表，不能静默关闭效果。

列表只用静态缩略图，当前选中的大预览才实时运行。预览模型、相机、灯光、参数控件、SSS和截图全部优先用上游现成能力，不重新编写渲染算法。

## 10. Prism 里怎么存，什么时候保存

第一期先接现有 `.prism` 工程和 SQLite 保存体系，增加真正的材质记录、资源和关联。不为了入口与预览功能先强制迁移整个工程格式。

一条材质需要保存：唯一编号、名称、分类、标签、原图、用途、预览设置、原生包版本、原生文件路径清单、来源和预览图。**预览设置与 UE 原件分开保管。**

原图必须已经复制到 Prism 自己管理的存储中。只记住 `D:/原项目/贴图.png` 不算收集完成。临时目录里的文件也不能作为长期保存保证。

原生包按文件保存和校验，不把几GB整体塞成一个没有边界的大字段。当前格式对单文件和总量的限制要预检，超过范围就明确说明；第三阶段再完成面向大库的存储升级，不能提前宣称无限容量。

| 用户操作 | 保存时机 |
|---|---|
| 改名称、分类、标签 | 操作后约半秒合并保存 |
| 调预览参数 | 停顿/松手后保存；连续操作最长约5秒留有效状态 |
| 导入/替换贴图 | 文件完整收进来，再发布新状态 |
| 接收UE原生包 | 全部必需文件校验并落盘，才确认完整收集成功 |
| 切页面、切材质 | 先收到最后参数回传，避免写错对象 |
| Ctrl+S | 等待当前修改真实保存完成 |
| 退出 | 完成有界保存；失败提示原因和恢复位置 |

这些是目标时间，实际慢盘要测。保存和导入共用一个写入队列；旧任务完成不能清掉后来新增的修改。未命名项目的材质也要有磁盘草稿。

缩略图是可重建缓存，原始贴图与原生包不是缓存。预览失败与保存失败分别显示；球画得出来不代表文件已经存住。

## 11. UE 插件只做用户真实材质的收取

插件暂定名 `PrismBridge`，作为独立编辑器插件开源。复用 HyperVault 相关代码和 UE 自带资产工具，保留原许可证；不把工具打进用户发布的游戏。

用户使用方式：

> 在UE内容浏览器选中真实材质/实例 → 右键“收集到Prism” → 看收集摘要 → 开始 → Prism确认保存成功。

插件需要先处理本次资产的未保存修改，但不顺手保存整个项目。一次选多条材质时，逐条有成功、失败和重试结果。

收集窗口同时显示“发送到哪个Prism工程、哪个材质文件夹”。本机打开多个Prism窗口或多个UE项目时，按明确的工程身份匹配，让用户选目标，不把最后打开的窗口随便当成接收方。

原来用 AssetPort 自动选择母材质、自动建立新材质的流程已取消。用户的母材质是什么就收什么，不把它替换成我们制作的版本。

插件新增代码独立维护并开源，计划使用MIT许可，保留HyperVault原有版权。Prism主程序许可不变，两边通过约定的消息和文件通信，不把Prism主程序实现直接复制进UE模块。

只有普通贴图、没有 UE 原件的条目，可以导出或通过插件导入纹理文件。若以后需要自动接入用户提供的母材质，再明确参数对应关系；这不是当前必须另做母材质的理由。

## 12. 点一次收集，后台按什么顺序做

1. 读取用户选中的根材质或实例，沿父级和引用查找依赖。
2. 显示名称、预计体积、文件数、缺件和外部插件要求。
3. 给这条收集记录分配稳定编号，准备独立的整理目录。
4. 调用UE高级拷贝，把可复制的项目资产整理进去并修正引用。
5. 检查整理后的根材质能否加载、编译、找到需要的文件。
6. 保存副本，生成UE原效果预览图、文件清单、版本和来源资料。
7. 用户选择需要时提取普通贴图，逐张记录来源。
8. 通过本机交接目录把文件交给Prism，消息传任务编号、清单和进度。
9. Prism校验并持久保存，返回保存确认。
10. 插件收到确认后才提示“已收集”，保留可重试结果。

Prism没开时可以启动它，或保存待接收包；中断后可继续，不把半套内容冒充成功。相同任务重复发送不会生成重复材质。

## 13. UE 整理目录和“全部依赖”怎么处理

推荐：

```text
Content/PrismM/MuTou_a83f29/R0001/
  Materials/
  Textures/
  Functions/
  Other/
```

中文“木头”用于显示，英文名便于路径阅读，唯一编号防止撞名，版本目录防止改动后覆盖旧包。只在Prism改显示名，不需要改UE内部路径。

原来不同目录可以各有一张 `T_Normal`。整理时保留必要子目录或生成不冲突的映射，不允许随便堆平后互相覆盖。

| 依赖类型 | 怎么处理 |
|---|---|
| 父材质、父实例、贴图、函数、参数集合等项目资产 | 找齐并经UE整理到独立目录 |
| 公共目录或别的项目目录里的必需资产 | 不能因为不在原目录就漏收 |
| 引擎自带资源 | 列为需要该引擎提供，不复制整个引擎 |
| 内容插件里的资产 | 能独立复制的整理；不能独立带走的记录插件要求 |
| C++自定义节点、着色代码、运行时外部条件 | 列出必要插件/环境，不能说普通资产文件已经包含全部能力 |
| 配套大数据、侧文件、虚拟化数据 | 核对是否已完整取得；拿不全要明确标记或失败 |
| 字符串动态加载等无法自动推断的资源 | 提供补充依赖入口，不承诺盲目发现全部 |

高级拷贝只创建副本，不改变原材质或场景引用。只有能确认由插件创建、已入库且没有被其他内容引用的副本，才允许用户选择清理；不默认删除原素材。

HyperVault现有依赖查找会按原目录过滤，旧取回流程也存在直接解包处理，因此不能原样当作完整性和安全覆盖保证。适配时保留可用部分，改掉不符合此流程的部分。

## 14. 普通贴图怎么从 UE 取得

有原始PNG/EXR等文件且允许保留时，收下原文件。原图丢失时可通过UE现成导出能力取得图片，但明确标记“由UE导出”，不能说恢复了已丢失的原图。

提取材质引用的纹理，与把任意复杂材质最终效果烘焙为一套贴图，是两件事。本方案先完成前者，不为展示功能自行写通用烘焙器。

如果母材质参数名能对应到颜色、法线、粗糙度等用途，就按已提供的对应关系给Prism预览；不知道用途时保留文件并让用户手工指定，不乱猜后覆盖资料。

UE原生包和普通贴图分别记录完成状态。完整包成功但贴图提取失败时，明确告诉用户，不把“两者都成功”当成统一结果。

## 15. 从 Prism 取出：两条路都要清楚

### 只要图片文件

选中材质 → 导出贴图 → 选择位置。默认原样导出，转换方向、格式或拆通道只生成额外文件，不改库内原件。只有UE纹理资产、没有普通图时，需要插件提取，不能改后缀伪装成图片。

### 把真实 UE 材质放回项目

1. 选择有原生包的材质与版本，点击“放入UE项目”。
2. 插件检查目标引擎版本、插件条件、路径、重名和本地未保存修改。
3. 默认恢复到收集包里记录的独立路径，保证内部引用成立。
4. 加载根材质，检查依赖，保存并定位到结果。
5. UE重启后仍可使用，才算验收通过。

同一版本已存在时识别并复用，不反复复制。不同内容遇到同路径时，明确选择保留本地、另存版本或受控更新，不能直接覆盖正在加载的资产。

用户想换UE文件夹时，通过UE自己的移动/高级拷贝处理引用，不只移动磁盘文件。原生材质取回不应用Prism的预览滑条值，用户的母材质和原参数按保存版本保留。

本机现有UE5.7.4与5.3.2。先选5.7.4做完整闭环，再单独验证5.3.2；插件分别编译。不能承诺新版本保存的原生资产能回到旧引擎。

## 16. 两端分别改哪里，哪些代码复用

| 位置 | 要做的事 | 现成来源 |
|---|---|---|
| Prism左侧树和导航 | 文档下材质库、标签最后、独立页面路由 | 当前 `workspace_service.py`、`resource_tree_model.py`、`window_workspace.py` |
| 分类/标签/搜索 | 材质记录参与计数、重命名、批量和筛选 | 现有资源树、`tags.py`、标签面板与搜索服务 |
| 列表和详情 | 卡片、缩略图、预览资料和状态 | 当前 `asset_browser.py`、`detail_panel.py` 等 |
| 展示渲染 | 全部八项能力、球/平面/方块、相机和截图 | Babylon.js现成PBR、SSS、Inspector |
| 原件/预览设置保存 | 分开记录、同工程写队列、原图持久化 | 当前SQLite、文件读写、附件与保存入口 |
| UE右键和发布 | 选择资产、显示收集摘要、预览与记录 | HyperVault相关源码+UE编辑器接口 |
| UE依赖整理 | 完整找依赖、独立路径、改引用、校验 | UE自带AssetTools/AssetRegistry/高级拷贝 |
| UE取回 | 查重、恢复、加载和保存 | HyperVault可用流程+UE资产接口 |
| 两端通信 | 任务号、文件交接、进度、确认与重试 | 现有本机通信/文件能力；只增加Prism协议适配 |

不会因为“复用”就零适配：现成引擎不知道Prism的分类，HyperVault不知道Prism怎么确认保存。我们只补这类连接和业务逻辑，不重写已有渲染、SSS、数据库、文件树、母材质和压缩器。

代码审查时特别检查：现有标签和素材查询主要遍历画布图元，材质不是图元，必须增加记录适配；现有非脑图页面可能默认按文档处理，必须加独立材质路由。不能只往常量里加一个名字就认为接入完成。

## 17. 逐步开发清单：不再省略入口和基础工作

| 顺序 | 具体工作 | 通过条件 |
|---|---|---|
| 0.一次备齐资料 | 核对两个源码ZIP、环境包、用户UE材质和版本；锁版本 | 来源、许可、完整目录和构建依赖清楚，不自动追最新 |
| 1.Prism入口 | 文档下增加材质库，标签最后；点击进入独立空页面 | 不依赖Babylon或UE也能打开入口，不误入文档/画布 |
| 2.页面与库基础 | 根目录/文件夹范围、空态、选择、切换状态、材质真实记录 | 返回页面不丢位置，不串工程；资料可保存重开 |
| 3.分类与标签 | 子文件夹、拖动移动、批量标签、搜索、撤销/回收站 | 材质参与完整标签操作，分类移动不复制原图 |
| 4.原图收集与持久化 | 导入、指定用途和通道、复制入库、未命名草稿 | 移走源文件后还能查看和取出，失败不假报成功 |
| 5.接现成展示 | 在Prism当前QtWebEngine中验证全部八项能力 | 真SSS、自发光、透明等逐项有效；不是只在外部浏览器通过 |
| 6.接预览设置与缩略图 | 现成面板接记录，合并保存，球/平面/方块，静态卡片 | 设置重开一致，不改变原件；列表不同时运行千颗球 |
| 7.Prism导出和画布引用 | 原图导出、材质包往返、画布引用卡 | 另一工程导入资料齐全，删除一张卡不删材质 |
| 8.Prism阶段验收 | 保存/退出/恢复/旧工程回归/离线安装 | 入口、分类标签、展示八项、存取全部通过，才能进入UE |
| 9.UE插件基础 | 开源编辑器模块、右键、接收设置和连接 | 插件可启动关闭、注册清理正常，不改用户母材质 |
| 10.完整收进Prism | 查依赖→高级拷贝→检查→预览→发送→落盘确认 | 关闭并移走源项目后，Prism拥有完整可取的内容 |
| 11.原样放回UE | 查版本/插件/重名→还原→加载→保存 | 空白目标项目和重启测试通过，根材质不偷引源项目 |
| 12.批量与异常 | 多选、重复收、版本、断连、取消、缺件、恢复 | 每条结果准确，失败重试不毁旧版或覆盖本地修改 |
| 13.大库与完整搬迁 | 容量基准、需要时升级托管目录、完整包与迁移 | 原内容不丢，跨机断网可打开，明确真实容量边界 |
| 14.小更新包 | 变化记录、共同基线、收件确认、重复乱序与冲突 | 两台共有原库后只传变化，不新建第二个项目 |
| 15.整体发布 | 两端兼容、性能、许可证、安装包、使用说明 | 干净环境可使用，必需条件和已知限制写清 |

步骤1先于渲染接入，步骤8先于UE开发。源码在第0步一次准备齐，不表示所有依赖都在第一天接入。

## 18. 第三阶段：大库、完整包和更新包

最初沿用`.prism`有利于先交付功能，但大库不能靠未测的单文件格式硬承诺。到大库阶段，用真实样本测加载、保存、导出、磁盘峰值与恢复，再实施已设计的托管目录和不可变资源存储；迁移保留材质编号、分类和两端绑定。

首次搬到另一电脑，导出完整库。以后发送更新包，内容包括变过的资料、新原图、新的UE原生版本和删除记录，不重新传旧的全部资源。

只改预览粗糙度、标签或位置，不重传旧贴图。新增2GB素材，包仍需带这些新增内容，不能保证永远几MB。

“上次导出了”不等于对方收到了。默认相对共同确认版本生成累积更新：对方漏掉U1，只收到U2也能取得这段期间需要的变化；收到回执再缩小下一包基线。

接收端双击/拖入包，按库编号找到本机原库，校验和应用；不要求用户每次同时导入大包和小包。重复、乱序、缺前置版本、双方改同一条、一边删另一边改，都有明确处理，保留冲突而非按系统时间覆盖。

更新包导出固定一个版本，导出期间的新编辑进入下一包。用户不会每操作一下就在桌面多出一个小文件。详细保存与同步细则可参考技术附录，但不能把附录旧的阶段顺序重新拿来覆盖本方案。

## 19. 必须提前处理的问题

| 情况 | 处理 |
|---|---|
| 两条都叫木头 | 显示名可一样，内部编号和整理目录不同 |
| 同一材质修改后又收集 | 选择同记录新版本或独立副本，旧版能找回 |
| 预览和UE原效果不同 | 清楚标识两种展示，不改原生包来迁就预览 |
| 公共父材质或函数在别的目录 | 不能漏收，整理后再检查引用 |
| 缺外部插件或不兼容引擎 | 收集/取回前说明条件，不把失败藏到导入后 |
| 原PNG已丢失 | UE导出图标明来源，不伪称原图恢复 |
| Prism没开、传输中断 | 保留待收任务，允许重试，落盘前不报成功 |
| 磁盘满或只读 | 旧版保持有效，失败原因和恢复位置明确 |
| 参数回传晚了 | 按材质编号和编辑批次处理，不写到下一颗球 |
| SSS不受当前显卡支持 | 明示能力限制，资料仍可存取；不能用透明代替SSS过验收 |
| 目标UE资产正被加载/修改 | 不直接覆盖文件，保留本地或另存版本 |
| 清理缓存/回收站 | 缓存与原件分开，仍被历史或任务引用的资源不误删 |
| 未知来源包 | 校验路径、大小、摘要，不越界写文件、不执行包中脚本 |
| 原生包已存好，普通图没提完 | 分别显示状态，允许补做，不假报两者都成功 |

母材质和实例的原内容始终由用户掌握。Prism预览参数、分类和标签的修改不能悄悄回写UE原件。

## 20. 验收按实际故事走，不只看按钮

### 第一组：Prism本身

- 启动后左侧顺序确实为画布、脑图、文档、材质库、标签。
- 空库能正常进入；新建分类、导入、切页、搜索和删除的状态正确。
- 木头、金属、树叶、薄纱、发光表面、皮肤/蜡样例覆盖全部八项展示能力。
- 分类、标签和预览设置保存重开一致，SSS场景设置也恢复。
- 原贴图移走仍能导出；同材质多处引用不重复复制文件。
- 只改预览，原始图片和保存的UE文件校验值不变。

### 第二组：UE双向闭环

- 用用户提供的真实材质收集，不生成替代母材质。
- 材质实例依赖公共父材质/函数，仍能完整整理。
- 关闭源工程、把源工程移走后，Prism还能向空白兼容项目提供材质。
- 目标UE保存并重启后仍可用；预览滑条没有改变原生参数。
- 重名、版本不兼容、缺插件、半途失败和重复操作不会毁坏已有内容。

### 第三组：搬库与大库

- 完整包在新位置、无网络和无原路径条件下可用。
- 双方已有原库，只传更新能得到正确结果；重复和乱序不回滚。
- 100张画布、约1万图片、100篇文档、100张脑图、1000套材质和约100GB数据按真实机器测量，记录性能和限制。
