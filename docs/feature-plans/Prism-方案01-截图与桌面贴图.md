# 方案 01：截图、桌面贴图与当前画布互通

日期：2026-10-15。状态：待实施。核心实现直接复用开源项目。

## 1. 最终用户能做什么

- 点画布工具栏“截图”，框住屏幕区域，选择“钉在桌面”“送入画布”或“两者都要”。
- 对画布图片点右键“钉在桌面”，把它变成独立于 Prism 缩放和移动的参考窗。
- 参考窗支持拖动、缩放、透明度、锁定位置、鼠标穿透、复制、保存、关闭和送回画布。
- 切换到 Photoshop、Blender、Maya 或其他软件时参考窗仍在；Prism 切换画布不会把参考窗缩放或藏起来。

## 2. 复用哪个项目，怎样避免重写

采用 [InterwovenCode/ScreenPinKit](https://github.com/InterwovenCode/ScreenPinKit)。它已经包含截图窗、桌面贴图及标注；主项目 MIT，基于 PyQt5。[项目说明](https://github.com/InterwovenCode/ScreenPinKit#readme)。

本次核对源码 commit：`1c0dc5fa14a9ec99660fbb3bc6eade7d7d1c3f77`。正式构建先将这个 commit 作为可复现的接入基线，再独立验证是否升级。

| 上游现成组件 | 本次核对到的接口 | 接入用途 |
|---|---|---|
| `src/view/screen_shot_window.py` | `ScreenShotWindow`、`reShow()`、`snipedSignal(QRectF, QPixmap)`、`closedSignal` | 直接复用框选截图、屏幕坐标和取消 |
| `src/manager/pin_window_manager.py` | `PinWindowManager.addPinWindow(screenPoint, realSize, pixmap)` | 直接创建和管理贴图窗口 |
| `src/view/pin_editor_window.py` | `PinEditorWindow`、`grabImage(withShadow)`、`setMouseThroughState()` | 直接复用贴图缩放、编辑与穿透 |
| `src/plugin/plugin_interface.py` | `RegisterContextMenuEvent`、`RegisterToolbarMenuEvent`、`ImageCopyingEvent` 等事件 | 优先通过插件增添“送入 Prism”按钮 |

这些接口来源于上游代码，不表示上游已经支持 Prism 通信。需要新增的是一个轻量桥接插件/启动器和 Prism 侧调用流程，不重写截图选区、画笔、贴图窗口或窗口缩放。

### 为什么用独立助手

Prism 当前为 PyQt6；ScreenPinKit 为 PyQt5，依赖中还有 QtWebEngine、Fluent Widgets 等。不能直接把两套 Qt 导入同一个进程。采用独立 `PrismCaptureHelper.exe`，内部运行锁定版本的 ScreenPinKit；Prism 仍只运行现有 PyQt6。[上游依赖清单](https://github.com/InterwovenCode/ScreenPinKit/blob/main/requirements.txt)。

第一阶段不做 Qt6 移植，不为了统一语言而重写成熟功能。助手样式通过上游主题配置和桥接按钮调整；不能移除版权标识或遗漏依赖许可证。

备选是 [Flameshot](https://github.com/flameshot-org/flameshot) 或 [ShareX](https://github.com/ShareX/ShareX)，但不同时给用户安装三套截图工具。只有当前助手的 Windows、多屏或维护验证失败，才评审替换适配器。

## 3. Prism 内的入口

| 位置 | 名称 | 行为 |
|---|---|---|
| 画布顶部工具栏 | 剪刀图标“截图” | 开启框选，保留当前导入目标和视口中心 |
| 主菜单“插入” | “屏幕截图…” | 与工具栏同一个动作 |
| 图片右键菜单 | “钉在桌面” | 对单张图片创建参考窗 |
| 多张图片右键菜单 | “将所选图片钉在桌面…” | 每张独立贴图，显示数量；大量选择时先给出数量确认，避免上千窗口 |
| 截图完成浮动栏 | “钉在桌面 / 送入画布 / 两者都要 / 取消” | 一步决定去向 |
| 贴图右键菜单 | “送入 Prism 当前画布” | 作为新素材导入，不移动原素材 |
| 设置→快捷键 | “屏幕截图 / 隐藏或显示贴图” | 用户自行启用和修改全局快捷键 |

全局热键不照搬上游 F2：Prism 的 F2 已用于重命名。建议提供 `Ctrl+Alt+A` 为可选截图快捷键，安装时检测冲突；被占用就显示冲突，仍可点按钮。贴图聚焦时 Esc 关闭当前贴图；截图中 Esc 取消截图，不修改工程。

## 4. 三条具体操作流程

### A. 截图 → 桌面贴图

1. 用户点“截图”。Prism 记录来源工程、真实目标画布和视口位置；让截图助手接管选区。
2. 截图前隐藏会遮挡选区的浮层和截屏按钮状态，等待屏幕完成一帧再抓取；不能截进自己的过渡残影。
3. 用户拖选，松开后浮动栏提供三种去向。点“钉在桌面”直接调用上游贴图管理器。
4. 此流程不向工程插入任何东西，也不使工程变脏。关闭参考窗不删除原截图的已保存文件。

### B. 截图 → 当前画布

1. 框选结束点“送入画布”；助手把实际截图保存成 PNG，发出结果消息。
2. Prism 校验消息、文件大小及目标工程，保留 PNG 原字节到现有素材存储，再走插入撤销命令。
3. 图片放到启动截图时记录的视口中心，按原始宽高比插入；仅选中新图片。一次导入只产生一次撤销记录。
4. “全部素材/未分类/标签”等聚合页没有持久化目标时，让用户选择画布；选完记住目标。不得把截图放进稍后会清空的临时注释层。
5. 点击“两者都要”时，一个截图结果分别用于贴图和导入，不重复截图，不重复导入两张。

### C. 画布已有图片 → 桌面贴图

1. 右键图片→“钉在桌面”。工作流取得稳定素材 ID，不把可回收 Qt 图元指针传给助手。
2. 后台从原图存储读取、按显示需求生成贴图文件；默认保留原裁剪、翻转及用户明确设置的灰度/透明度效果。临时曝光、假色检查不写入源文件，也不默认带入贴图。
3. 图片原文件仍在工程；桌面贴图是独立显示副本，移动贴图不改变画布坐标。
4. 原图不可用时明确提示可用预览的分辨率，用户选择后再使用；不能把 8px LOD 预览放大并假称原图。
5. 默认在鼠标附近以屏幕可容纳尺寸显示，最大不超过当前显示器可用工作区的 80%。放大时再按需加载更清晰层级。

## 5. 桌面参考窗的交互约定

| 操作 | 约定 |
|---|---|
| 拖动 | 左键拖动图片；锁定位置后拖动无效 |
| 缩放 | 滚轮围绕鼠标缩放，保持长宽比，不能影响 Prism 画布缩放 |
| 透明度 | 右键透明度滑杆，保留可见边框提示 |
| 鼠标穿透 | 开启后显示短提示；托盘菜单“取消所有穿透”始终可恢复操作 |
| 复制/保存 | 复用上游复制与保存；保存不含窗口阴影；文件存在时遵循覆盖询问 |
| 隐藏全部 | 只隐藏助手管理的贴图，恢复时回到原屏幕位置 |
| 关闭工程 | 贴图继续存在；原工程无需保持打开。送回画布时重新确认当前工程 |
| 删除源素材 | 已打开贴图仍可作为临时参考；“定位来源”显示源素材已删除，不能跳到别的素材 |
| 同图再次贴图 | 先复用/激活已经存在的窗口；是否支持重复独立窗口放到后续选项 |

## 6. 通信和数据约定（待实现的适配接口）

使用 Qt LocalSocket/LocalServer 的本机通信，助手端 Qt5 与主程序端 Qt6 分进程，各自使用自己的 QtNetwork。每个 Prism 会话使用随机通道名和 token；不开放公网端口。消息为带长度的 UTF-8 JSON，单消息设上限；图片通过本次任务目录传文件，不把大幅 Base64 塞进日志和消息。

请求包含：`protocol_version, request_id, command, session_token, project_id, project_generation, target_canvas_id, image_path, screen_position, device_pixel_ratio`。命令限于 `capture / pin_file / hide_all / show_all / close_pin / shutdown`。

响应包含：`request_id, status, result_path, pixel_width, pixel_height, logical_rect, device_pixel_ratio, sha256, error_code`。仅在用户点击“送入画布”时附导入意图。Prism 以 `request_id` 去重；先成功接收持久化再回执，助手才删除任务临时文件。

任务文件目录与上游截图缓存目录分开。上游现有 `clearScreenImages()` 会整理其截图缓存，不能把等待导入文件放进那里以免误删。原图或工程目录从不交给助手执行清理。

## 7. 多屏、质量与性能

- 截图结果记录物理像素尺寸与每屏 DPI，窗口坐标使用逻辑坐标。测试负坐标副屏、跨 100%/150%/200% 缩放移动，以及竖屏。
- 跨屏截图必须验证上游坐标转换；混合 DPI 拼接不正确时，仅修上游适配处并保留补丁，不在 Prism 另写一个截图引擎。
- 不把截图先压缩成 JPEG 再入库；保留 PNG、透明通道和真实尺寸。颜色管理能力按实际测试说明，不承诺截图能够恢复显示器 HDR 原始动态范围。
- 默认最多同时打开 20 个贴图窗；解码文件队列最多 2 个。显示缓存总预算目标 128 MiB，超预算逐出离焦窗口高分辨率层；不能只按窗口数限制而允许每窗无限占内存。
- 常驻助手按需启动；无贴图且无截图任务后空闲 60 秒退出。原图解码不在 Prism GUI 线程执行。
- 首个可用预览目标 300 ms 内、助手已启动时框选响应目标 100 ms 内。这是验收目标，须在目标机器测量，当前未实测。

## 8. 实施任务与验收

| 阶段 | 必须交付 | 验收方式 |
|---|---|---|
| S1 上游验证 | 独立构建 ScreenPinKit、固定依赖、许可证清单 | Windows 10/11 普通账户可截图和贴图，不依赖开发者 Python |
| S2 最小桥接 | 截图回传、调用 `addPinWindow`、送入 Prism 插件按钮 | 不使用模拟按键或抢占系统剪贴板作为唯一通信方式 |
| S3 Prism 接入 | 三个入口、目标画布和撤销、原图持久化 | 截图导入后重开工程清晰，源 PNG 字节哈希一致 |
| S4 桌面体验 | 穿透恢复、隐藏全部、多屏、助手退出 | Prism 最小化和切换画布不影响贴图 |
| S5 打包回归 | 可选助手组件、崩溃隔离、内存限额 | 助手崩溃后主工程仍能保存；重复 100 次截图/关闭无持续增长 |

另外逐条验收：取消不导入；同一回包不重复插入；等待截图时换工程不串工程；目标画布被删后进入待处理；删除源图不导致贴图崩溃；贴图保存无阴影；混合 DPI 图像无偏移；全局 F2 不抢 Prism 重命名；无助手时入口给出安装操作；断网仍能完成所有截图/贴图操作。

日志只写截图尺寸、数量、耗时和错误，不写屏幕内容。记录 `capture.start / capture.ready / capture.cancel / pin.open / pin.close / capture.import`，关联同一个请求 ID，服从主程序的日志轮转上限。
