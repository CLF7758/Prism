## 1. 最终给用户做出来的是什么

它是一个可以收进来、看效果、分类整理、再取出去的材质储存库。

用户可以往里面放两类东西：

1. 从电脑上选一组材质贴图，例如木头的颜色图、粗糙度图、法线图。
2. 从 UE 选一个已经做好的材质或材质实例，连同它的贴图、母材质及其他必要依赖一起收进来。

两类内容都显示成材质卡片。Prism 用贴图和展示资料把效果显示在球上，不要求用户自己准备一张球体效果图，也不要求用户电脑上一直开着 UE。

UE 原件、普通贴图、Prism 展示资料分开保管，但可以属于同一条材质记录。整理分类、加标签和生成缩略图，不改变原件。

**你提供真实 UE 母材质和用于“只有贴图”场景的默认 UE 材质模板。开发负责接入、贴图对应、实例生成、存储和取回，不另做一套 UE 母材质。**

## 2. SurfaceStudio 怎么直接用

以现有源码为基础改造，移植能用的模块，不重新画一套相似界面，也不另写同类扫描器、收藏系统和材质卡片。

| 已有部分 | 怎么用在 Prism |
| --- | --- |
| 卡片网格、卡片大小、列表切换 | 直接复用，默认是用户参考图那样的缩略图卡片网格 |
| 点击卡片、选中高亮、右侧详情 | 直接复用交互和布局，右侧加入贴图生成的球体展示与 UE 资料 |
| 搜索、分类、收藏、最近浏览、集合、对比 | 沿用已有功能，接到 Prism 当前工程和记录 |
| 贴图文件名识别、元信息读取 | 沿用已有扫描逻辑，补 UE 常见命名、通道打包和导入确认 |
| 贴图缩略图、颜色图放大、平铺检查 | 复用已有能力，原文件由 Prism 的托管存储提供 |
| 原有本机通信及任务结果思路 | 能用的保留，将 Blender 专用消息改成 Prism 与 UE 的任务协议 |
| Blender 插件和节点构建 | 不装进 Prism 的 UE 流程；用 UE 插件及你提供的默认材质接替 |
| SurfaceStudio 自己的启动器、安装器、独立侧栏 | Prism 继续负责启动和外壳，不让用户面对两个软件、两套分类侧栏 |

源码位置已经明确：

- `public/app.js`：`drawCards`、`openDetail`、`renderResults`、`statsHTML` 等。
- `public/style.css` 及配套界面文件：卡片、详情、标签和布局。
- `server.py`：`scan`、图片访问与索引等。
- `organizer.py`、`public/organizer.js`、`public/categories.js`：整理、分类及相关操作。
- `blender_bridge.py`：本机任务交接的参考基础；其中 Blender 对象选择、节点等逻辑不能直接当成 UE 接口。

**需要改的不是它“是不是材质库”，而是三处具体差异：**

1. 它现有普通材质库主要扫描原目录。这里要把原文件复制收进 Prism，源目录移走后仍能取出。
2. 它现有材质球展示主要读取已有图片。这里必须能从贴图生成球体展示。
3. 它连接 Blender。这里连接 UE，既能还原用户原件，也能给普通贴图配上你提供的默认 UE 材质。

SurfaceStudio 的界面与业务代码保留来源和 GPLv3 许可。Prism 已有文件树、标签及工程保存继续复用；同一个功能只保留一份真正生效的数据，避免 SurfaceStudio 和 Prism 各存一套分类后互相不认识。

网页界面接入 Prism 已有的 QtWebEngine。保留现成业务模块，改它们的资料来源与保存接口；不用再启动一个 SurfaceStudio 桌面窗口，也不用重写一套 Qt 卡片来模仿网页。

卡片、分类、收藏、最近、集合、标签统一使用同一个稳定材质编号。重复扫描或改名不能让这些关系丢失；迁入既有 SurfaceStudio 索引时，要保留旧编号到新记录的对应关系。

## 3. 界面长什么样，点哪里会发生什么

### 左边：分类和入口

顺序固定：**画布 → 脑图 → 文档 → 材质库 → 标签**。

材质库下面放用户自己的文件夹，例如木头、金属、布料、植物，可以继续分子文件夹。入口的“＋”和右键可以新建分类。文件夹支持改名、移动、删除与恢复。

点材质库根入口看全部材质；点文件夹看该文件夹及子文件夹里的材质，页面上写清当前范围。切去文档再回来，恢复上次的范围、搜索、滚动位置和选中材质。需要回全部时，再点材质库根入口或页面中的“全部材质”。

收藏、最近浏览和集合沿用 SurfaceStudio 的功能，放在材质库页面内的快捷筛选区域，不再额外造一套覆盖 Prism 的左侧栏。集合只是挑选材质组成一组，不重复复制原文件。

### 中间：材质卡片列表

**默认是多列缩略图卡片，不是目前那种几行文字条目。**

每张卡片主要展示：

- 由贴图生成的材质球缩略图。
- 材质名称。
- “只有贴图”“含 UE 原件”或“两者都有”的标记。
- 已知的 UE 版本、少量标签，以及缺件等必要状态。

没有生成完缩略图时，显示真实的“正在生成”；缺贴图就显示缺件，不用无关球图充数。卡片列表用缓存好的图片，不让几百颗球同时运行。

上方提供搜索、排序、筛选、卡片大小和导入入口。沿用 SurfaceStudio 现有的网格／列表切换，默认保持参考图的卡片网格。

- 单击卡片：选中它，右边切换到这条材质。
- 多选：批量加标签、移动分类、收藏或导出。
- 右键：查看资料、整理分类、导出、发送到 UE、删除等。
- 进入文件夹：更新卡片范围，不打开文档编辑器。
- 改分类或集合：只改归属，不重新复制几十 GB 贴图。

### 右边：效果、参数资料、版本和标签

从上到下展示：

| 区域 | 展示什么、怎么操作 |
| --- | --- |
| 材质球效果 | 根据实际贴图与展示资料画出球体；可转动、放大查看，材质参数固定，不提供实时调参滑条 |
| 名称与来源 | 材质名称、说明、来自本地贴图还是 UE、当前分类 |
| 版本 | UE 引擎版本、这条记录的收集版本；使用默认模板时再显示模板名称与版本，三者分开 |
| 材质属性 | 不透明／透明裁切／半透明；金属度、粗糙度、法线、自发光、SSS 的已知信息和使用通道 |
| 标签 | 标签列表，点击可筛选；支持使用现有标签系统添加、删除及批量整理 |
| 贴图明细 | 每张图的用途、名称、真实像素尺寸、格式、大小；可打开原图、放大和平铺检查 |
| UE 原件 | 是否完整、主材质或实例、依赖数量、需要的引擎及额外插件 |
| 取出入口 | 导出原贴图、导出材质包、发送到 UE；根据实际收存内容提供可用操作 |

没有来源数据的版本和参数写“未提供”；使用默认展示值的地方写“默认”，不假装是从 UE 读到的值。普通贴图没有 UE 版本时也能正常入库和展示。

“球上的粗糙感”来自实际贴图或已记录的展示值。右侧参数是查看资料，不是把 Prism 做成材质编辑器。

## 4. 第一期要能显示哪些效果

以下效果都属于 Prism 第一期，不能拖到 UE 插件完成后才支持。

| 效果 | 球上应该看见什么 | 要接入什么资料 |
| --- | --- | --- |
| 不透明 | 正常完整表面 | 颜色与明确的不透明方式 |
| 透明裁切 | 树叶、网孔等轮廓被正确裁出 | 透明来源、通道、裁切门槛；默认门槛明确记录为 0.5 |
| 半透明 | 能透过表面看见背景 | 透明图或固定透明值、背面及必要展示设置 |
| 金属度 | 金属反射效果 | 金属贴图／固定值，配现成环境光 |
| 粗糙度 | 磨砂或光滑程度正确 | 粗糙贴图／固定值及使用通道 |
| 法线 | 表面的细节起伏正确 | 法线图、方向约定，必要强度资料 |
| 自发光 | 发光区域与颜色正确 | 自发光图、颜色和强度；需要光晕时使用现成能力 |
| SSS 次表面散射 | 皮肤、蜡等散射效果 | 厚度、散射颜色和现成渲染器需要的散射设置 |

三种透明方式是一组选择；金属、粗糙、法线、自发光、SSS 可以按资料组合，不是八个互斥分类。

**用 Babylon.js 已有的球体、PBR、透明、法线、自发光和 SSS 实现，不自己写渲染算法，不接一套交互式材质编辑器。**

显示过程是：取得贴图与固定展示资料 → 套到球上 → 生成卡片缩略图 → 点选时在右侧显示。平时只有右侧选中的一个展示场景工作；切走材质库就暂停。

主展示必须能够在没有 UE、没有预先准备球图的情况下成立。UE 预览图可以作为附加参考，但不能成为展示功能的前提，也不能用它代替贴图套球。

Prism 按贴图和已知资料绘制展示效果。复杂 UE 自定义节点需要补充可用展示贴图或参数；资料不全时标出缺少什么，原始 UE 资产仍完整保管。不能承诺网页渲染器自动运行任意 UE 材质图。

验收要检查真 SSS，不把普通透明当散射。半透明与 SSS 等组合按所用渲染器实测结果列明，不能静默关闭效果后仍显示“全部支持”。

## 5. 用户从电脑导入一套贴图，怎么走

以“木头”为例：

1. 点击“导入贴图”，或把贴图／文件夹拖到材质库中间。
2. 沿用 SurfaceStudio 扫描和命名识别，分组为一套木头材质；支持直接选一套贴图目录，也支持批量选库目录。
3. 显示导入确认：这是颜色、这是法线、这是粗糙度；能识别的自动填，拿不准的让用户指定用途。
4. 用户填写名称，选择分类和标签，确认不透明／透明裁切／半透明等必要信息。
5. 原文件真正复制入库，保存用途和通道对应关系。
6. Prism 用这些贴图生成球体和卡片缩略图。点卡片，右侧看效果、参数资料和贴图明细。
7. 关闭软件、移走原贴图文件夹，再开 Prism，仍然可以展示和导出原文件。

导入确认不是实时材质编辑器。用户在这里纠正“哪张图接哪个用途”，确认后再生成展示。

补齐 SurfaceStudio 现有规则的不足：

- 能选到真正装贴图的那一层，不能因为选了一套材质目录就扫描出 0 条。
- 对多层分类目录提供递归发现和分组确认，不能把整库误合并成一条材质。
- 增加 UE 常见后缀和 ORM／RMA 等打包贴图的通道对应；拿不准时必须确认。
- 原图保持原样，展示需要转换时另生成缓存。EXR 等高精度原件保留；预览代理的支持情况单独显示。
- 实际读取像素尺寸，不只按文件夹名中的“4K”猜分辨率。
- 只传一张法线、颜色图或其他单通道时也能收进库，明确它是单通道资产；展示使用已标明的其余默认配置。

## 6. 用户从 UE 收进来，怎么走

UE 插件后做，先完成 Prism 的库、普通贴图导入、套球展示和保存。

插件提供“收集到 Prism”：

1. 用户在 UE 内容浏览器选中材质或材质实例，点击收集。
2. 插件找齐该材质的贴图、父材质、函数、参数集合、SSS 配置等必要依赖，给出收集摘要。
3. 使用 UE 自带高级拷贝，整理到独立目录，例如 `Content/PrismM/MuTou_编号/R0001/`。用户原工程资产继续保留。
4. 检查引用是否仍偷偷指向原目录；确实需要的引擎或额外插件依赖另列清楚。
5. 保管整理好的 UE 原生文件，同时尽量取得可供 Prism 展示的普通贴图与参数对应关系。
6. 发送到 Prism；Prism 校验文件、收进自己的存储、生成展示资料和球体缩略图。
7. 确认完整落盘后才报告“收集成功”。缺件、缺展示贴图和完整原件分别标明，不能混为一个成功状态。

UE 资产有原始 PNG 等源图时尽量收原图。只能从 UE 纹理导出图片时明确标记“UE 导出图”，不说它就是丢失的原始源文件。

只拿到 `.uasset` 且无法取得展示贴图时，仍可保存原件，但该条记录显示“待补展示贴图”，不能拿一张默认球假装已复现。

## 7. 用户取到 UE，分两条路

### A. 这条记录本来就带 UE 原件

用户点“发送到 UE”，选择当前连接的目标 UE 项目。

插件检查版本、必要插件和重名，再把保存的原生材质及依赖放回目标工程。**取回的是用户上传的那套资产。**

Prism 的卡片样式、分类、标签和展示默认值不会改写原件。目标项目里原件的文件位置和内部引用由 UE 工具正确处理，不能只往资源管理器里随便复制文件。

### B. 这条记录只有普通贴图

用户点“发送到 UE”，插件按这条记录的透明方式和材质用途，选择**你提供的默认 UE 材质模板**。

接着导入贴图，按已确认的用途、通道和模板参数名称接好，创建材质实例，再放到目标工程的 PrismM 目录下。

例如：木头贴图配你的默认不透明模板；树叶贴图配你的裁切模板；半透明资料和 SSS 资料使用你提供的适用模板。具体模板数量由你的实际素材决定，不强行限定为只有三个。

这里新增的是贴图导入与实例绑定，不从零制作母材质。对应模板还没提供或目标 UE 不兼容时，说明缺哪一项，仍允许单独导出原贴图。

模板适配需要一张清楚的对应表：哪个模板、支持哪个 UE 版本、颜色／法线／粗糙度等参数叫什么、打包通道怎么用。接 UE 时由开发根据你提供的模板整理，不把这项工作推给普通用户。

### C. 同一条记录两类资料都有

默认提供“取回原 UE 资产”，也可单独导出贴图。需要使用默认模板时明确选择，不能悄悄替换用户原材质。

## 8. 收集什么、存什么、怎么取出来

| 内容 | 收什么 | 存什么 | 取出来是什么 |
| --- | --- | --- | --- |
| 普通贴图 | 用户选中的原文件 | 原始字节、文件名、用途、使用通道、尺寸和校验信息 | 原文件，或交给 UE 插件导入并绑定你的默认模板 |
| UE 原件 | 材质、实例及必要依赖 | 完整原生文件、相对路径、主资产、引擎版本和依赖清单 | 上传时那套 UE 资产及其引用关系 |
| 材质资料 | 名称、说明、来源 | 唯一编号、分类、标签、收藏、集合和收集版本 | 继续显示在库里，也随材质包带走 |
| 展示资料 | 展示用贴图和固定设置 | 通道对应、透明方式、已知参数、球体缩略图及其生成版本 | 重开后仍能套球；不替代原件 |
| 默认 UE 模板 | 你提供的模板及依赖 | 模板编号、版本、适用 UE 和参数对应表 | 普通贴图通过插件生成可用材质实例 |

“文件在原电脑某个目录”不算收存成功。资料必须已经收进 Prism 自己管理的存储，再标为可取用。

同名材质靠唯一编号区分；一次修改后重新收集，可以存为同一条材质的新版本，也可以另存一条，不覆盖旧件。

第一轮沿用现有 `.prism` 工程和 SQLite 存取能力，材质记录、原文件、关联和展示缓存分开保存。图像附件、文件保存和校验优先复用已有能力；UE 原生包按文件记录，不把整库塞成一个巨大字段。

原件只因明确替换或删除而改变。重新分类、重新生成缩略图、更新软件，不重写原图和 UE 文件。导出材质包要带齐记录和原件，不能只导出预览图。

## 9. 分类、标签、搜索和删除怎么完整工作

- 文件夹支持多层、新建、改名、移动、拖动和恢复。一条材质有一个主要文件夹，可以进入多个集合。
- 标签复用 Prism 已有标签系统，支持添加、改名、合并、删除及批量操作。最下面“标签”入口能搜到材质，不能只找到画布图片。
- 搜索至少支持名称、标签、文件夹、资料类型、UE 版本、透明方式、是否缺件。SurfaceStudio 现成的收藏、最近、通道与排序继续使用。
- 数量来自真实材质记录；卡片数、文件夹数和搜索结果要一致，不混用画布图片数。
- 删除材质先进回收站，可恢复。删除文件夹时明确“把内容移到未分类”还是“连内容一起删除”。
- 恢复时保留原件、编号、分类和版本关系；永久删除在回收站执行，仍被其他版本引用的原件不误删。
- 在材质库按 Delete，只操作当前材质；Ctrl+S 保存当前工程全部有效修改，不误操作后台画布。

## 10. 开发顺序：每一步具体做什么

前面的入口和文件夹基础可以保留，第二步界面按下面重做。**文字条目和只有名称／说明的右栏，不算材质库页面完成。**

| 顺序 | 这一步开发什么 | 用户能看见什么 | 通过条件 |
| --- | --- | --- | --- |
| 0.核对现成项目 | 固定 SurfaceStudio 来源，拆清界面、扫描、存储和 Blender 连接；核对 Babylon、HyperVault 和现有 Prism 接口 | 暂不改用户操作 | 来源和复用范围清楚，不把下载成功当接入成功 |
| 1.入口 | 保留文档下的材质库，标签最后；接入工程切换 | 能进独立材质库 | 不跳文档，不串工程，不误操作画布 |
| 2.复用完整浏览界面 | 接 SurfaceStudio 的卡片网格、选中交互、详情结构、卡片大小和搜索；保留当前材质记录基础 | 中间卡片列表，右边预览区域、属性、版本、标签和贴图区域 | 界面与参考图同一类；点击确实切换同一条记录；明确缺资料状态，不能伪装成完整材质 |
| 3.先把原件收进库 | 接扫描、单套／批量导入、分组确认、贴图用途和打包通道；复制原文件，保存完整记录 | 用户能导入一套木头贴图并找到它 | 移走源目录后仍能查阅和原样导出；未完成时不显示已收存 |
| 4.贴图套球 | 接 Babylon 现成展示，完成全部八项效果；生成缩略图，右侧显示选中材质 | 不用 UE、不用现成球图，也能看到材质球 | 木头、金属、树叶、半透明、发光和 SSS 样例逐项通过；无实时调参滑条 |
| 5.分类标签与整理 | 复用 SurfaceStudio 整理功能，接 Prism 文件夹和标签；完成收藏、最近、集合、批量、搜索、删除恢复 | 材质能被完整分类和找回 | 标签入口能找到材质，计数正确；移动不复制原件；删除可恢复 |
| 6.Prism 存取验收 | 保存、退出、重开、普通贴图导出、完整材质包导入导出、离线运行 | 材质库独立可用 | 重开效果和分类一致，原图校验不变；另一工程导入资料齐全；再进入 UE 开发 |
| 7.接你提供的模板 | 登记默认 UE 材质、适用版本和参数名称；实现模板选择与对应表 | 详情能准确显示可使用的模板 | 不制作替代母材质；每种用途能找到正确模板，缺模板明确提示 |
| 8.UE 插件基础 | 基于 HyperVault 可用模块和 UE 现成工具，做连接、收集、接收和任务状态 | UE 能连接 Prism，显示清楚的操作入口 | 连接可重试、插件可正确启停；尚未完成的任务不报成功 |
| 9.先做“贴图去 UE” | 把库内贴图导入空白 UE 项目，绑定你的默认模板，创建实例 | 普通贴图变成 UE 可用材质 | 保存并重启 UE 后仍可用；三种透明与 SSS 等模板对应正确 |
| 10.再做“UE 收进来” | 找依赖、高级拷贝、查引用、传文件、收存确认、取得展示资料 | 用户把现成 UE 材质收进 Prism | 移走源工程后，库里仍有完整原件；有展示资料时自己套球，缺资料明确标记 |
| 11.原件放回 UE | 检查版本、依赖、重名，再原样还原已收集资产 | 拿回上传时的材质和依赖 | 在空白兼容工程中加载、保存和重启通过；不换母材质、不偷引源工程 |
| 12.异常、批量和发布 | 多选、重复收集、版本、取消、中断、磁盘不足、重名保护、安装包和来源说明 | 普通用户能稳定使用完整流程 | 失败可恢复，旧件不毁；离线使用，干净环境可运行 |

第 2 步先把正确的浏览界面接出来；完整第一期还必须做到第 6 步。不能把界面骨架称为全部功能完成。

第 9 步先做普通贴图到 UE，是因为它能先验证“你提供的模板怎么接贴图”。之后做完整原件收取和还原，定位问题更清楚。

## 12. 验收按真实用户操作走

### 场景一：只有本地贴图

导入木头的颜色、法线、粗糙度图 → 自动识别并确认 → 收进原件 → 中间出现球体卡片 → 点击右侧看球和贴图资料 → 分文件夹、加标签 → 关闭软件并移走源目录 → 重开仍能展示和导出 → 发送到 UE → 使用你提供的默认模板生成实例。

### 场景二：来自 UE 的完整材质

UE 选中实例 → 收集母材质、贴图和必要依赖 → 高级拷贝整理并交给 Prism → Prism 保管原件和展示资料 → 关闭并移走源项目 → 从 Prism 放到另一个兼容空项目 → 保存、重启后仍能用，原母材质没有被替换。

### 场景三：效果完整

分别用不透明木头、金属、裁切树叶、半透明表面、法线细节、自发光、皮肤／蜡的 SSS 资料测试。检查效果是否来自正确贴图和现成渲染设置，重开后是否一致，不靠一张外部球图蒙混。

### 场景四：整理与异常

同名材质能区分；标签改名和合并不漏材质；分类移动不复制文件；删除恢复内容齐全；版本不兼容或缺模板时说明原因；中途断开或磁盘满时不报告成功，不破坏已存旧版本。
