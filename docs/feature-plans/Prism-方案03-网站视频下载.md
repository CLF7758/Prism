# 方案 03：网站视频下载、入库与抽帧

日期：2026-10-15。状态：待实施。网站解析和下载直接使用 yt-dlp，不自写平台解析器。

## 1. 平台支持与实际承诺

第一批目标为 YouTube、哔哩哔哩、小红书、抖音。yt-dlp 当前官方站点清单包含相应提取器；**列入支持清单不保证每个链接随时能下载**，登录、地区、签名、防自动化和平台改版仍可能影响具体链接。[yt-dlp 官方站点清单](https://github.com/yt-dlp/yt-dlp/blob/master/supportedsites.md)。

无需用户填写收费 API Key。需要登录的内容由用户主动提供自己的有效登录状态。界面说明失败原因、可采取的动作和当前提取器版本；不把“正在解析”无限挂着，也不把平台不支持伪装成用户网络故障。

首期支持单视频及用户明确选择的分集/合集项目。小红书图文笔记、多图文案全采集不混进“视频下载”第一版；若 yt-dlp 对这类链接不支持，展示明确提示。后续可评审 [XHS-Downloader](https://github.com/JoeanAmier/XHS-Downloader) 专用适配，但不在第一版同时维护两套引擎。

## 2. 直接使用哪些开源程序

| 组件 | 职责 | 接入约束 |
|---|---|---|
| [yt-dlp](https://github.com/yt-dlp/yt-dlp) | 解析链接、列出清晰度、下载音视频和提取元信息 | 使用官方 API/CLI 协议，不解析人类可读终端进度文本 |
| [FFmpeg](https://github.com/FFmpeg/FFmpeg) / ffprobe | 合并视频和音轨、探测完整文件 | 选择并固定构建，校验哈希；记录所选构建 LGPL/GPL 等许可证 |
| yt-dlp 官方 EJS 组件与兼容 JS runtime | 满足现代 YouTube JS challenge 需求 | 按锁定 yt-dlp 版本的上游说明配套；优先评估其推荐的 Deno |
| Prism 现有视频/素材服务 | 画布视频导入、播放、抽帧及保存 | 原视频保留，下载缩略图不当原视频 |

Prism 已安装 PyAV 不代表机器上有 `ffmpeg.exe`、`ffprobe.exe`。需要显式检测并传入组件路径。JS runtime 同样需要清单和版本锁定，不允许“开发机碰巧装了所以能用”。[yt-dlp 依赖与用法](https://github.com/yt-dlp/yt-dlp#dependencies)。

优先用独立 Python helper 调用锁定 yt-dlp Python API，再通过 JSONL 输出结构化结果；也可使用官方 Windows EXE 的结构化参数模式。实施前二选一固定，不能同时维护两套行为不一致的下载流程。首选 helper 便于可靠接入 `progress_hooks`、后处理回调和可解释错误；抓取核心仍完全由 yt-dlp 执行。[官方嵌入示例](https://github.com/yt-dlp/yt-dlp#embedding-yt-dlp)。

## 3. 入口与界面

| 入口 | 名称 | 说明 |
|---|---|---|
| 画布工具栏“添加”菜单 | “网站视频…” | 默认目标为当前真实画布 |
| 主菜单“插入” | “网站视频…” | 同一个工作流，不复制界面代码 |
| 画布空白处右键→添加 | “网站视频…” | 记录鼠标所处画布位置作为导入锚点 |
| 任务按钮/通知区 | “下载任务 N” | 查看进度、取消、失败重试和完成后导入 |

输入窗口沿用 Prism 深色主题和二级窗口标题栏样式，中文按钮“解析链接”“开始下载”“取消”，不留下白色系统边框或英文 Close。

第一屏包含：多行链接输入（每行一个）、“解析链接”、保存位置、真实目标画布、下载后动作。自动识别粘贴文本中的 URL，可以粘贴抖音等平台的分享文字；保留解析后的原链接信息，但不把分享文案作为命令执行。

下载后动作三个单选：

1. **下载并加入画布**（默认）；
2. 下载到文件夹；
3. 下载后选择帧并加入画布。

“下载到文件夹”不改变工程。“加入画布”要持久化原视频；“选择帧”先完成下载，然后复用现有抽帧界面。

## 4. 完整用户流程

### A. 解析与选择

1. 用户粘贴一条或多条分享链接，点“解析链接”。只获取元信息，尚未创建工程素材。
2. 显示标题、平台、时长、封面、可用清晰度、是否需要登录、预计体积（未知时写“未知”）。
3. 默认选择可用的较高画质与兼容音轨，提供“原始最佳/兼容 MP4/仅音频”明确选项。兼容 MP4 若必须转码，要在开始前说明额外时间；不把改扩展名当转码。
4. 合集/播放列表要展开条目供用户选择；初次解析默认单条，不因一个链接自动下载上千视频。
5. 在聚合页启动时，目标画布用明确选择器；不能将结果塞入临时“全部素材”场景。

### B. 下载与后台任务

1. 点“开始下载”进入非阻塞任务面板。画布可继续平移、选择、保存。
2. 任务状态依次为：排队→解析→下载视频/音频→合并→校验→等待导入/导入→完成。
3. 分别显示当前条目、总条目、已下载字节、速度和剩余时间；平台不给长度则用不确定进度，不能虚构百分比。
4. 用户取消任务时终止自己的下载子进程及合并子进程，释放文件句柄；保留可恢复分片由用户选择继续或清理。取消不会删除此前成功导入的其他批次。
5. 任务失败可以单条重试，已完成条目不重复下载和导入。断网重试采用有限次数与退避，不无限重试占 CPU。

### C. 加入画布与视频帧

1. 仅在视频音轨合并及完整性校验通过后导入；`.part` 文件不能显示为成功素材。
2. 用 `AssetImportService` 分类并走现有媒体导入流程，把原视频保留到工程管理的存储；记录来源页面 URL、平台、标题、视频 ID、格式和提取器版本。短效媒体 CDN URL 不作为永久来源。
3. 视频放在约定锚点。批量导入只排列新视频卡片，不移动用户原有图片，也不排列画笔、文字或箭头。
4. 如用户选择提取帧，复用 `fileio/video_service.py`、`video_frames.py` 和现有抽帧界面，允许时间点、时间范围和间隔选择；开始前显示预计张数。
5. 抽取的每帧 PNG 原字节持久化，再调用现有最优排列，对本批新帧执行一次布局；原视频保持不变。保留帧时间戳与视频来源，方便回查。
6. 查询任务期间切换工程，下载可继续，导入进入待处理状态；用户选回正确目标后再写入。不能使用全局“当前画布”指针吞掉来源工程约束。

## 5. 技术接法（计划）

```text
工具栏/插入菜单/空白右键
      ↓
actions/web_video_workflow.py（表单与目标画布）
      ↓
video_download_service.py（队列、子进程、取消、进度）
      ↓
独立 helper → yt-dlp API → FFmpeg / JS runtime
      ↓ 文件与结构化结果
现有媒体导入 → source_store → 视频卡片/抽帧
```

新增文件仅包装上游。平台提取器、签名算法、媒体合并不在 Prism 重新实现。由下载 service 负责上游版本及组件定位；工作流不直接调 shell。

### 进程参数与协议

- 使用参数数组或 JSON stdin 传任务，不拼接 shell 命令；Windows 子进程隐藏控制台。
- helper stdin 请求示例字段：`protocol_version, job_id, command, source_url, format_id, output_directory, credential_reference, request_generation`。支持 `inspect / download / cancel`。
- helper stdout 只输出 JSONL：`ready / metadata / progress / postprocess / completed / failed / cancelled`。第三方普通日志去独立限额 stderr，不混进协议。
- progress 至多 5 Hz，Prism 仅更新这一行任务。清晰度和视频选择使用 yt-dlp 结构化元信息，不在字符串里猜。
- yt-dlp 的下载完成回调不等于整个任务完成：FFmpeg 后处理成功、最终路径确认并校验后，才能发 completed。
- 每个 job 的工作目录独立，结果路径必须落在其授权工作目录或明确输出目录。标题进行 Windows 文件名清理，内部使用唯一 ID 避免同名覆盖。

### 并发和资源预算

首期同时下载最多 2 个、合并/转码最多 1 个；解析队列最多 20 个等待任务，更多链接以分页批次接收。任务面板只渲染可见行，显示 20 条近期完成任务，详细历史有数量上限。

整段视频不读入内存；磁盘流式写入。抽帧沿用有限解码队列与主线程分批安装，禁止几千帧一次触发 scene 全量刷新。网速不设本机不可能保证的固定指标；检测 UI 进度响应、取消响应和内存增长。

## 6. 登录、Cookie 与可解释错误

默认先尝试无需登录的公开链接。网站要求登录时，任务显示“需要登录状态”，用户主动选择导入 Cookie 文件，或明确选择从某个浏览器/配置读取；不在后台遍历所有浏览器私密资料。

Cookie 只供本次下载组件访问，不能写进日志、崩溃栈附件或进程可见命令参数；如需落盘，使用用户专属临时目录、限权限并在结束后清理。长期凭据保存要使用系统凭据存储，首期可以只支持本次会话，不强行保存。

| 错误 | 提示及操作 |
|---|---|
| 不支持的链接 | “当前下载器不支持该链接”，可复制诊断，不无限重试 |
| 登录失效 | “登录状态已失效”，更新 Cookie 后仅重试该条 |
| 平台验证/签名失败 | 显示平台及提取器版本，提供检查组件更新；不承诺一定绕过验证 |
| 地区/权限限制 | 准确说明当前账号或地区不可访问 |
| 缺 FFmpeg / JS runtime | 给出缺失组件名称和安装入口，不显示泛化“下载失败” |
| 磁盘不足/不可写 | 明确路径与所需空间信息，保留可恢复分片，不误标完成 |
| 合并失败 | 下载文件可恢复，单独重试后处理，不强制重下一遍 |
| 目标画布不存在 | 下载完成并保留，等待用户选择导入目标 |

## 7. 缓存、保存与更新

下载的原视频是素材，不是随意清理的显示缓存。进入工程存储并确认保存后，才能清理任务副本。导入后移动外部下载目录，重开工程仍须能播放、抽帧和导出原视频。

解析元信息缓存设期限；进度、分片及任务清单按 job 管理。退出程序提示正在运行任务的去向，默认暂停可恢复下载，不强杀用户其他 yt-dlp/FFmpeg 进程。

yt-dlp、FFmpeg、EJS/runtime 版本一起写进组件清单。平台改版时只升级下载组件，验证样例后原子切换；失败可回滚，不需要为每次网站变化重打整个 Prism。更新从明确可信发布源取得、校验哈希并保留许可证，不执行网页提供的未知脚本。

## 8. 实施与验收

| 阶段 | 交付 | 通过条件 |
|---|---|---|
| D1 上游组件 | 固定 yt-dlp、FFmpeg、JS runtime 的独立运行包 | 无开发环境机器解析和下载一条 YouTube 样例 |
| D2 协议适配 | 元信息、进度、后处理、错误、取消 | 用户取消后子进程退出，最终完成状态与文件一致 |
| D3 四平台验证 | YouTube、B站、小红书视频、抖音视频 | 各至少 2 条当前可公开/授权访问的链接，记录时间、是否登录和结果 |
| D4 Prism 工作流 | 三处入口、任务面板、正确画布、原视频持久化 | 关工程重开视频可用，目标高亮和撤销正确 |
| D5 抽帧和稳定性 | 现有抽帧、最优排列、资源和异常回归 | 只排新图片，不排笔刷；期间画布操作和保存正常 |

额外验收：中文/emoji 标题、分享短链接、不同清晰度、视频音轨分离、合集单条选择、取消后继续、断网恢复、磁盘不足、重复 URL、同标题不同视频、工程切换、重复完成回包、原视频导出哈希、组件缺失、登录失效、FFmpeg 崩溃。

日志事件为 `download.inspect / metadata / transfer / merge / verify / import / extract_frames / cancel`。每一阶段记录 job_id、上游版本、耗时和失败类型；不记录原始 Cookie、用户分享全文、鉴权查询参数。下载总耗时与主线程卡顿是两套指标，不能把下载 60 秒直接记成界面卡住 60 秒。
