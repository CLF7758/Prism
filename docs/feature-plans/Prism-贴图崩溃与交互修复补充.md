# Prism 贴图崩溃与交互修复补充记录

## 最新崩溃
日志中的调用链是 selection.py:itemChange → items.py:on_selected_change → ReferenceScene.has_selection 不存在。前一次 cursor_cleared 异常与本次属于同一接入缺陷：主画布图元进入了不完整的独立场景。

已把贴图场景改为继承完整的 PrismGraphicsScene，共享选择计数、单选/多选、组合选择框、光标、层级和撤销接口；鼠标手势仍局限在贴图窗口，不触碰主工程。贴图视图提供图元所需的缩放和变换接口。没有继续逐个伪造 has_selection 等方法。

## 当前贴图交互
- 复用 CanvasToolbar，只保留用户红框中的选择、笔刷、橡皮、直线、箭头、文字、颜色、线宽和线型。
- 删除工具条中的适应全部、中心与右侧留白，工具条高度36，按钮尺寸仍与主画布共用。
- 移动/缩放图片窗口时工具条跟随，靠近屏幕边缘时限制在可见范围。
- 同时只允许一张贴图显示标注条；切换到其他图片或应用会隐藏并回到选择模式。
- 笔刷线宽调用主画布相同的屏幕像素换算，避免缩放导致粗细不一致。

## 截图延迟
普通手动框选跳过 ScreenPinKit 的 OpenCV 自动窗口识别，减少一次全屏抓取与轮廓扫描；启动后后台预热助手，助手随主进程关闭。聚合素材视图不再先弹画布选择器，只有用户确认“送入画布”后再选目标。
本机原生Windows实测：助手冷启动1265ms，助手就绪后首次框选328ms、第二次172ms。统计事件 capture.overlay_ready 已写入诊断逻辑。

## 以图搜图
保留 OpenCLIP/FAISS 做内容候选，在前600候选上用 OpenCV Lab颜色分布与8×8明暗布局重排，再返回前200。权重为内容0.55、主色0.30、布局0.15，属于应用层排序策略，不是新的模型或画风分类器，仍不保证完全同一画风。
搜索结果画布改为保持排名的逐行排列，避免紧凑装箱按尺寸把低排名结果摆到前面。
已用用户2451原图和2,742张图库副本验证，原图仍排第一；冷青灰、雾气相近的图被提升。新增外观缓存后第二次查询约0.594秒；已有CLIP缓存情况下首次计算外观并加载模型总共约18.6秒。新的排序标识 clip+opencv-lab-v2。
