# UE 收取：历史方案参考，不作为当前实施要求

最新整体方案见 [Prism材质展示库与UE收取](Prism-整体开发方案-材质展示库与UE收取.md)。用户已经明确：真实UE母材质由用户提供，Prism仅做展示、保存和分类。本文旧的AssetPort母材质生成、自动创建UE材质等要求全部作废；这里只保留历史讨论，不能据此增加下载依赖或开发任务。

本文保留上一版 UE 收取流程供后续参考。当前先按 [Prism 第一期方案](Prism-工作库与材质管理-完整改造方案.md) 完成材质球库；第一期全部材质能力使用 Babylon.js 现成实现验证，本文的 Three.js 选型、阶段顺序和下载要求不再作为第一期要求。

版本：2.0　更新：2026-10-19

**这次方案始终只围绕三件事：收集什么、存什么、怎么取出来。**

用户已经确认：不透明、透明裁切、半透明三种都必须支持；材质必须像画布一样支持文件夹、子文件夹和标签；UE 插件需要开源。以下全部是开发要求，不能把计划写成已经完成。

这份文件替代上一版主方案。上一版关于大库、自动保存、更新包的详细技术内容保留在 [存储与离线更新技术附录](Prism-存储与离线更新-技术附录.md)。有范围或顺序冲突时，以这份新版方案为准。

## 1. 先把最终效果说清楚

用户在 UE 中选中一个“木头”材质，点击“收集到 Prism”。插件把这套材质需要的文件整理好，放到项目的 `Content/PrismM/` 里面，再交给 Prism 保存。

以后用户打开 Prism，在“材质 → 木材 → 地板”里面找到它，可以：

- 只把贴图拿出来，交给其他软件使用。
- 把整套 UE 材质放进另一个兼容的 UE 项目。
- 把本地收集的贴图套进 Prism 的默认材质球，查看效果，再让插件生成基础 UE 材质。

用户不用理解软件内部怎么编号、怎么去重。界面只需要让他知道“这里有一套木头材质，哪些文件已经保存好，能拿出来做什么”。

Prism 主要负责收纳、分类、预览和保存；UE 插件负责整理、检查和把内容放进 UE 项目。首版不把 Prism 做成完整的 UE 材质节点编辑器。

## 2. 到底收哪两种东西

### 第一种：只有贴图

例如用户在本地有一套木头贴图：颜色、法线、粗糙度、金属度等，没有 UE 材质文件。

收集：这套贴图，以及用户给它选的材质类型和参数。

保存：每一张原始贴图、名称、标签、所属文件夹、贴图分别负责什么、预览参数和预览图。

取出：可以原样导出贴图；也可以让 UE 插件用默认母材质生成一颗可用的材质实例。

“母材质”就是提前做好的一套接线模板。用户给它放上贴图、调整参数，就能生成自己要用的材质。

### 第二种：UE 材质球和它需要的文件

例如 `MI_Wood` 使用了父材质 `M_Wood`，父材质又使用了几个材质函数和纹理。

收集：选中的材质或材质实例，以及它真正需要的父材质、贴图、函数等文件。

保存：整理后的 UE 文件、原始路径和整理后路径的对应关系、UE 版本、需要的外部插件、预览图；能单独取得的贴图也可另外保存。

取出：通过插件，把这套内容还原到兼容的 UE 项目。用户要的只是贴图时，也能单独导出已经取得的贴图。

### 同一条材质可以同时有两种内容

“木头”可以既保存完整 UE 材质，又保存一套普通贴图。Prism 里仍然只显示一张材质卡，不需要分成两个毫无关系的素材。

卡片上明确显示：

| 显示状态 | 含义 |
|---|---|
| 贴图已保存 | 可以单独导出普通图片文件 |
| UE 材质已保存 | 可以通过插件尝试放入兼容项目 |
| 两者都有 | 两条取用方式都可选 |
| 资料不完整 | 缺什么就显示什么，不能伪装成完整收集成功 |

## 3. 三种默认材质全部必做

这三种不是以后再考虑的选项。Prism 预览、参数保存、贴图导出和 UE 默认材质生成，都必须有对应的处理。

| 类型 | 大白话解释 | 典型用途 | 必须可调的内容 |
|---|---|---|---|
| 不透明 | 看不到背后的东西 | 木头、墙、金属 | 颜色、法线强度、粗糙度、金属度、贴图大小 |
| 透明裁切 | 按图上的黑白区域挖洞；一个地方要么显示，要么不显示 | 树叶、铁丝网、破布 | 上述参数、挖洞用哪张图/哪个通道、裁切门槛、是否显示背面 |
| 半透明 | 能看到后面的东西，还能调看得有多清楚 | 薄纱、薄膜、简单透明表面 | 颜色、法线、粗糙度、透明程度、透明图来源、是否显示背面 |

### 3.1 不透明要做到什么

颜色图片即使自带透明通道，只要用户选了“不透明”，也不能悄悄把材质变成透明。

没有金属度图时，默认按非金属显示；没有法线图时，按平面表面显示；缺少非必需贴图不妨碍保存，但界面要显示“未设置”。

### 3.2 透明裁切要做到什么

用户可以选择“使用颜色图里的透明通道”，也可以选择“使用另一张黑白图”。如果用了另一张图，还可以选红、绿、蓝或透明通道。

首版统一使用 0.5 作为默认裁切门槛，并允许用户修改。Prism 和生成出来的 UE 材质必须使用同一个值，不要一个看着完整、另一个被裁掉一半。

用树叶样例检查叶片轮廓；用铁丝网样例检查网眼；能调背面是否可见。不能只放一个带透明背景的球截图就算支持了透明裁切。

### 3.3 半透明要做到什么

用户可以调整整体透明程度，也可以指定透明图。预览背景可以切成棋盘格，并提供有前后层次的测试场景，让用户看清楚透明效果。

基本半透明显示和保存必须完成。真实玻璃的厚度、复杂折射和特殊光照属于增强能力，不能用“以后再研究玻璃”拖延基本半透明功能。

半透明经常会遇到前后遮挡和排序问题，要用薄纱、两层交叉平面等样例检查。不能简单把“不透明”改一个开关后就宣称所有半透明效果都正确。

### 3.4 两端的默认材质要对应

| 用户选的类型 | Prism 内部预览 | 插件生成到 UE 的基础模板 |
|---|---|---|
| 不透明 | 不透明预览模板 | `M_Prism_Opaque` |
| 透明裁切 | 按门槛裁切的预览模板 | `M_Prism_Masked` |
| 半透明 | 支持透明混合的预览模板 | `M_Prism_Translucent` |

这些名字是我们计划使用的名字。它们不是说 Three.js 能直接读取 UE 的 `.uasset`，而是两边各有一套模板，按同一份贴图和参数工作。

用户收集来的复杂 UE 材质保持原样，不强行换成这三种基础模板。三种默认模板主要服务于“手里只有贴图”的情况。

## 4. UE 里点“收集”，具体会发生什么

下面用“木头”举例。

1. 用户在 UE 内容浏览器里选中一个或多个材质，也支持材质实例。
2. 右键点击“收集到 Prism”。首版以内容浏览器选中项为准，从场景物体反查材质可后加。
3. 插件显示一个小窗口：材质名、收集方式、预计文件数、预计大小、有没有缺的东西。
4. 收集方式有“只要贴图”“完整 UE 材质”“完整材质并提取贴图”。默认完整收集，用户可以记住上次选择。
5. 插件检查材质是否保存、哪些文件有未保存修改。只处理本次需要的文件，不顺便保存整个项目。
6. 用 UE 的高级拷贝把需要的项目资产整理到 `Content/PrismM/` 的独立文件夹。
7. 对整理后的材质重新检查：有没有还指向原项目其他目录的必需文件；材质能否加载和编译；贴图有没有丢。
8. 生成用于 Prism 展示的预览图，列出实际保存的文件和需要的外部条件。
9. 把这些内容发送给 Prism。
10. Prism 校验、写入磁盘，保存成功后返回确认。UE 这时才提示“已收集到 Prism”。

Prism 没启动时，插件可以提示打开 Prism，也可以先生成一个待接收文件。不能因为收件软件没开就丢掉刚整理好的内容。

用户一次选中 10 个材质时，按 10 条记录显示进度和结果，失败哪条就指出哪条。两个材质共用一张贴图时，整理结果可以分别引用，Prism 保存时按真实文件内容去重。

## 5. `Content/PrismM/MuTou` 怎么整理才不会出问题

### 5.1 显示中文名，内部加一个不会撞的编号

推荐路径：

```text
Content/
  PrismM/
    MuTou_a83f29/
      R0001/
        Materials/
        Textures/
        Functions/
        Other/
```

`MuTou` 方便人看，`a83f29` 用来区分两套都叫木头的材质；`R0001` 表示第一次收集的版本。

用户再收集修改后的同一材质，可以更新这条记录并形成 `R0002`。原版本不被直接盖掉。用户只是在 Prism 把“木头”改名成“旧木头”，不需要连带移动 UE 内部文件。

拼音生成只为文件名友好服务。拼音失败或重名时用安全英文名加编号，不因此阻止收集。

### 5.2 不能把所有文件随便堆在一层

原来不同目录里可能各有一张 `T_Normal`。整理时必须分别命名或保留必要的子目录，并让材质引用指向正确的新文件。

这件事要交给 UE 高级拷贝及其路径检查来做，不能只用 Windows 的复制粘贴。

### 5.3 “所有东西”具体包括什么

| 遇到的东西 | 怎么处理 |
|---|---|
| 项目里的父材质、材质函数、贴图、参数集合等 | 本次需要且允许复制的，整理进收集目录 |
| 材质实例的父实例 | 沿着父级继续找，不能只收最外面一个文件 |
| 引擎自带的东西 | 记录“需要引擎提供”，不把整个 Engine 目录搬过来 |
| 第三方内容插件里的资产 | 先判断能否复制；能复制的经 UE 整理，不能独立带走的列成外部要求 |
| 插件提供的 C++ 节点或着色代码 | 普通材质文件带不走这段能力，记录插件要求并在取出时检查 |
| 运行时才通过字符串加载的资源 | 自动收集未必知道；提供“补充依赖”入口，不能承诺盲目全找到 |
| 贴图或资产旁边的配套数据文件 | 一起核对并带走，不能只按 `.uasset` 后缀选文件 |
| 虚拟化后放在其他地方的大数据 | 先通过 UE 取回完整数据；取不全就明确失败或不完整 |

高级拷贝完成不等于检查完成。必须检查新的材质仍然能正常用，才能进入发送环节。

### 5.4 不改变原材质

收集建立的是副本，原材质和场景中已经使用它的物体保持原来的引用。清理收集目录也只能清理插件创建、已确认可清理的内容，不能顺手删掉原素材。

收集成功后可以提供“保留整理副本”“检查后清理副本”。默认先保留，等用户确定工作流可靠再自行清理。生成的版本已经被场景或别的资产使用时，不允许自动删除。

## 6. Prism 到底保存哪些东西

每一条材质至少保存下面这些内容。

| 内容 | 用来干什么 |
|---|---|
| 名称、说明、文件夹、标签 | 找得到、分得清 |
| 这条材质的唯一编号 | 改名或移动文件夹后仍知道是同一条材质 |
| 原始贴图及各自用途 | 原样导出，正确预览，生成 UE 基础材质 |
| 不透明/透明裁切/半透明的选择和参数 | 重开软件后效果不变 |
| 完整 UE 文件包（如果有） | 以后把原生材质放回 UE |
| 包里哪些文件对应哪些 UE 路径 | 还原时不丢引用 |
| UE 版本和外部插件要求 | 提前判断目标项目能不能用 |
| 预览图、可选的预览模型信息 | 在 Prism 里快速浏览 |
| 来源与许可信息 | 知道从哪里来，分享时保留来源 |
| 每次修改/收集的版本 | 用错或改坏后能找回以前的版本 |
| 每个文件的大小和内容校验值 | 发现传输损坏、避免重复存完全相同的文件 |

“内容校验值”可以理解为文件的指纹。名称一样但内容不同，不是同一份；名称不一样但内容完全相同，可以共用底层存储。

### 6.1 一份工作库里统一存

继续采用 Prism 管理的工作库文件夹，用户只打开一个库。内部可以分开存索引、原文件和预览缓存，用户不需要手工整理内部文件。

```text
场景设计.prismlib/
  library.json      这是什么库
  index.sqlite      名称、分类、参数、版本和文件对应关系
  objects/          真正收进来的原始文件
  staging/          还没收完的临时内容
  cache/            可重新生成的预览图等
  backups/          恢复需要的记录
```

材质分类文件夹是 Prism 内部的分类，不要求用户去移动 objects 里的文件。拖动“木材”分类不应该复制几十 GB 贴图。

### 6.2 不能只记 UE 项目里的路径

如果只记 `D:/某项目/Content/...`，用户删掉原项目后材质就丢了，这不叫收集完成。

Prism 必须已经拥有独立可读取的内容。验收时需要关闭 UE、移走原项目，再确认 Prism 还能展示、导出和重新发送。

### 6.3 UE 原生文件和普通贴图要分清

UE 的纹理资产文件并不等于用户最初那张 PNG 或 EXR。

原图还在时，可以按用户选择保留原文件；原图不在时，插件可尝试通过 UE 导出可用图片，但必须标明“由 UE 导出”，不能宣传恢复了已经丢失的原图。

“取出材质引用的贴图”和“把复杂材质的最终效果烘焙成一套贴图”是两件事。首版完成前者；不能把一个复杂程序化材质简单提取几张纹理，就说和原材质效果完全相同。

## 7. 分类必须像画布一样好用

### 7.1 材质有自己的分类入口

左侧增加“材质”，使用当前画布/文档/脑图相同的文件夹交互：新建、改名、拖动、移动、删除、恢复。

```text
材质
  木材
    地板
    家具
  金属
  植物
  布料
```

不是只提供一页搜索结果，也不是让用户靠文件名分类。

### 7.2 文件夹和标签一起支持

一套木地板可以放在“木材/地板”，同时打上“旧化、暖色、室内、4K、UE材质”等标签。

首版一条材质只有一个主要分类位置，但可以有很多标签。放到多个画布只是多处引用，不会复制全部文件。“复制材质”则是一条独立记录，需要在菜单上说清楚。

标签沿用 Prism 现有的标签管理和搜索，不另做一套互不认识的材质标签。支持批量添加/删除标签、按类型筛选、按是否有 UE 文件筛选、按是否缺文件筛选。

### 7.3 删除分类时不能把内容悄悄删光

删除文件夹时给出“连内容放进回收站”或“内容移到未分类”。删除一条材质不删除已放进 UE 项目的资产。删除画布上的材质卡也只删这次引用，不默认删除库中的材质。

分类改名、标签修改、移动和删除都要能撤销，并且要保存到工作库。

## 8. Prism 界面上用户怎么操作

中间仍是 Prism 的素材浏览方式。材质卡显示球预览、名称、材质类型、贴图数量、分辨率、有没有 UE 材质和有没有缺文件。

单击卡片，右侧显示详情；双击打开大预览。右侧最先放用户需要的操作：

- 查看贴图。
- 导出贴图。
- 发送到 UE。
- 修改基础预览参数。
- 查看版本。

预览模型至少有球体、平面、立方体。材质拖进 Prism 画布时，生成引用这条材质的卡片；卡片可以回到材质详情。

### 8.1 参数能改到什么程度

只有贴图的基础材质可以修改颜色、粗糙度、法线、透明方式等常用参数，修改后自动保存。

完整 UE 原生材质在 Prism 首版主要用于查看、分类和取用。不能在 Prism 改一个粗糙度滑条，就假装已经修改了任意复杂的 UE 材质图。

如需修改原生材质，先发送到 UE，用户在 UE 编辑，再收集成新版本。Prism 可以保存辅助预览参数，但要明确它不改变原生材质文件。

### 8.2 预览图从哪里来

贴图材质用 Prism 的默认模板实时预览。

原生 UE 材质由插件在 UE 里生成预览图。若同时收到了可组成基础材质的贴图，Prism 可以另外提供“贴图预览”，但要和“UE 原效果图”分开标注。

显卡不支持实时预览时，仍然能看静态预览、改标签、导出和保存。不能因为球画不出来就打不开整个库。

## 9. 用户只想拿贴图，怎么取

1. 用户选择一条或多条材质，点击“导出贴图”。
2. Prism 展示现有贴图及用途；哪些是原文件，哪些是由 UE 导出的，写清楚。
3. 默认原样导出，不改变分辨率、位深、文件格式和颜色数据。
4. 可以选择“同时导出说明文件”，记录每张图用在哪个位置、法线方向和透明图来源。
5. 如果用户主动选择“拆分 ORM”“法线方向转换”“转成 PNG”，这些属于另外生成的文件，不能覆盖库里的原图。
6. 目标位置同名时，选择换名、跳过或明确覆盖，不能默默替换。

只有 UE 原生包、没有普通图片时，界面提示“当前只保存了 UE 纹理资产，需要通过插件提取”。不能把 `.uasset` 改成 `.png` 后缀交给用户。

## 10. 用户要把完整材质放进 UE，怎么取

### 10.1 有完整 UE 材质包的情况

1. 用户在 Prism 点击“发送到 UE”，选择当前打开的项目。
2. 插件检查 UE 版本、需要的插件、目标路径、同名或已导入内容。
3. 默认恢复到包里记录的独立位置，例如 `Content/PrismM/MuTou_a83f29/R0001/`。
4. 包里的路径和文件校验通过后，插件导入或恢复这套内容，让 UE 重新发现资产并加载根材质。
5. 检查引用、材质编译和文件保存结果，定位到导入的材质。用户重启编辑器后仍可使用，才算完整成功。
6. 首版不自动给场景里全部物体换材质；可以另提供明确的“应用到选中物体”。

首次还原到不存在的独立路径，可以在校验后复制文件并让 UE 扫描。更新已加载或有未保存修改的资产时，不允许直接用磁盘文件覆盖；要检查、提示，并走受控更新或另存新版本。

### 10.2 只有贴图的情况

1. 用户选择发送到 UE。
2. 插件读取贴图用途、材质类型和参数。
3. 导入贴图，设置颜色图、法线图和数据图各自的正确读取方式。
4. 按用户选择使用不透明、透明裁切或半透明默认母材质，创建一个材质实例。
5. 连接贴图和参数，编译、保存，再定位到结果。

这条流程可以优先改造 AssetPort 的相关代码，但不带入不需要的骨骼、动画、重定向和模型批量处理功能。

### 10.3 用户想换一个 UE 文件夹

首版优先保留整理好的路径，降低丢引用风险。用户想移动时，通过 UE 的资产移动/高级拷贝重新处理路径，不能只改文件夹名字。

同一材质不同版本使用不同的整理路径，避免在另一个项目里遇到同路径、不同内容。重复发送相同版本时应识别已存在内容，不每次生成十套副本。

### 10.4 UE 版本怎么处理

记录收集时的完整 UE 版本，并检查外部插件和项目需要的材质功能。不能承诺新版 UE 保存的原生材质一定能回到旧版。

本机现有 UE5.7.4 与 UE5.3.2。实施时先在 5.7.4 跑通，再单独验证 5.3.2。插件按各引擎版本分别编译，不能把一份 DLL 发给所有版本。

只有贴图的基础材质可以由目标版本插件重新生成，但具体母材质、参数和编译仍要在该版本测试。

## 12. UE 插件具体分成哪几块

插件暂定名 `PrismBridge`，独立工程开发并开源。自己的新增代码按 MIT 方案管理，复用的 MIT 部分保留原版权和许可证。Prism 主程序仍遵守原有许可，插件通过约定的消息和文件通信，不把 Prism 主程序代码随意复制进插件。

只做编辑器插件，不把收集工具打进用户发布的游戏。

| 部分 | 大白话职责 |
|---|---|
| 收集入口 | 右键菜单、收集窗口、批量进度 |
| 文件整理 | 找依赖、调用高级拷贝、给出缺件清单 |
| 预览生成 | 为原生材质拍球体/平面预览 |
| 发送与接收 | 和 Prism 建立本机连接，传输任务结果与文件 |
| 放入项目 | 检查版本与重名，还原原生包或从贴图建基础材质 |
| 三种模板 | 管理不透明、透明裁切、半透明母材质及参数 |
| 结果记录 | 记住这个项目已经收过哪套材质、哪个版本 |

首版的通信只在同一台电脑上进行。大文件走受控的本机临时交接目录，消息只传任务编号、清单和进度，不把几十 GB 文件塞进一条网络消息。

Prism 和插件各有明确的任务状态：等待、整理、传输、保存、完成、失败。相同任务重试时识别已保存的结果，不重复生成材质。

连接只监听本机，并验证本次连接凭据。插件不能接受任意网页发来一个本地路径，就去覆盖用户的项目。跨电脑先通过 Prism 完整库/更新包传递，不让 UE 插件直接承担一套云同步服务。

## 14. 什么时间保存，什么时候才算成功

### 14.1 用户正常编辑时

| 用户做了什么 | 新方案什么时候保存 |
|---|---|
| 改材质名称、标签、分类 | 操作后约半秒合并保存 |
| 调粗糙度或透明程度 | 拖动时先预览，松手后约半秒保存；一直拖也要周期性留恢复点 |
| 替换贴图 | 新文件完整收进库后，再正式切换这条材质使用的贴图 |
| 接收 UE 材质 | 全部必需文件校验并写好后，才显示完整收集成功 |
| 文档、脑图输入 | 停顿约 0.8 秒保存；持续输入最长约 5 秒留一次有效内容 |
| 拖动画布上的材质卡 | 松手后合并保存，不每移动一个像素就写一次 |
| Ctrl+S | 等待当前修改真正保存好 |
| 关闭软件 | 尝试保存未完成修改；失败时提示原因与恢复位置 |

以上时间是新方案的目标，实际慢机器需要测试。当前 Prism 默认 5 分钟自动保存，未命名恢复也没有覆盖完整材质库，因此需要改造，不能说现在就已经满足。

### 14.2 保存时继续编辑怎么办

举例：软件正在保存粗糙度 0.5，用户又调成 0.8。0.5 保存完成不能让界面假装 0.8 也保存了，后一个修改仍然要继续保存。

界面只显示几种真实状态：“有未保存更改”“正在保存”“已保存”“保存失败”。“已保存”和“已传给另一台电脑”分开显示。

### 14.3 未命名项目也要能恢复

用户还没给库起名字时，软件先把内容存进自己的草稿工作库。不能把新导入的贴图只放在进程临时目录里，软件一关就没了。

首次保存时再把草稿搬到用户选的位置。软件异常退出后，下次启动能看到“恢复未命名工作”。

### 14.4 后台要做什么

复制大文件、校验、生成球预览、建搜索索引、导出包都在后台任务中执行。用户能看到进度、取消、重试和失败原因。保存当前编辑优先，生成所有缩略图不能挡住 Ctrl+S。

任务本身也要记录到磁盘。收一半断电，重开后知道哪份没收完；已经收好的部分不要白传，但未收完不能进入“完整可用”列表。

## 15. 100 GB 库怎么带走，以后怎么只传更新

这部分保留之前讨论的目标，但不压过材质收取这个主线。

第一次：导出完整库，另一台电脑导入一次。

以后：点击“发送更新”，只带上变化的分类、标签、文档、材质参数、新版本和新增文件。另一台电脑双击更新包，软件找到同一工作库，应用进去，不再让用户选择一次大包加一次小包。

只改粗糙度或标签，不重传老贴图；新加 2 GB 贴图，更新包就仍然需要带这 2 GB 的有效新增内容，不能保证永远只有几 MB。

软件必须处理：重复收同一个包、先收到后面的包、漏掉上一个包、两边都修改同一条材质、一边删掉另一边修改。默认保留冲突版本，让用户选择，不按电脑时间简单覆盖。

后台记录变化，用户需要时才生成更新包。不能在软件每保存一下时，就在桌面扔一个新小文件。

完整库、更新包和“只分享选中材质”是不同操作。选中材质分享给另一个库时，需要把它用到的贴图一起带上，不能只发一张材质卡和失效路径。

## 16. 这些问题现在就要想好

| 问题 | 必须怎么处理 |
|---|---|
| 两个材质都叫木头 | 显示名可同名，内部编号不同，收集路径不撞车 |
| 两边共用同一个父材质 | 不能漏收；库里可去重，取出时仍要保证引用能找到 |
| 本机没有需要的插件 | 导入前说明缺哪个插件，不把材质导进去后才让用户发现变黑 |
| UE 材质还没保存 | 先明确处理本次相关修改，再收集磁盘上真实存在的版本 |
| Prism 没开或连接中断 | 待交接内容可重试，不直接丢弃，不误报完成 |
| 文件传坏或磁盘满 | 本次失败，不把旧的完整材质覆盖掉 |
| 预览图生成失败 | 可以保留已经存好的资料，显示“预览待生成”；不把预览失败当作所有原文件丢失 |
| 用户同时要求完整材质和贴图，但贴图只导出一半 | 分别显示两部分状态，不把两者都标成成功；可单独补做提取 |
| 新旧 UE 版本不兼容 | 拒绝不可靠的原生导入；可以提供已保存的贴图作为另一条取用方式 |
| 同一版本反复发送 | 识别已存在结果，不反复创建新副本 |
| 目标资产有本地修改 | 保留本地版/另存新版/明确更新，不能无声覆盖 |
| 收集的材质带特殊程序化效果 | 原生包保留；普通贴图预览只能标“基础近似”，不能说完全还原 |
| 原图没有了 | 标明由 UE 导出，不能编造原图已恢复 |
| 删除 Prism 材质 | 进回收站，不自动删除 UE 项目里的文件 |
| 清理缓存 | 只能清掉可重建预览，不把原始贴图一起删掉 |
| 移动工作库、换盘符 | 库内部引用仍可用，找不到库时让用户定位一次 |
| 打开未知来源的交接包 | 检查文件路径和体积，不能写到库或项目之外，更不能执行包里的脚本 |

对“缺外部依赖”的材质，允许用户选择暂存为资料不完整的条目，但默认的完整收集按钮不能跳过错误并宣布成功。引擎本身应提供的依赖可列为正常外部条件，不强行复制整个引擎。

## 17. 开发先做什么，后做什么

不要先做一个漂亮球体，再发现文件没有真正存进库。也不要先做完整云同步，迟迟不能收一套木头材质。

### 第一步：统一一条材质记录要保存什么

先定名称、编号、分类、标签、三种模式、贴图用途、原生包、预览、版本和外部要求。把插件和 Prism 要交接的清单格式定好。

完成标准：用一套手工样例描述“木头”，两边读到的含义一致。三种模式和透明来源不能各猜一套。

### 第二步：Prism 能把贴图真正存住、分好类

接入最小可靠工作库、材质记录、分类、标签、导入和原样导出。把文件从原路径收进自己的存储，增加保存成功/失败状态。

完成标准：导入木头贴图，关闭软件，移走原图，再打开能分类查找并导出原文件。

### 第三步：三种默认材质全部跑通

使用 Three.js 做 Prism 预览。分别验证木头、树叶、薄纱，补齐透明图来源、裁切门槛、透明程度和双面设置；修改参数后能保存恢复。

同时在 UE 验证 AssetPort 的三种候选母材质、默认纹理、参数和依赖，适配为插件的正式基础模板。

完成标准：三种都能正确预览，不出现只完成不透明就进入发布的情况。UE 模板测试与 Prism 预览测试各自有记录。

### 第四步：UE 插件能收一套完整材质

先做内容浏览器右键、单条收集、高级拷贝、依赖检查、预览图和交接。复用 HyperVault 能用的代码，修掉目录过滤和不安全覆盖的问题。

完成标准：收进 Prism 后关闭源项目，Prism 仍有完整文件。再逐步加批量收集、只提取贴图和失败重试。

### 第五步：从 Prism 真正拿回 UE

分别跑通“原生材质包还原”和“贴图生成三种基础材质”，加入版本、重名、已有修改检查。

完成标准：全新目标项目收到材质，保存并重启后可用；不偷偷引用原项目的文件。

### 第六步：补齐用户日常操作

材质画布引用、批量标签、版本历史、撤销、回收站、任务中心、断电恢复、旧工程迁移。已有图片、文档、脑图、截图和贴图操作不得被改坏。

旧 `.prism` 保持可读，迁移生成新库，旧文件保留。不为了新材质功能直接覆盖老工程格式。

### 第七步：完整搬库与更新包

在收集、保存、取用都跑通以后，再做可靠的跨电脑增量交接、冲突处理和大库回收。详细规则见技术附录，不能拿普通 ZIP 文件冒充已经实现的双向更新协议。

完成标准：两台电脑共有原库，只传变化就能更新；漏传、重复、乱序、两边修改均可处理。

### 第八步：正式发布前验证

验证百 GB 库、1 万图片、1000 套材质、100 张画布、100 篇文档、100 张脑图；在干净电脑上离线安装。记录加载、保存、导出、显存和内存情况，不把规划指标写成实际跑分。

插件源码、构建说明、支持版本、第三方许可证和已知限制一起交付。安装包带齐经过确认的默认模板和离线预览文件，用户不需要首次运行再装开发工具或下载代码。

## 18. 用这些实际例子验收

| 验收例子 | 什么才算通过 |
|---|---|
| 一套不透明木头贴图 | 收进库、预览、改参数、保存、导出都正确；生成 UE 材质并重启仍可用 |
| 一张带透明通道的树叶 | 用户选择裁切，叶片轮廓正确，门槛保存后不变；UE 同样按该门槛裁切 |
| 独立黑白图控制的铁丝网 | 用户选对通道，两端网眼一致，不误用颜色图的透明通道 |
| 半透明薄纱 | 可连续调透明程度，能看到背景，重开参数不丢，交叉平面效果有测试 |
| 同一张图在不透明和裁切两种材质使用 | 原图只需存一份，两条材质的显示和参数互不影响 |
| 一个实例引用公共目录的父材质和函数 | 收集时能找到，不因依赖在其他目录而漏掉 |
| 两个不同目录里都有 `T_Normal` | 整理后都保留，各自引用正确 |
| 完整材质依赖第三方插件 | 清楚列出条件，目标缺插件时提前阻止不可靠导入 |
| 完整材质带 UE 纹理，但原始 PNG 已丢失 | 原生包仍可收集；提取图明确标记来源，不声称找回原图 |
| 收集后删除/移走原项目 | Prism 能拿出已保存内容，新目标项目仍能加载材质 |
| 同一材质修改后再收集 | 用户能更新成新版本，也能另存独立材质；旧版能找回 |
| 保存中继续改粗糙度 | 后来的值不会被旧保存完成回调误判为已保存 |
| 传到一半取消/断电 | 不误报完整，重试不会制造重复材质或破坏旧版 |
| 按文件夹和多个标签查找 | 能正确组合筛选；移动分类不重新复制几十 GB 文件 |
| 画布里引用三次同一材质 | 能分别摆放，删除一张卡不删库内材质 |
| 两台电脑只传更新 | 对方原库更新，不多一个项目；重复收件不重复添加 |

收集和取出的成功不能只看“按钮没报错”。必须重新打开文件、检查引用、对照原始文件，并在 UE 重启后再确认。

## 19. 这轮实际完成了什么

这轮完成的是重写方案、开源调查、源码和候选模板归档，不是已经实现了 Prism 新功能。

已取得并保留许可证的主要内容：HyperVault 相关源码、AssetPort 相关源码及三种母材质和默认纹理、Three.js 离线预览库。它们的文件校验值已经记录，尚未执行 UE 编译/导入验证，没有改动用户的 UE 项目。

原来的保存、备份、更新包等深层技术规则保留为附录。后续写代码时按本文件的步骤推进，并给每一步补实测结果，不能只凭下载到源码就写“已经支持”。

## 20. 资料链接与开发时必须核对的依据

- UE 高级拷贝：[BeginAdvancedCopyPackages](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Developer/AssetTools/IAssetTools/BeginAdvancedCopyPackages)。本机 UE5.7 的 `IAssetTools.h` 也确认了资产和依赖的高级拷贝入口。
- UE 资产迁移：[Migrating Assets](https://dev.epicgames.com/documentation/en-us/unreal-engine/migrating-assets-in-unreal-engine)。迁移时需要包含依赖，目标路径和重名也要处理。
- UE 三种混合模式：[Material Blend Modes](https://dev.epicgames.com/documentation/en-us/unreal-engine/material-blend-modes-in-unreal-engine)。这里是行为依据，不等于所有材质都能跨软件完全一致。
- UE 原生文件版本限制：[Versioning of Assets and Packages](https://dev.epicgames.com/documentation/en-us/unreal-engine/versioning-of-assets-and-packages-in-unreal-engine)。
- HyperVault：[本次查看的依赖与发布代码](https://github.com/nsynkde/HyperVault/blob/c9d9fcea7234e6482a43f4ba30ce263776054bd6/Vault/Source/Vault/Private/AssetPublisher.cpp)、[取回代码](https://github.com/nsynkde/HyperVault/blob/c9d9fcea7234e6482a43f4ba30ce263776054bd6/Vault/Source/Vault/Private/SLoaderWindow.cpp)、[MIT 许可证](https://github.com/nsynkde/HyperVault/blob/c9d9fcea7234e6482a43f4ba30ce263776054bd6/LICENSE)。
- AssetPort：[三种模式选择与实例生成](https://github.com/Colosyn/Asset-Port/blob/3b82afd755216c76d298db95aada37839c7fe10f/asset_port/materials.py)、[三种母材质目录](https://github.com/Colosyn/Asset-Port/tree/3b82afd755216c76d298db95aada37839c7fe10f/Materials)、[MIT 许可证](https://github.com/Colosyn/Asset-Port/blob/3b82afd755216c76d298db95aada37839c7fe10f/LICENSE)。
- Three.js：[透明及裁切属性源码](https://github.com/mrdoob/three.js/blob/beab9e845f9e5ae11d648f55b24a0e910b56a85a/src/materials/Material.js)、[透明贴图取绿色通道的实现](https://github.com/mrdoob/three.js/blob/beab9e845f9e5ae11d648f55b24a0e910b56a85a/src/renderers/shaders/ShaderChunk/alphamap_fragment.glsl.js)。

这些是本次调查实际读取或取得的依据。上游项目声称支持、我们读到相关源码、我们在本机运行通过，是三种不同状态，实施记录里始终分开写。
