# Prism 三个功能执行总方案

日期：2026-10-15。状态：功能设计与接入任务书，三个新功能尚未实现。

## 1. 已确定的产品要求

1. 截图后可以直接钉在桌面，也可以送入当前画布；画布已有图片可以拿到屏幕上做绘画、建模参考。
2. 以图搜图的主入口在**现有搜索框右侧的小图标**，按用户提供的 Eagle 截图位置安排。搜索对象是本地素材库，不需要用户填写 API Key。
3. 从网页链接下载视频，优先使用 yt-dlp，下载后可导入画布及继续提取视频帧。
4. 复用 GitHub 开源项目的核心实现；Prism 只负责入口、数据衔接、任务调度和界面一致性。不开一个自己的截图引擎、检索模型或网站解析器。
5. 不能因为增加功能，再让画布出现原图同步解码、全库扫描、长时间主线程计算和大量图片对象常驻。

## 2. 选型及复用边界

| 功能 | 确定采用的开源能力 | Prism 必需的适配 | 集成方式 |
|---|---|---|---|
| 截图、桌面贴图 | [ScreenPinKit](https://github.com/InterwovenCode/ScreenPinKit) 的截图窗、贴图窗和窗口管理 | 工具栏“送入画布”、图片文件传输、画布目标、快捷键配置 | 独立辅助进程，避免其 PyQt5 与 Prism PyQt6 混用 |
| 本地以图搜图 | [OpenCLIP](https://github.com/mlfoundations/open_clip) 编码；[FAISS](https://github.com/facebookresearch/faiss) 排序检索 | 搜索框图标、索引与素材 ID 对应、筛选和定位、增量更新 | 独立可选检索组件，模型按需安装和加载 |
| 网站视频下载 | [yt-dlp](https://github.com/yt-dlp/yt-dlp) 解析和下载；FFmpeg 合并 | 链接输入、进度取消、错误提示、素材导入 | 受控子进程，独立升级解析器 |

ScreenPinKit 自有代码为 MIT，其依赖的许可证须随构建逐项保留；OpenCLIP、FAISS 的代码许可证为 MIT；yt-dlp 源码为 Unlicense，其官方 Windows 打包程序会因所含依赖采用 GPLv3+。不能把代码许可证直接当成所有模型、字体和依赖的许可证。[ScreenPinKit 许可证](https://github.com/InterwovenCode/ScreenPinKit/blob/main/LICENSE.md)、[OpenCLIP 许可证](https://github.com/mlfoundations/open_clip/blob/main/LICENSE)、[FAISS 许可证](https://github.com/facebookresearch/faiss/blob/main/LICENSE)、[yt-dlp 授权说明](https://github.com/yt-dlp/yt-dlp#license)。

这里的“直接用开源项目”指复用核心实现。把独立工具变成 Prism 的入口、把结果交给当前工程，仍然需要少量适配；上游并没有一个能直接替 Prism 管理画布的现成接口。

## 4. 所有新任务共用的约定

### 4.1 身份与导入

任务提交时记录 `job_id / project_id / target_canvas_id / project_generation`。截图或下载期间用户切换工程，完成结果不能误塞进后来打开的工程。目标消失则保留在任务收件区，提示“请选择导入画布”。

在“全部素材、未分类、未标签、最近使用、标签聚合”页面操作时，不能把临时聚合页当成真实的持久化画布。第一次导入先显示目标选择：已有画布、默认画布或新建画布；后续记住选择并明确显示目标。纯搜索、纯贴图不改变工程。

导入成功以素材存储和工程中的新增记录均完成为准。一个批次对应一个可撤销操作。原始 PNG、视频文件保留原字节；预览缓存和特征向量允许重建。

### 4.2 任务、取消与主线程

任务有等待、运行、成功、失败、取消状态。后台任务不接触 Qt 场景对象；界面接收 ID 和结果文件，再分批导入。所有队列有限，进度刷新最多每秒 5 次；禁止每张图片完成都触发全画布刷新。

不另造一个复杂任务框架：延续现有工作流和子进程管理方式，抽出必要的进度/取消适配。截图辅助进程、检索进程和下载进程独立退出，不影响保存工程。

### 4.3 安装与更新

基础安装包保留现有画布功能。截图助手、图像检索运行时、视频下载组件为可选组件，界面显示状态和磁盘占用。首次使用先说明下载大小；支持指定本地离线组件包。不要在普通图片点击时加载 PyTorch，也不要把 PyQt5 装进 Prism 主进程。

锁定每个上游的 tag/commit、构建来源及 SHA256，记录依赖许可证。更新经过隔离目录验证再切换版本，失败可回到旧版。不能静默从 GitHub main 下载代码立即执行。

### 4.4 日志

任务按 `job_id` 关联开始、阶段、结束，记录时长、数量、设备、队列和错误类型。继承当前有界轮转，不保留无限任务历史；不记录 Cookie、图片内容或签名 URL。主线程响应目标与后台任务总耗时分别统计。

## 5. 执行顺序与交付门槛

| 顺序 | 交付内容 | 进入下一阶段的条件 |
|---|---|---|
| 0 | 先完成本轮直方图、检查预览恢复及相关回归 | 不改变原图、切换立即恢复、原有显示回归通过 |
| 1 | 截图与桌面贴图 | 截图→贴图、截图→画布、画布→贴图三条路径全部可用；多屏 DPI 通过 |
| 2 | 搜索框以图搜图 | 离线检索、增量索引、结果定位、删除/撤销同步通过 |
| 3 | yt-dlp 下载 | 四个平台的真实授权样例、取消重试、合并、导入及原视频保留通过 |

每个功能先做“上游最小接入验证”，再做 Prism 交互，最后打包。上游不可用时，记录具体失败，不能用自写引擎悄悄替换。

## 6. 分功能执行文件

- 《Prism-方案01-截图与桌面贴图.md》：具体组件、通信约定、入口、贴图行为、多屏、内存和验收表。
- 《Prism-方案02-搜索框以图搜图.md》：Eagle 式入口、本地模型、索引结构、结果交互、定位及性能预算。
- 《Prism-方案03-网站视频下载.md》：yt-dlp/FFmpeg 接法、四个平台、登录、任务、导入和抽帧。

这三份文件中的模块名称、接口和指标属于**计划**，不是宣称功能已经写好。指标是后续验收目标；没有在本机做过的模型、下载、多屏性能测试，不写成实测成绩。
