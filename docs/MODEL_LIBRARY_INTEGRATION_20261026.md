## 实际架构

~~~text
主窗口／现有导航提交门
  → ModelLibraryComposition（项目路径、项目 ID、打开代次）
      → ModelLibraryService（能力门、事件归一化、GUI 确认）
          → ModelRepositoryAdapter／既有工程附件与对象存储
          → ModelImporter／ModelOriginalExporter
          → ModelBundleStore（租约工作包）
          → F3DBackend／NativeModelJobController
              → 离屏辅助进程：读取、封面、统计
              → 独立 PyQt6 辅助进程：大预览、相机、封面捕获
  ← GUI 队列投递，核对会话、源／外观／相机版本
  → 单条已提交模型同步到 scene 和部分保存基线
~~~

主进程不 import F3D／VTK。运行时探测、依赖包准备、派生贴图与原生等待均在后台。模型原件继续走既有附件／对象存储通道。模型导入期间拒绝工程保存和替换，提供取消入口；取消不把已经提交的结果说成没写入。

封面图片缓存与工程内容分开：工程保存内容地址键与版本，不持久化整库 Base64；查询按当前摘要页读取缓存图。缓存缺失可以重新生成。已完成的原生输出在复制进入缓存后释放，预览依赖保留到首帧切换确认或进程停止。缓存的长期磁盘回收、全 GUI 图片驻留预算仍需专门实测，不能据此宣称达标。
