# Prism 目标架构与迁移裁决 V2

日期：2026-10-24。性质：目标设计与执行约束，尚未实施，不是性能完成报告。

用户确认六个既有 bug 已修复；本设计不再把那六项作为等待条件。迁移以开始实施时的源码快照和已修复行为为基线，不复用旧报告宣称当前失败。

## 1. 明确选择

采用：**模块化桌面单体 + 会话内统一编辑状态 + 独立的只读查询投影 + 按视口分块渲染 + 有界异步任务**。

这是根据目前 Prism 的 Python/Qt/SQLite、画布/资料库/文档/脑图/材质混合工作流做出的目标选择。没有脱离约束的绝对最优架构；本方案用数据正确性、交互工作量、资源可控、实现成本和扩展成本共同评判，并通过实测修正具体参数。

产品边界：现有 UI 布局、快捷键、文件格式和主要操作语义保持。新增等待/错误状态复用已有区域，不以重画界面代替内部改造。继续使用 Qt、SQLite、Babylon、PyAV 和已有编辑器。后台进程只用于有隔离或 CPU 并行价值的任务，不把桌面程序改成多个常驻服务。

不采用全工程重写、所有模块插件化、微服务、完整事件溯源、通用全局事件总线、每个类一层接口、全量 ECS 或立即改用全新 GPU 画布。命令/查询分别设计接口，但不拆成两个部署系统，不为架构名称引入分布式组件。

## 2. 第一版必须修正的地方

1. 不能把已有 ProjectAssetCatalog 再套一层同义 AssetQueryService，却保留原来的全量合并。应改原查询内核及边界，旧名称可保留为适配入口。
2. 不能宣布建立单一 ProjectSession 就合并所有状态。持久化基线、编辑覆盖、选择、相机、加载状态各有所有者和寿命。
3. 不能直接把现有 scene/catalog 对象送进后台。ProjectAssetCatalog 当前含 GUI 场景依赖；必须先分出纯数据快照。
4. 不能先清理页内对象，再补撤销。commands.py 的现有命令持有逻辑素材对象，partial_residency.py 会保留对象保障身份与撤销。释放策略必须按依赖迁移。
5. 不能为统一调度另造一套万能线程池。保留不同执行域，只统一任务身份、取消、优先级和结果交付约定。
6. 不能以文件行数或通过测试数量承诺性能。必须检查实际工作量、同条件端到端延迟、画质和保存重开。

## 3. 六个结构模块与依赖方向

| 模块 | 唯一职责 | 禁止承担 |
|---|---|---|
| 核心数据 core | ID、记录值、变更、版本、几何和查询契约 | QWidget、文件连接、全局线程池 |
| 应用 app | 打开/导航/编辑/导入/导出/保存用例与生命周期 | 自绘算法、SQL 文本、解码实现 |
| 基础实现 infrastructure | SQLite/附件/索引/解码/原生计算/文件监测 | 直接改变页面、按钮和用户选择 |
| 展示 presentation | 窗口、面板、Qt 模型、输入、状态展示 | 全库扫描、持久化事务、同步等待缺页 |
| 画布 rendering | 空间分块、视口、图元适配、LOD/瓦片/合成 | 全工程业务聚合、数据库读写 |
| 装配 bootstrap | 构建服务、连接显式依赖、启动与关闭 | 业务规则、运行中到处查找任意服务 |

依赖规则：presentation → app → core；rendering → core。infrastructure 实现 core/app 边界所需的具体端口；bootstrap 组装各方。app 通过少量注入的端口调用存储、调度与渲染适配器，不反向导入窗口。Qt 的信号/控制器属于边界适配层，不能假装都能立即变成无 Qt 的纯业务代码。

只在确实有异步边界、测试替身或两个实现时引入 Protocol/接口；纯函数不机械包装成类。公开入口显式注入，避免 service locator 和动态猴子补丁成为长期扩展方式。

目标目录（迁移后形态，不要求第一天搬文件）：

```text
prism/
  core/             ids, values, changes, query contracts, geometry
  app/
    project/        open, close, session, save coordinator
    editing/        commands, history, editor commit
    workspace/      navigation, page lifecycle
    catalog/        read facade, search/count coordination
    media/          import/export/preview use cases
  infrastructure/
    storage/        current SQLite format, attachments, partial save
    catalog/        scalar index, SQL query implementation
    media/          decode, thumbnails, derived files
    execution/      executors and result delivery
    native/         optional measured kernels
  presentation/
    window/         composition-facing window adapters
    panels/         existing document/mindmap/material/library panels
    models/         paged Qt models
  rendering/
    canvas/         spatial chunks, viewport snapshots, selection adapter
    previews/       LOD, tiles, composition
  bootstrap/        application construction
```

旧导入在迁移期使用显式再导出兼容；只在所有正式调用者迁走、测试覆盖后删除。移动文件单独进行，不与逻辑改动混在一个大包内。

## 4. 数据所有权：最关键的约束

### 4.1 状态表

| 状态 | 唯一所有者 | 保存/释放规则 |
|---|---|---|
| 已保存内容与原始附件 | 工程存储 | 权威持久化基线；事务与格式校验 |
| 未保存新增/修改/删除 | 编辑会话的变更覆盖层 | 不能因切页或缓存逐出丢失；保存收据确认指定版本 |
| 撤销历史 | 编辑会话历史 | 保存可逆值/引用和版本，不长期依赖图元身份 |
| 全工程搜索/计数索引 | 查询投影 | 可重建，有已应用基线版本，不能冒充工程原件 |
| 页内已加载元数据 | 驻留管理 | 干净记录可逐出；脏数据和历史依赖另行保护 |
| 选择、相机、展开、筛选 | 工作区/视图状态 | ID 化；不把面板可见性写成资产被删除 |
| 可见图元和合成 | 渲染适配器 | 可重建，随视口和页释放 |
| 像素/缩略图/派生文件 | 预览缓存 | 可重建；明确字节预算和源版本 |
| 加载进度、请求代次 | 对应操作 | 操作终结后释放，不用永远有效的全局标志 |

核心原则：**工作会话的有效状态 = 已保存基线 + 尚未被确认的编辑覆盖。** 不能说“数据库是唯一真相”就忽略未保存编辑，也不能让索引和场景各自拥有一份可独立修改的真相。

### 4.2 对象模型

- 所有资产创建时即有稳定 ID；持久化编码可映射既有 save_id。区分 asset_id、page_id、attachment_id、session_epoch，不使用 Python 对象地址作为长期身份。
- 区分 AssetSummary（查询/列表）、EditableAsset（编辑值）、RenderEntry（几何与显示句柄）。它们是投影，不是三份独立可写资产。
- 当前 ImageRecord 保留为过渡适配器。其位置、选择、图元代理和预览状态逐步归回正确所有者，避免一次移除其全部兼容行为。
- 核心值对象无需 QGraphicsItem；现阶段无需为了纯度立即重写所有 QPointF/QRectF。先阻断后台访问 GUI 对象，再按需要改紧凑数值结构。
- 未知字段继续透传，未加载字段保持 absent/unloaded，不能按空值写回。

## 5. 会话、编辑和保存的完整闭环

### 5.1 会话边界

每个打开工程有独立的会话 epoch。应用运行期组件（线程池、共享可重建缓存）和工程期组件（覆盖层、历史、索引句柄、页面）分开管理。选择“单个工程编辑写入串行”，查询可并行。

会话状态建议：opening → ready → closing → closed，失败进入可恢复状态。索引是否 ready、当前页是否加载、是否 saving 是独立状态，不强行塞成一个枚举。关闭流程先阻止新编辑、确认编辑器提交和未保存策略，再取消任务、断开交付、释放资源。

### 5.2 编辑事务

一次用户操作：校验目标版本 → 应用可逆补丁 → 递增相关修订 → 发布一个 ChangeSet → 界面和查询投影消费。

ChangeSet 包含项目/会话、事务序号、受影响 ID、变化字段、必要前后值和旧新区域。只携带需要的数据，不把整库拷进通知。不用全场景 changed 表示所有类型的业务变更。

拖动期间：相机/临时几何由渲染交互控制；按帧合并预览，松手提交一个可撤销操作。需要实时命中时更新相关空间块。既有依赖图元回调写值的逻辑通过适配收口，避免新旧两路各写一次。

撤销/重做也经过同一变更入口；不是只恢复像素却忘记计数/脏标记。批量操作按一个逻辑事务发布通知，在计算阶段可取消；提交后的“取消”需要反向命令，不能假装没发生。

### 5.3 撤销与驻留迁移

第一步保留现有命令对象、素材身份及 parked 保护，不宣称已实现元数据内存有界。第二步逐类把新命令改为 ID + before/after + attachment reference，跨页撤销按 ID 恢复所需记录。大删除/导入可逆内容引用可读快照或历史附件，不复制所有原图到 Python 内存。

历史存储单独计费并保护所引用附件；如果以后需要落盘历史或限制历史容量，必须明确产品行为、清理时机及恢复承诺，不能默默丢弃撤销来达到内存指标。

只有一个命令族的身份和跨页撤销验收完成，才能释放该族不再需要的干净对象。最后才能删除对应 parked 强引用。不能颠倒顺序。

### 5.4 保存协议

1. 对文档/脑图获取编辑提交确认；超时或失败显式失败，保留当前内容。
2. 在编辑所有者线程捕获版本 S 的不可变变更快照，范围含必要页面/附件，不全库物化。
3. 写入协调器串行提交，沿用现有 partial save、基线校验、附件和未知字段保护。工作线程只接收快照。
4. 回执确认 S；新于 S 的编辑保持 dirty。不能收到“保存成功”就清空全部脏标记。
5. 保存期间发生外部修改按既有冲突规则处理，不能最后写入者直接覆盖。
6. 另存为成功后再绑定新路径与来源；失败保留原来源。预览缓存变化不等于用户内容 dirty。

第一轮不改变 .prism 格式、不随意切换 SQLite journal 模式，不加入自动写回临时库的新机制。恢复/自动保存应作为独立需求设计，不夹带到重构。

## 6. 查询架构：后台计算，一致结果

### 6.1 分离线程边界

保留 ProjectAssetCatalog 的公共语义，提取“索引查询内核”和“GUI 适配快照”。GUI 获取当前可变对象的最小值快照并维护增量覆盖索引；后台仅接收不可变基线标识、覆盖快照、QuerySpec 和取消标记。

QuerySpec 明确范围（页/工程/集合）、类型、过滤、排序、游标和首批上限。结果携带基线/覆盖版本、查询代次、complete/pending/error、total_known，而不是只有一个列表。

### 6.2 基线与覆盖的正确合并

- 对修改/删除 ID 先遮蔽基线旧行，再把覆盖层的当前值参与过滤和排序。
- 新增、删除、移动、重命名、标签变更必须同时影响搜索与计数；覆盖层不能只处理已保存 ID。
- 游标包含查询与快照身份、排序键和 ID 作并列次序。用固定快照保证后续页不重复/漏项；版本变化明确重启或增量刷新，不能混拼两个版本。
- 基线 keyset 分页逐批读取，直到合并后达到 K 或基线耗尽；不能只查基线前 K 条再删除覆盖项，导致结果不完整。
- 精确排序和模糊搜索需要的工作量不能凭空消失。优先索引过滤/排序、限定首批、后台增量返回；表达复杂时注明代价，不伪称所有查询 O(K)。
- 索引未就绪返回 pending/incomplete，支持明确的后台重建或有限回退；绝不返回伪空结果。
- 外部文件变动在存储/查询边界验证；文件监测仅作提示，不能作为数据有效性的唯一证明。

计数和分组复用同一版本快照。优先增量 delta，复杂变更后台重算；结果携带版本，过期不安装。每个明确提交周期只发布一份计数结果。

## 7. 执行架构：统一协议，多个执行域

| 执行域 | 工作 | 数据与连接约束 |
|---|---|---|
| GUI | 输入、轻量编辑提交、Qt 对象安装、绘制 | 不阻塞取页，不跑全库查询 |
| I/O/查询工作线程 | 文件/SQLite/索引读取 | 每执行所有者使用自己的连接，明确只读事务寿命 |
| 原生解码工作线程 | Qt/PyAV/NumPy 等已有解码处理 | 以源快照和版本为输入；尊重对象线程亲和性 |
| 写入协调器 | 顺序保存、导入持久化等写入 | 同工程写入有顺序，提交/取消语义明确 |
| 可选 CPU 进程/扩展 | 测量证实的纯计算 | 纳入复制、启动、崩溃和取消成本 |
| WebEngine/GPU | 保留框架自有执行与进程模型 | 不被通用线程池接管 |

任务协议包含 session_epoch、operation_id、局部 generation、必要 resource revision、优先级、取消、输入/输出字节预算。单一全局 revision 会造成无关任务全部失效；按元数据/几何/像素源/查询维度判断。

任务状态：queued/running/completed/cancelled/failed。可计算但过期的结果属于 discarded，不是成功显示。完成队列也必须有上限，避免 worker 太快把 GUI 堆满。

相机输入优先；焦点图像优先于边缘图像；当前页优先于预取/索引。高优先任务不能永久饿死后台，采用可调并发配额和老化策略。重复资源请求合并，引用数归零时取消有价值的剩余工作。

线程任务不能强杀，协作检查取消；进程隔离只在有必要时使用。GUI 每轮安装预算以真实耗时为准，单个不可拆 Qt 创建/首次 WebEngine show 超支必须单列，不能说切成4ms就保证永不冻结。

关闭/取消后必须清理信号、回调、队列及资源引用。诊断记录失败不能改变业务控制流，也不能把全部对象堆栈或原图内容写入日志。

## 8. 画布架构：把工作量锁在视口附近

保留 QGraphicsView 与现有虚拟记录/合成瓦片能力，优化数据与绘制协议。未来若分析证明 Qt 原生绘制已是主要极限，再单独做 GPU 后端可行性试验，不能同时换数据层与渲染引擎。

### 8.1 持久几何与空间块

页面/画布维持紧凑几何投影（ID、包围范围、层级键、几何版本），空间索引按可更新块组织。局部改动仅更新旧新块；选中集合独立按 ID 维护。

视口计算先取得候选块，再取得候选项。远景读取低分辨率合成块，近景展开必要项。普通帧不构造全工程 Python 卡片集合，不按全库 z 序重新排序。

单页真实有十万项时，首个精确空间索引/布局仍可能需要 O(N) 处理。该成本放在后台、可取消、有进度，并在合理范围持久缓存。远景的准确图像也需要生成成本：未准备好可显示有标识的占位/上一帧，不能谎报已绘制清晰内容。

### 8.2 渲染快照和失效

每帧消费稳定 RenderSnapshot：相机/几何版本、候选块、可用 LOD、编辑预览。绘制中不修改工程、不查询数据库、不触发同步解码。缺失预览只排任务。

缓存键区分几何、源像素、样式、LOD、块；改名称不失效像素，改裁剪失效相关几何/派生图。布局缓存命中若布局版本未变直接复用，不全量重装位置。

合成缓存未命中时排有界任务，不回退到同帧逐张遍历全部素材。框选/命中保留原有精确语义；高密度查询实际命中 K 很大时允许 O(K)，明确限制工作切片，不能通过粗包围盒改变选中结果。

### 8.3 布局

自动排列是显式后台重操作；尺寸快照 → 纯布局计算 → 坐标/边界结果 → 检查版本 → 分块应用。局部编辑保留未变化组；手动摆放不被自动缓存覆盖。

已有 compact_layout 使用 rpack；不能未经剖析把布局计算一概视为纯 Python。需区分数组准备、Python 分组、锁等待、原生 pack 和 GUI 安装成本。

## 9. 文档、脑图、视频、材质和导入导出

共同契约：activate/deactivate、commit_async、snapshot、dispose。按现有能力提供适配器，不要求每个功能都实现不存在的操作。

- 文档/脑图：保留编辑器；内容提交确认与预览截图分开取消域。搜索读取已提交的文本投影，不强制唤醒所有 WebEngine 页面。
- 视频：保留 PyAV/Qt 后备；播放与缩略图队列分开，seek 合并，释放时确认解码/音频资源停止。
- 材质/GLB：保留 Babylon；可复用的 WebEngine 宿主按实测成本设计，不把每张列表卡片变成独立重型网页。活动场景切换有资源释放协议。
- 导入：先读取/校验/生成元数据，再按批次发布一致变更。中途失败有明确已导入范围或事务回滚，不留下伪完整项目。
- 导出/外拖：使用稳定资产/附件引用及快照；非可见资产不必先生成全部图元。临时文件直到接收者用完才清理。
- 网络、AI 推理、浏览器采集继续使用既有组件；结果以导入用例进入项目，不直接写窗口内部字段。

## 10. 资源预算与可观测性

预算至少分四账：可重建CPU像素/元数据缓存、持久编辑/历史、磁盘派生/临时文件、GPU/WebEngine/外部进程。沿用 resource_budget 已有注册和线程内淘汰规则。

为可见区域设置保底，为预取设置上限；预览按字节而非只按个数；页面释放不得破坏 dirty/history。总内存受这些账、Python/Qt 分配器及驱动影响，不能把一个缓存 budget 写成进程 RSS 硬上限。

观测复用 performance_trace 与现有计数。区分 input→反馈、查询→首批、视口→清晰、GUI阻塞、I/O等待、Qt安装、后台积压和源内容覆盖。正常模式低开销，诊断模式限流采样。历史报告和新源码需绑定版本，paint完成不等于屏幕实际呈现。

## 11. C++：可替换内核，而不是第二套应用

接口边界保留给 geometry batch / layout kernel / 紧凑结果筛选等纯计算；输入连续数值缓冲和ID，输出数组/位图，避免每项跨语言调用和 Python 字典来回复制。

先测已经使用的原生库和 Qt 安装路径。若热点来自 O(N) 误用、数据库等待或 WebEngine 首次初始化，迁移纯计算不是对应解法。

原生试验必须同时报告内核与端到端、转换复制、峰值内存、正确性、Windows构建/打包。保留可禁用原生实现和等价回退。绑定库及版本实施前核对官方资料；本设计不预先引入编译依赖。

是否上线取决于绝对延迟目标与维护成本；热点占比≥30%、端到端改善≥20%可作为初筛建议，不是僵硬规则。一个占比不大的内核如果造成关键帧长停顿，也可能值得改；反之微基准十倍但用户操作无改善则不采用。

## 13. 迁移依赖与交付顺序

### A. 基线与契约（先做）

固定当前已修复版本；记录正式启动入口、源码摘要、代表性副本、关键操作和未测项。定义会话/版本/查询/ChangeSet最小契约。已有架构测试重新运行，以当次结果为准，不继续引用旧的31/1作为现状。

### B. 一条完整的画布切片（最先产生用户收益）

不先迁完整数据模型。沿用现有记录/撤销，改可见候选、合成回退、布局快照与GUI安装；保持所有权不变。验证正常/失效/冷缓存/快速切页，量出收益。

### C. 查询与变更收口

提取后台可用的查询输入；索引+覆盖合并、搜索分页、版本计数和定向通知。先资产后其他类型，分别保留结果语义；旧GUI调用逐一替换。由app显式连接原UI，不能只增加闲置服务。

### D. 编辑命令与驻留（有严格先后）

编辑入口收口 → 命令族ID化/跨页撤销 → dirty/history附件保护 → 单族释放干净对象 → 内存实测 → 删除该族旧强引用。每完成一族立即保存重开验收，不一次迁完所有命令。

### E. 多编辑器与资源统一

文档/脑图/材质/视频适配提交、停用、释放；调度协议接到已有执行器，完成队列与缓存背压。不可取消的保存提交与可取消的预览分别处理。

### F. 剩余CPU热点裁决（按证据可选）

仅原生化一个测得的内核，做Python/现有原生库/新C++对照。无足够端到端价值则记录不采用，不把“没写C++”算架构未完成。

### G. 物理拆包与发布收口

稳定职责迁目录，兼容再导出逐步移除；清理不再使用的信号、状态字段、旧后台入口和猴子补丁。验证源码与安装包走同一实现。发布保留上一可用版本和数据兼容说明。

B与C的局部无冲突工作可以安排并行；D不能绕开历史依赖；不同任务同时改同一状态所有者应串行集成。本文件不授权自动启动多个代理。

每个包必须有：旧调用链/新调用链、状态所有权、修改范围、接口接线、同条件前后结果、正确性回归、风险和回退开关。迁移读路径时允许只读影子比较；写路径只执行一套，禁止为了验证进行双写。新流程确认后删除旧流程，开关不能永久积累。

## 14. 架构和性能完成标准

### 架构硬条件

- GUI交互路径没有会阻塞的缺页访问；关键查询/布局不访问活动GUI对象。
- 业务变更只有一个负责写入会话状态的入口，读模型版本与覆盖层一致。
- 新写入不能由可见图元列表推断全工程内容；未加载不等于删除。
- 页面释放与撤销/保存语义兼容，旧任务不得改新项目。
- 核心模块不导入面板；面板不直接操作SQL；旧异常依赖有清晰迁出终点。
- 规范由静态依赖检查和真实行为测试共同约束；仅新增接口或移动文件不算完成。

### 性能目标（待基线校准，非已达成绩）

1. 固定视口/画质，把总素材从1万增到10万，常规帧候选/安装/数据库访问不随总量线性膨胀；实际命中数K变大和首次索引成本分开报告。
2. 普通平移缩放目标GUI工作p95≤16ms、p99≤33ms；采样足够后才报告分位数。paint耗时、输入延迟和屏幕呈现分别计量。
3. 不允许常规交互中无说明的>100ms同步任务。显式全局重排/首次编辑器启动单列进度和最坏延迟。
4. 热索引搜索首批目标≤300ms，首次反馈≤100ms；复杂查询或冷索引显示真实pending/incomplete。
5. 当前页首次可操作目标热态≤1s/冷态≤3s，最终清晰不并入首个占位画面；具体依数据与硬件验证。
6. 页往返30轮后队列、图元和可重建缓存回落，主/子进程资源无持续无解释增长；历史增长单列，不假装已受缓存上限覆盖。
7. 增删改、跨页撤销、保存中继续编辑、另存为、取消、外部冲突、附件缺失和关闭重开全部保持数据语义。

小工程/大工程、密集单页/分散多页、冷/热/缓存逐出、真实混合类型副本均需覆盖。先冒烟，再按已知成本跑大规模；不对用户原件做写入试验。前后同数据、版本记录、磁盘和画质条件。无端到端收益不能以微基准结案。

## 15. 风险、回退和终点

最大风险不是搬文件，而是编辑覆盖、图元身份、撤销、分页查询和保存回执之间的契约断裂。使用独立副本、阶段源码快照和单写路径；不清空缓存/历史掩盖不一致，不把未知字段写空，不取消已有安全检查换取漂亮数字。

回退单位为一个完整用例/命令族/内核，记录相应数据是否已写入。源码回退并不能撤销磁盘格式变化，因此初期保持格式兼容；涉及格式变更另做向前/向后兼容设计和备份。本计划不含这类变更。

终点不是目录整齐，而是：数据有明确主人，编辑能可靠撤销和保存，搜索/计数一致，常规交互只承担局部工作，后台与缓存有边界，新增功能能找到唯一入口。它既允许未来替换某个C++内核，也不依赖C++才能成立。
