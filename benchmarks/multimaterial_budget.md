| 编号 | 指标 | 口径 | 阈值 | 反证条件 |

## 2. 必须一并记录的参考量（不设门槛，但没有它就不算完整报告）

- 冷准备耗时：**不得排除在报告之外**，与暖路径分列。
- 每个阶段的 P50 / P95 / P99、最长停顿、样本数。
- CPU / RAM / VRAM 峰值；50 次往返后的驻留内存、句柄数、临时文件数趋势。
- 数据规模：库 100 / 1000 / 1 万 / 10 万；单模型 1 / 10 / 100 / 1000 材质。
- 模型几何、贴图数量与分辨率、独立文件比例、分配分布、历史长度、冷暖缓存。
- 索引合成集与真实混合集**分开报告**；十万级真实混合数据不存在时如实写「未测」。
- `benchmarks/multimaterial_bench.py` 的合成部分只测**清单编解码**
  （`catalog_to_payload` → JSON 编解码 → `catalog_from_payload`），
  因此它的名字是 `synthetic-catalog-codec`，**不是**索引基准：它没有测数据库
  索引、查询、写入、恢复、WAL、单槽读写放大或工程增长，也不能用来判断存储布局
  或十万级索引性能。

## 3. 测量必须拆开的成本

GUI 线程 / 后台线程 / I/O 等待 / 原生渲染 / GC / 日志开销。日志另外按
`off` 与 `normal` 两个口径分别记录单事件与端到端（见
`artifacts/model-multimaterial/d6/logging-overhead.json`）。

## 4. 禁止的达标方式

缩减数据、降画质、关闭 GC、不计准备时间、只报缓存命中率、只报单事件耗时、
把解析放到 GUI 线程、用索引基准代替真实混合数据。出现以上任一种，对应指标
在报告里记「失败」而不是「通过」。
